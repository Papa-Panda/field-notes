## 一句话总结

推理蒸馏争的是思考过程而非答案：CoT 数据 SFT 学格式，on-policy 让学生自己生成、教师评判，SFT + RLVR 则是 R1 式能力跃升的标准组合。

## 核心

1. **问题/背景**：强推理模型（如 o1 级）能力强但调用贵，能否把推理能力搬进 7B 小模型？推理蒸馏与普通知识蒸馏不同：后者压的是知识（温度、软标签），前者要让小模型学会怎么思考、检查与回溯，目标是在数学、代码上逼近大模型的推理能力。
2. **机制/方法**：三条路线递进——
   - **CoT 数据蒸馏**：教师模型为题目生成带完整思维链的解答，过滤低质量样本后对学生做 SFT；关键在数据量与推理模式覆盖度。风险是学生可能只模仿到格式、没学到推理。
   - **On-policy 蒸馏**：学生自己生成推理，教师负责评判好坏、保留或丢弃；学生学的是自身能力范围内的推理方式，分布更贴合。
   - **SFT + RLVR**：先用 CoT 数据 SFT 学会推理格式，再用可验证奖励做 RL，让学生在格式之上探索自己的策略——这是 R1 蒸馏版的标准 pipeline。
3. **关键证据或数字**：实操流程为收集数学与代码题（GSM8K、MATH、HumanEval 等）→ 教师生成 CoT → 过滤 → SFT 1–3 个 epoch → RLVR 继续训练 → 独立评测验证。
4. **结论/判断**：只蒸馏答案得到的是记忆，蒸馏过程才得到能力；三法中 SFT + RLVR 上限最高，CoT SFT 是必备起点。

| 项 | 取值 |
| --- | --- |

## 可迁移

- 给小模型做推理增强时，先判断瓶颈在格式还是策略：格式没学会补 CoT SFT，格式有了但不会探索就上 RLVR。
- 这条 pipeline 与 R1 的公开做法同构，面试聊蒸馏可直接以此为骨架展开。
