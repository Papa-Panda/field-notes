## 一句话总结

RAG 微调是两端协同的工程：检索器用对比学习（正样本 + 难负样本）把「答得上」而非「长得像」的文档拉近，生成器在带检索上下文的条件下训练学会利用与甄别证据，两端联合训练效果最好，但要付出索引刷新的工程代价。

## 核心

1. **问题/背景**：开箱即用的通用嵌入模型 + 通用 LLM 直接拼 RAG，常出现两类失败：检索器召回的是词面相似但答不了题的文档；生成器拿到上下文也不会用，或被噪声文档带偏。微调就是分别治这两端。

2. **机制/方法**：检索器端用对比学习：对每个问题构造正样本（包含答案的段落）与负样本，负样本质量决定上限——随机负样本太容易，难负样本（ BM25 或旧检索器召回的高排名无关段落，如 DPR 的 in-batch negatives + BM25 hard negatives）才逼模型学细粒度区分，损失通常是 InfoNCE。生成器端用检索出的上下文拼接问题做条件生成训练，目标是标准语言建模损失；进阶做法（如 Atlas）把检索器与生成器联合训练，用生成端的困惑度信号（如 PPL 反传或 perplexity distillation）指导检索器。联合训练的固有麻烦是索引异步更新：编码器一变，全体文档向量过期，需要周期性重建索引（ Atlas 用周期性 re-indexing 缓解）或干脆冻结文档编码器只训查询端（如 RETRO 冻结 chunk 编码器）。

3. **关键证据或数字**：DPR 证明在 Natural Questions 等开放域问答上，稠密双编码器检索的 top-20 召回显著超过 BM25（约 78.4% vs 59.1%，NQ top-20 accuracy 口径）；Atlas 在仅 11B 参数、且只用 64 个示例 few-shot 的设定下在 NQ 上超过同量级大模型，说明检索 + 联合微调能以参数换数据。

4. **结论/判断**：RAG 微调的收益排序大致是：难负样本质量 > 生成器学会用上下文 > 两端联合训练；联合训练收益真实但工程成本最高，多数团队的最优解是「检索器认真训、生成器带上下文 SFT、编码器冻结避免索引失效」。

## 可迁移

- 自建检索管线时优先投入标注难负样本（用现网检索结果挖 hard negatives），这比换更大的嵌入模型性价比高。
- 面试可迁移点：能讲清联合训练的索引过期问题及三种解法（冻结文档塔 / 周期重建 / 异步更新），是区分「调过 RAG demo」和「做过 RAG 系统」的分水岭问题。

## 疑问 / 下一步
