2一句话总结

断点续训要恢复的是整套训练状态——权重之外还必须恢复优化器状态、学习率调度位置和数据加载进度，只加载权重等于动量清零、近乎从头再来。

3核心

  1. 问题/背景：长训练崩溃后要 resume，直觉做法是加载最近的权重继续跑，但这样恢复出来的训练轨迹与原轨迹并不等价。
  2. 机制/方法：完整恢复需要四件套：模型权重、optimizer state（动量与方差等优化器内部状态）、LR schedule 的当前位置（当前学习率走到哪一步）、data loader state（数据读到哪了）。其中 optimizer state 缺失最致命——动量全丢，效果等于从头开始。工程侧靠 Flash Checkpoint 做秒级存取支撑大模型断点续训，Universal Checkpointing 则解决跨框架兼容：用统一的张量并行映射策略对齐不同框架的切分方式，使一个框架（如 Megatron）存的 checkpoint 能在另一个框架（如 DeepSpeed）里恢复。
  3. 关键证据或数字：视频为要点式短篇，未给量化对比，核心数字就是「四件套」清单与秒级存取的目标。
  4. 结论/判断：checkpoint 的设计目标不是「存下权重」，而是让训练能从中断点无损接续，存什么、多久存一次、跨框架怎么恢复都要在开训前定好。

4可迁移

  • 设计 RL/预训练的 checkpoint 策略时，按四件套核对保存清单，并把优化器状态的存储体积与恢复耗时纳入容错预算；只存权重的 checkpoint 只能用于推理或微调起点，不能用于无损续训。
  • 面试被问「训练中断怎么恢复」时，先答状态清单（权重/优化器/调度/数据进度），再谈异步秒级 checkpoint 与跨框架通用格式，比只说「加载权重」完整得多。

5疑问 / 下一步

  • 视频未展开 RNG 状态与数据顺序随机种子是否也要恢复才能做到逐位复现，实际工程中通常接受非逐位一致，可结合可复现性那期一起对照。
