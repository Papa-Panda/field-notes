2一句话总结

序列并行沿长度切序列、用通信把 KV 换齐让每段看到全局；专家并行把 MoE 专家分置各卡、token 按路由 all-to-all 往返，用 5%–10% 的通信换参数与算力的解耦。

3核心

  1. 问题/背景：两条隐藏战线——长上下文下注意力的中间激活随序列长度平方增长，单卡连一条百万 token 序列都放不下；MoE 模型有上千个专家，单卡装不下全部专家参数。前者要切序列，后者要切专家。
  2. 机制/方法：序列并行沿长度把一条序列切成若干段、每卡负责一段；注意力需要全局视野，各卡通过环形传递或 all-gather 把其他段的 K、V 换过来，每段照样 attend 到完整序列，每卡只存 $1/Q$ 的激活（ $Q$ 为段数），理论加速接近 $Q$ 倍，代价是前后各一次通信、约占总时长 10%–30%。专家并行把专家分置不同卡上：门控路由器给每个 token 对所有专家打分，选 top-k（通常 $k$ 为 1 或 2）送去对应卡计算、再送回合并；为防热门专家被挤爆，设容量因子 $\alpha$ ：每个专家最多接收 $\alpha$ 倍于平均数的 token，超出的丢弃或绕行。token 的跨卡往返靠 all-to-all 点对点交换，这是专家并行特有的通信模式。
  3. 关键证据或数字：示例账——512 个 token、16 个专家、4 张卡（每卡 4 个专家）、top-2 路由、容量因子 1.2：稀疏激活使实际计算量只有总模型的 $2/16$ ，吞吐提升约 2–3 倍，而路由与 all-to-all 通信只占总时长 5%–10%，用小通信代价换来参数量与计算量解耦。
  4. 结论/判断：六种并行各切一样东西——数据并行切数据、张量并行切矩阵、流水线切层、序列并行切长度、专家并行切专家、ZeRO 切冗余状态；真实训练是积木组合（机内 TP、机间 DP、跨层 PP、叠 ZeRO，有 MoE 上 EP、长文本上 SP），设计方案就是在算力、显存、通信三角里找平衡。

5可迁移

  • 面试题「MoE 怎么分布式」：top-k 路由 + 容量因子 + all-to-all 三件套缺一不可，容量因子是防专家挤爆与负载均衡的关键旋钮。
  • 给长上下文训练做容量规划时，先按序列并行的通信占比（10%–30%）打折算有效算力，别按理想线性加速估。
