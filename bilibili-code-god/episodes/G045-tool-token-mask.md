## 一句话总结

多轮 Agent 轨迹里约一半 token 是环境注入的观察而非策略采样，把它们算进策略梯度等于训练模型去预测环境；正确做法是 loss、KL、重要性比三处都排除，但 attention 不能 mask——观察是输入，不是目标。

## 核心

1. **问题/背景**：一条多轮轨迹是动作与观察交替拼接的长序列：模型写思考和工具调用，系统把搜索结果、代码执行输出等拼回上下文。在搜索、代码类任务里观察 token 常占一半以上，若不 mask，奖励高时梯度会去提高「生成这段搜索结果」的概率。
2. **机制/方法**：策略梯度的推导只对策略自己采样出的动作 token 成立，观察 token 相对当前策略是 off-policy 的，算进去违反推导假设、经验上也破坏稳定性。要排除的一共三处：策略梯度目标只在动作 token 索引上求和（分母也只算动作长度）；KL 项里观察位置上策略与参考模型的 KL 没有意义，排除；重要性比是新旧策略在同一 token 上的概率比，观察 token 不是策略生成的，比值无定义，排除。但 attention mask 必须全 1——模型要读到观察才能决策，所以存在两个 mask：attention 全通，loss mask 只在动作段为 1。
3. **关键证据或数字**：视频强调这与 SFT 中 mask 掉 user 消息形式相同但理由更强：SFT 是「不想学」，RL 是「算了就错」。第三个工程细节是边界准确性：历史轮次应保留原始 token id 直接拼进输入缓冲，只对新到的观察做分词；每轮把整段文本重新分词会让 token 边界漂移，mask 跟着错位。轨迹里每个 token 应带来源标签（动作/观察）及 log-prob，保证 rollout 与训练看到的 token 完全一致。
4. **结论/判断**：实操三条——构造 batch 时按来源打标签，三种 mask 都从标签生成；attention 别动；多轮拼接保留历史 token id。训练前抽几条轨迹把 mask 与文本对齐打印核对，是最便宜的防错手段。

## 可迁移

- 面试问 Agent RL 实现细节，先答这个 mask 三件套（loss/KL/重要性比排除、attention 保留），是最容易漏的得分点。
- 自己的 RL 训练脚手架可加一条 pre-flight 检查：随机抽样轨迹，断言观察段的 loss mask 全为 0 且与原始 token id 对齐。
