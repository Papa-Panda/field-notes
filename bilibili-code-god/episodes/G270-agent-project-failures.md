## 一句话总结
Agent 项目约四成失败、上生产不足四分之一，多数不是败在模型能力，而是败在架构、容错、可观测、评测、成本这五道工程鸿沟。

## 核心
1. **问题/背景**：2026 年被称 Agent 元年，但行业数据扎心：近三分之二的组织在试 Agent，能成功扩展到生产的不足 1/4，失败率约 40%（不同调研口径下大致在三到五成）。模型已够强，落地仍难。
2. **机制/方法**：五道鸿沟——①系统架构不稳：Agent 是多步调用 + 状态管理 + 工具协作的复杂系统，没有状态机、重试、超时设计，遇异常就死循环、丢状态、断调用链；②错误处理弱：差的 Agent 反复踩同一坑，好的能把报错、权限拒绝、无效结果转成下一轮的高价值上下文；③可观测性差：定位不到是哪一步出错；④评测缺失：没有整体效果的自动评估就无法迭代；⑤成本失控：多步调用 + 长上下文使单次任务的成本与延迟远超单轮对话。
3. **关键证据或数字**：失败项目大多败在工程基本功而非模型——「模型是天花板，工程是地板」，地板没搭好照样摔。
4. **结论/判断**：解法是系统工程化四板斧：架构设计（状态机、错误恢复、工具编排）、容错机制（重试、降级、兜底）、可观测性（全链路追踪、每步可审计）、评测体系（自动化评估整体效果）。四块补齐，Agent 才可能从 demo 走到生产。

## 可迁移
- 做 Agentic RL / Agent infra 时，rollout 侧的容错与轨迹可观测性应与训练框架同等优先：失败轨迹若能结构化回收，本身就是训练信号与排障依据。
- 面试聊 Agent 落地，别只谈模型选型；能讲清状态管理、失败上下文复用、轨迹级评测的人更像做过生产系统。
