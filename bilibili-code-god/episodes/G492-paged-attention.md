## 一句话总结

PagedAttention 借用操作系统虚拟内存分页管理 KV Cache：固定小块按需分配、块表做逻辑到物理的映射，把 60%–80% 的显存浪费压到 4% 以下。

## 核心

1. **问题/背景**：推理分 prefill（整段提示词并行算出全部 KV 存入缓存）与 decode（逐 token 生成并追加 KV）两阶段。麻烦在于生成长度事先不可知，而传统框架按最大长度一次性预留整块连续显存，产生三种碎片：预留碎片（按最长预留、大部分格子空等）、内部碎片（序列提前结束、预留作废）、外部碎片（请求间空隙合计够用却不连续、新请求只能排队），叠加浪费 60%–80% 显存。
2. **机制/方法**：照抄 OS 分页——序列对应程序、块表对应页表、物理块对应物理页。把 KV Cache 切成固定大小的小块（vLLM 默认一块装 16 个 token），生成时装满一块再申请下一块，用多少占多少，浪费最多只发生在最后一个未填满的块（十几个位置）；块表实时记录每个逻辑块对应的物理块，逻辑连续、物理可散落各处。分页还附带共享福利：并行采样、beam search 等同前缀候选可指向同一份物理块，只在某候选要改写时才复制该块（写时复制），省显存也省拷贝时间。
3. **关键证据或数字**：显存利用率冲到 96% 以上、浪费从 6–8 成压到 4% 以下；vLLM 对比原始 HuggingFace 实现，吞吐最高快 24 倍。
4. **结论/判断**：PagedAttention 优化的是显存管理，不改变注意力的数学；与优化计算读写的 FlashAttention 是两回事，面试切勿混淆。

## 可迁移

- 推理 infra 面试连招：先估 KV Cache 大小，再指出连续分配的三种碎片，最后甩出分页 + 块表映射 + 前缀共享/写时复制，是一条完整答题链。
- RL rollout 用 vLLM 时同理：高并发采样下 KV 显存是吞吐上限，分页与前缀共享直接决定一批能塞多少条轨迹。
