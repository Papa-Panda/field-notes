## 一句话总结

GRPO 训练后期的熵突然暴涨、梯度爆炸、奖励归零是一种独立于熵坍塌的临界失稳：根源是正负样本对熵的作用不对称与 token 级熵流长期失衡，常规旋钮救不回来，修法是把熵稳定在一个区间而非一味压低。

## 核心

1. **问题/背景**：症状面板很典型——策略熵在几十步内从约 0.1 冲到 1 以上，梯度范数同步飙升，reward 从平台期断崖跌回起点；换数据、降学习率、加大 KL、放宽最大长度、降采样温度等常识清单全部无效，说明这不是某个旋钮的问题，而是训练动力学走到了临界点。它与熵坍塌不同：不是慢慢失去多样性，而是突然失控。
2. **机制/方法**：机制一（ScopeRL 的分析）：softmax 策略下正、负优势样本的更新对熵的作用不对称——高温采样下正样本更新推高熵、负样本更新压低熵；训练前期负样本多，压熵占上风，熵一路下降、模型越来越确定，临界点后策略对少数模式过度自信，一旦采到意外的正样本或分布外题目，更新方向剧烈反转把熵猛推上去，形成尖峰。机制二（OOPF 的 token 级统计）：逐 token 统计更新对熵的贡献，发现降熵 token 长期压过升熵 token，熵流严重失衡，而现有熵正则与比率裁剪都没碰这个根因；失衡积累到后期，模型过度确定，梯度出现爆炸性更新与剧烈波动。故熵尖峰不是熵坍塌的反面，而是同一失衡走到尽头的后果。
3. **关键证据或数字**：修法两条——ScopeRL 用温度自适应的正样本构造正则项把熵稳定在区间内，pass@1 与 pass@k 同时优于强基线，并发现探索是非单调的、存在最优水平（完全坍塌与无限制探索都不是最优）；OOPF 按各 token 的实际贡献重标定升熵与降熵的更新、严格保持 on-policy，在六个数学基准上同时提升稳定性与最终性能。
4. **结论/判断**：排查顺序应为：先排除更常见的病因（低成功率任务负样本主导、截断样本、clip 缺口、训推不一致），再看熵曲线形态（慢降到底是坍塌、先降后尖峰是本故障），然后上熵控制（温度自适应正则或熵流重标定，目标是稳在区间），并加密 checkpoint、尖峰出现即回滚配合更小学习率过临界点。

## 可迁移

- RL 训练监控要把熵曲线形态当一等诊断信号：坍塌与尖峰是两种病、两种药，混为一谈会越调越糟。
- 面试排障题里讲出「正负样本不对称」与「token 级熵流失衡」两个机制词，基本就是满分答案骨架。
