2一句话总结

32B
模型单张 H100 就能跑

QeRL 把冻结的基座权重压到 NVFP4、只训 LoRA，量化误差对 logits 的扰动意外地把策略分布压平、抬高熵，等于一份免费的探索奖励；再用 AQN 把可衰减的高斯噪声并进 RMSNorm 缩放参数，精度追平全参微调，显存省六成，32B 模型单张 H100 就能跑 GRPO。

3核心

  1. 问题/背景：直觉上把模型压到 4-bit 再做 RL 应该掉精度，NVIDIA 的 QeRL 给出反直觉结论：不掉，探索反而更好。先厘清架构：量化的是冻结的基础权重，训练的是旁边的 LoRA 适配器，并不是 4-bit 全参数训练。
  2. 机制/方法：量化即把连续权重吸附到最近格点（NVFP4：每 16 个数共享一个 FP8 缩放、整张矩阵再共享一个 FP32 缩放），吸附误差对前向而言是一个固定的小扰动，最终落到 logits 上。关键洞察是这个扰动对 RL 是好事：logits 被抖动后 softmax 分布变平、采样熵升高，模型更愿意尝试不同回答，即探索变强，且全程不需要额外的显式熵奖励。静态噪声的问题是它不随训练阶段变化——早期需要多探索、后期需要收敛——于是 AQN（自适应量化噪声）把高斯噪声并进 RMSNorm 的缩放参数：在通道维度加噪等价于把噪声吸收进归一化权重，推理内核一行不改；噪声标准差按指数衰减调度。
  3. 关键证据或数字：熵曲线上 4-bit 模型的策略熵在整个训练中一直高于 16-bit 模型，奖励约 200 步就起来，普通 LoRA 要 500 步以上。精度上，Qwen2.5-7B 在 GSM8K：全参微调 91.2，QeRL+AQN 90.8（仅低 0.4），16-bit LoRA 88.1，QLoRA（NF4）只有 85.0；MATH500 上 QeRL 77.4 与全参一模一样。QLoRA 掉得多是因为 NF4 量化误差更大、又没有噪声调度，探索的好处没吃到、精度损失吃满。AQN 的噪声标准差在 GSM8K 约 600 步内从 0.01 衰减到 0.0005。效率上，7B 模型显存 5.9 GB 对 16-bit LoRA 的 15.2 GB（省 61%，另一口径省 64%）；单张 H100 端到端 GRPO 比 LoRA 快 1.5 倍、比 QLoRA 快 1.8 倍，rollout 阶段快 1.1–2 倍（4-bit 权重用 Marlin 内核算得快）；32B 模型一张 80 GB 的 H100 就能跑 GRPO。
  4. 结论/判断：量化在 RL 里是「省显存还送探索」的双收益，但要分清对比对象：显存数字是和 16-bit LoRA 比、不是和全参比。边界也要记住：论文最大验证到 32B、任务集中在数学，70B 与 Agent 任务不能直接外推。实操三条：用 QeRL 时记清「量化冻结基座 + 训 LoRA」；评估时别只看熵曲线，还要看奖励上升速度与最终精度；PEFT 侧已有 NVFP4+LoRA+噪声调度的集成 issue 可以跟进。

5可迁移

  • RL infra 选型时把量化从「精度税」重新归类为「带探索红利的压缩」：rollout 占大头时，4-bit 权重同时省显存、加速生成、抬熵，三处都对着 RL 的瓶颈。
  • 面试问 RL 怎么省显存，除 ZeRO/offload 外可答 QeRL 这条线，并点出 AQN「噪声并进归一化缩放、内核不改」的工程巧思。
