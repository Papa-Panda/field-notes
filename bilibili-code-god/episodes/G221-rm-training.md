## 一句话总结

奖励模型（RM）不学绝对打分，而是从 SFT 模型改造出一个标量输出头，用人类对同一问题多个回答的排序、经成对比较损失学出"好回答得分更高"，从而把人类偏好规模化地注入 RLHF。

## 核心

1. **问题/背景**：RLHF 的 PPO 阶段每一步都要给回答打分，不可能每次请真人评判，必须先训一个能自动打分的"裁判"；但让人直接打绝对分数噪声极大（同一人不同心情分数漂移），改让标注员对同一问题的多个回答排序，相对判断稳定得多。
2. **机制/方法**：RM 结构改动极小——取 SFT 模型，去掉输出词表概率的最后一层，换成只输出单个标量的小层，整体变成一个回归模型。训练用成对比较损失：排序靠前的回答记为正例、靠后的记为负例，两者分数之差过 sigmoid 后取对数似然，最大化正例胜过负例的概率（即 Bradley-Terry 模型）。同一问题的全部回答对打包成一个 batch 一起算，既省显存又防过拟合。
3. **关键证据或数字**：InstructGPT 的 RM 只有 6B 参数，刻意不用 175B 的最大模型——裁判不需要和选手一样大，小模型更省算力、训练更稳。
4. **结论/判断**：RM 的质量直接决定对齐上限：它本质上是人类偏好的可微代理，后续 PPO 优化的其实是这个代理而非人类本身。

## 关键数字

| 项 | 数值 |
|---|---|
| InstructGPT RM 参数量 | 6B（对比策略模型 175B） |
| 标注形式 | 同题多回答排序，而非绝对打分 |
| 损失 | 成对比较（Bradley-Terry）：$-\log \sigma(r_w - r_l)$ |

## 可迁移

- 面试高频题"RM 怎么训"：答题骨架 = SFT 模型换标量头 + 排序数据 + pairwise loss + 同题打包一个 batch，四点缺一不可。
- 做偏好数据时优先收集排序而非分数：标注一致性更高，后续 DPO 等方法也能直接复用同一批成对数据。

## 疑问 / 下一步
