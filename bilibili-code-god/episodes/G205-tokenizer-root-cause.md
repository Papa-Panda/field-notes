## 一句话总结

模型看到的世界是按语料频率切出的 token 碎片而非完整字符与数字，数不清字母、算不对乘法都是这一表征盲区的必然结果。

## 核心

1. **问题/背景**：BPE 按子串在语料中的频率切分，不按单词或数字的完整性切：高频的 100 保留为单个 token，低频的 2026 被切成四个碎片；strawberry 被切成三个 token 后，字母边界对模型不可见。
2. **机制/方法**：算不对乘法是三重根因叠加——数字被切碎看不到完整数值；生成方向从左到右与乘法从低位到高位进位的方向相反；模型本质做的是 token 间统计模式匹配而非执行算术规则。一个反直觉的缓解法是把数字逆序输入，让左到右生成恰好对齐低位到高位的进位顺序，准确率显著提升。
3. **关键证据或数字**：strawberry 有 3 个 r，模型常答 2 个——不是推理不行，而是 token 层面根本看不到字母。
4. **结论/判断**：新一代的三条改善路线是：tokenizer 层把数字按位切分（如 LLaMA 3）；推理层用长思维链分步计算加自我验算（如 o1、DeepSeek-R1），用算力换准确率；系统层遇到精确计算直接调用计算器工具。根因仍在，主要是绕过而非根除。

## 可迁移

- 评测模型算术/计数能力时先确认 tokenizer 的数字切分方式，否则测到的可能是分词伪影而非推理能力。
- Agent 场景的工程结论：精确计算交给工具调用，不要指望模型在 token 碎片表征上内生地算对。
