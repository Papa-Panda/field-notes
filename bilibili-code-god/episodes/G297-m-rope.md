## 一句话总结
普通 RoPE 只能编码一维位置、图片拉平后二维空间感全丢；M-RoPE 把每个 token 的位置拆成（时间、高、宽）三元组，并把旋转频率分成三组分别旋转，一套编码通吃文本、图片和视频。

## 核心
1. **问题/背景**：RoPE 按一维序号旋转向量来编码位置，文字天生一维所以很合适；但图片是二维 patch 网格，拉平成一维序列后，上下相邻的 patch 在序列里相距很远，模型只知道「排第几」、不知道谁在谁上面/右边；视频再加一维时间，一维位置彻底装不下。
2. **机制/方法**：两个动作——① 位置拆三轴：每个 token 的位置不再是一个数，而是（时间、高、宽）三元组，时间管第几帧、高管第几行、宽管第几列；② 频率分三组：把 RoPE 向量里的旋转频率维度切成三组，分别用时间、高、宽坐标去旋转同一个向量，三个维度的位置信息同时写进一份编码。
3. **关键证据或数字**：三种输入的兼容方式是关键推导——纯文本时三坐标取相同值同步递增，M-RoPE 严格退化回普通 RoPE，与原有文本处理完全一致；图片时时间坐标固定、高/宽取 patch 的行列号，二维坐标原样保留；视频时时间坐标取帧号逐帧递增、高/宽仍是帧内行列。附带福利：高、宽被限制在图片行列范围内，位置索引数值更小，向更长序列/更长视频外推更容易。
4. **结论/判断**：M-RoPE 没有发明新机制，只是把「一个位置数」升级成「三轴坐标 + 分组旋转」，就让文本、图片、视频共用同一套位置编码混训不打架，是多模态架构里低成本高回报的设计。

## 可迁移
- 理解多模态模型时先问位置编码怎么处理维度差异：凡是「拉平多维数据喂 Transformer」的方案，都要交代空间关系靠什么保留，M-RoPE 的三轴拆分是最常见的答案模板。
- 面试速记：文本三坐标相同（退化 RoPE）、图片时间固定（高宽 = 行列）、视频时间 = 帧号——三句话即可完整复述。
