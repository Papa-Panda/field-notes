## 一句话总结

把视觉编码器和语言模型两头全部冻结，只训练中间的 Q-Former 小桥，用 32 个可学习 query 经 cross-attention 把视觉特征压成 32 个视觉 token 喂给 LLM，不端到端也能看图说话。

## 核心

1. **问题/背景**：视觉编码器 + 语言模型端到端联训，两个几十亿到上百亿参数的模型一起更新，显存算力顶不住，还容易把语言模型原有能力训废。问题是：能不能不动两个大模型，照样把它们接起来？
2. **机制/方法**：两头冻结、只训中间桥。Q-Former 内置 32 个可学习 query 向量，以 query 作 $Q$ 、冻结的视觉特征作 $K$ 和 $V$ 做 cross-attention，一轮轮从视觉特征里「提问」，把对后续生成有用的信息吸到 query 上；出口恒定为 32 个视觉 token，无论输入视觉特征有多少。训练分两阶段：第一阶段只配冻结视觉编码器，用海量图文对做对比/匹配类任务，先学会抽出与文字对齐的视觉信息；第二阶段把 Q-Former 输出接到冻结 LLM 前面当视觉提示，学会据此生成文本。
3. **关键证据或数字**：视觉特征一张图可达 200 多个块、每个上千维，直接塞给 LLM 又长又贵；Q-Former 把它恒定压到 32 个 token。视频给出的量级是：真正更新的只有约 1.2 亿参数的 Q-Former，而冻结的视觉塔（几亿）与语言模型（几十上百亿）全程不参与反向传播。
4. **结论/判断**：省钱的秘密全在「冻两头、训中间」——桥的参数量比两头小一到两个数量级，同一张卡要扛的从一整头多模态巨兽缩成中间一小段。

## 关键数字

| 项 | 数值 |
|---|---|
| 可学习 query 数 | 32 个 |
| Q-Former 出口 | 恒定 32 个视觉 token |
| 实际训练参数量 | 约 1.2 亿（两头大模型全冻结） |

## 可迁移

- 这是 PEFT 思路在多模态连接层的版本：冻结骨干、只训轻量适配模块，训推成本与灾难性遗忘风险同时下降，做 post-training 系统设计时同理优先考虑「哪部分真的需要更新」。
- 面试高频：被问多模态对齐方案时，能说清 Q-Former 与 LLaVA 式线性投影的区别——前者用可学习 query 做注意力式压缩（输出 token 数恒定），后者是逐 patch 投影（token 数随分辨率涨）。

## 疑问 / 下一步

- query 只有 32 个，细粒度视觉信息（如 OCR、小目标）会不会被压丢？值得对比 Q-Former 与高分辨率直连方案在文档理解类任务上的差距。
