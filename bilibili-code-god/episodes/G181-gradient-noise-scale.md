## 一句话总结

batch size 存在可计算的临界值：用约一百步小实验测出梯度噪声尺度，就能直接推算最优 batch，不必在大集群上试错。

## 核心

1. **问题/背景**：batch 太小则梯度噪声大、更新频繁但每步不准；batch 太大则梯度准但更新次数少。两者之间存在临界 batch size，在它之下增大 batch 能同时提升速度与效果，超过之后收益急剧递减，纯粹浪费算力。
2. **机制/方法**：把每步梯度看作真实梯度加噪声，噪声尺度定义为梯度方差与真实梯度模长平方之比；batch 越大，噪声被平均掉越多，噪声尺度正是定位拐点的量。
3. **关键证据或数字**：实操只需在当前配置下跑约 100 步，记录每步梯度并计算方差与均值之比，按 OpenAI 的公式换算即得最优 batch 的估计；结论可从小规模直接外推到大集群。另外噪声尺度随训练推进会下降，意味着理论上 batch 应越训越小。
4. **结论/判断**：batch 该多大不是经验玄学，噪声尺度给了一个几分钟就能算出的定量答案。

## 关键数字

| 量 | 说明 |
|---|---|
| 测量成本 | 约 100 步小实验 |
| 噪声尺度 | 梯度方差 / 梯度模长平方 |
| 最优 batch | 约等于噪声尺度量级，超临界值后收益递减 |

## 可迁移

- 做 RL / SFT 扫参时，先花几分钟测噪声尺度定 batch，比网格试错便宜得多。
- 面试被问「batch size 怎么选」时，用「临界 batch + 噪声尺度随训练下降」作答比背经验值更有说服力。
