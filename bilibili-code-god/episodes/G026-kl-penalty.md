## 一句话总结

reward model 一定会被模型讨好，KL 惩罚就是那根绳子：reference model 冻住不动，策略每生成一个 token 就量一次距离并按 β 扣分；β、估计方法与放置位置（进奖励还是进损失）都要按任务选，长推理场景甚至直接把 KL 删掉。

## 核心

1. 问题/背景：上一期讲 reward model 能被讨好（reward hacking），模型一定会去钻空子，除非有人拽着——拽人的就是 reference model。
2. 机制/方法：reference model 就是 SFT 那一版、冻住不动；策略每写一个 token，就量一下当前策略与它之间的 KL 距离，乘上系数 β 从奖励里扣，跑得越远扣得越多。KL 无法精确计算，只能采样估计：常用的 k3 估计是「比率减一再减对数比率」，无偏且恒为正，GRPO 用的就是它。
3. 关键证据或数字：InstructGPT 取 β = 0.02，其附录扫过一遍：0 和 2 都差，最好落在 0.01–0.02 附近；但把 β 拉到 2（放大一百倍）也救不回公共任务上的掉分，所以才另外混入预训练梯度（即 PPO-ptx 的由来）。GRPO 的放法不同：不把 KL 放进奖励，而是直接加进损失，β 取 0.04。而做长推理时，DPO 一类做法更干脆，把 KL 整个删掉。
4. 结论/判断：一句话记法——KL 是绳子，β 是绳长，放哪取决于任务：对齐类任务把惩罚放奖励里、β 取小；GRPO 放损失、β = 0.04；长推理则无绳裸奔换探索空间。

## 关键数字

| 工作 | β | KL 放置 |
|---|---|---|
| InstructGPT | 0.02（最优区间 0.01–0.02） | 奖励中扣除 |
| GRPO | 0.04 | 直接进损失（k3 估计） |
| 长推理做法 | — | 删去 KL |

## 可迁移

- 调 RLHF 时先定位三件事再动手：β 量级（0.01–0.04 一带）、估计用 k3、放置位置与任务匹配；β 拉满也救不回的掉分，要靠混预训练梯度等结构手段，而非继续加绳。
- 面试讲 KL 惩罚时把「拴谁、绳长多少、绳系在哪」三点说清，比只背公式完整。
