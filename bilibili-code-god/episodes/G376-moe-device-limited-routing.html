DeepSeek-V2 的设备受限路由（device-limited routing）

2一句话总结

MoE 的卡间通信量正比于单个 token 触达的卡数，设备受限路由先选卡再在卡内选专家，把每个 token 的通信范围焊死在至多 $P$ 张卡内。

3核心

  1. 问题/背景：MoE 用门控网络给每个专家打分，每个 token 只激活 top-$k$ 个专家，参数可以做大而计算稀疏。但专家分散在多张卡上，一个 token 选中的专家可能横跨十几张卡，隐藏向量要经卡间通信逐卡发送、算完再收回，通信成为训练最大瓶颈。
  2. 机制/方法：三步走。先把专家平均分到 $M$ 张卡上、每卡专家编号连续；再以每组内最高专家概率作为该组分数，挑出分数最高的 $P$ 组，锁定这 $P$ 张卡为唯一允许的目标卡；最后只在这 $P$ 张卡覆盖的专家里取全局概率最高的 $k$ 个作为最终路由。
  3. 关键证据或数字：示例中 8 个专家分在 2 张卡（每卡 4 个），取 $P = 1$ 、 $k = 2$ ：比较两组最高概率（0.55 对 0.9）锁定 1 号卡，再在该卡内取 0.9 与 0.7 两个专家。DeepSeek 的实验表明 $P \ge 3$ 时效果几乎追平无限制 top-$k$ 路由。
  4. 结论/判断：实现上就是分组、选组、组内 top-$k$ 三步（排序 + 切片几行代码）；通信量有了硬上限，精度损失几乎可忽略。

4关键数字

量 值
示例配置 8 专家 / 2 卡 / $P = 1$ / $k = 2$
无损的经验阈值 $P \ge 3$ 时效果 ≈ 无限制路由
通信成本 正比于 token 覆盖的卡数，被限制在 $P$ 以内

5可迁移

  • MoE 训练的通信优化核心是控制 all-to-all 的扇出范围；专家并行（EP）调参时先想清楚每 token 的目标卡上限，再谈带宽。
  • 面试写这题要先讲清「通信正比于覆盖卡数」这个成本模型，再给三步算法，顺序反了会显得只背代码。
