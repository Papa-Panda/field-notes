## 一句话总结
完整后训练 pipeline 是 PT → SFT → 偏好对齐 → 能力精化四层垒叠，偏好对齐三选一，而 PAFT 把 SFT 与 DPO 并行再合并，有时优于串行。

## 核心
1. **问题/背景**：从基座到可用产品要经过目标各异的多个阶段，顺序与取舍取决于资源和需求，不是每一步都必做。
2. **机制/方法**：预训练在万亿 token 上做 next-token prediction 学知识与语言规律，产出的基座只会续写、不会听指令；SFT 用几千到几万条指令-回答对教对话格式，是对话模型的必经之路，只跑 1–2 个 epoch 防过拟合、数据质量重于数量；偏好对齐三选——DPO 最轻量（只需偏好对、不用训奖励模型），PPO 版 RLHF 效果最强但要 Actor/Critic/Reference/Reward 四模型同训、显存与调参成本最高，SFT 够用时也可跳过。PAFT 范式则把 SFT 与 DPO 在同一基座上并行训练再合并权重，避免串行时 DPO 覆盖 SFT 学到的格式能力。
3. **关键证据或数字**：阶段成本对比悬殊——预训练需数千 GPU 跑数月，SFT 数据量仅万条量级；PPO 的四模型同训是其贵的主要来源。
4. **结论/判断**：简单场景用 SFT + DPO 串行，追求极致效果用 PPO 或 PAFT 并行；四步的顺序本质是能力逐层垒加，不能乱序。

## 可迁移
- 面试讲后训练全景时按「每阶段解决什么问题、能不能跳、代价是什么」组织，比背算法名更显工程判断。
- PAFT 的动机（后续阶段覆盖前阶段能力）与持续学习里的灾难性遗忘是同一类问题，可互相印证。
