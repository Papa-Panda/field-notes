## 一句话总结

推理模型答对后仍继续反思是 RL 只奖励「答对」、从不奖励「答完就停」训出来的；RIRM 给答后反思 token 负奖励、RAPO 把它嵌进策略梯度，反思 token 砍掉九成、推理成本降约 75% 且质量不掉。

## 核心

1. **问题/背景**：把一次数学推理的输出按 token 时间线摊开：前面一小段在真正解题，答案已经正确后模型仍不停止，后面一大串是重新检查、换个角度再算一遍的反思。更反直觉的是，反思可能帮倒忙——已经算对的答案在反思中被改错。
2. **机制/方法**：根源在 RL 的奖励设计：只奖励最终答对，写 100 字答对与写 1 万字答对拿同样的正奖励，从没有奖励发给「答完及时停」，于是策略梯度自然把模型推向更长的思维链。解法两招：RIRM（反思抑制奖励机制）对答案正确之后仍继续反思的 token 给显式负奖励；RAPO（反思感知策略优化）把 RIRM 嵌进策略梯度，从训练源头教会模型答完就停——区别于推理时事后截断。
3. **关键证据或数字**：Yuan3.0 Flash（400 亿总参数、激活 37 亿的稀疏 MoE）实测：答后反思占总 token 的 71.6% ；加 RIRM + RAPO 后该占比压到 23.4% ，反思阶段 token 砍掉 90.58% ，整体推理成本降约 75% ，质量未掉（被砍的本是注水部分）。
4. **结论/判断**：推理模型的啰嗦是 RL 训出来的病，要在训练里给「答完就停」一个正反馈，而不是靠推理时剪枝。

## 可迁移

- 做 reasoning RL 时把「答对后的冗余长度」作为单独监控指标：奖励只看最终对错时，长度膨胀是默认趋势，需要显式的停机激励对冲。
- 评估推理模型成本时先做 token 时间线分解，区分解题 token 与答后反思 token，再决定优化手段。
