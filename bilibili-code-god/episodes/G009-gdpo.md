## 一句话总结

多奖励先相加再组内归一化会把不同的结果组合压成同一个优势值，信号分辨率坍缩、GRPO 训到约 400 步就崩；GDPO 改成每个奖励单独归一化再相加、最后 batch 归一化，分辨率从约 50 种回到 480 多种，AIME 涨 6.3 分且全程不崩。

## 核心

1. **问题/背景**：GRPO 的核心动作是对同题一组采样按组内均值、标准差算优势，只看相对位置，会扔掉一部分「差多少」的信息。单奖励时没问题；正确性、格式等多个奖励先加成总分再归一化，麻烦就来了。
2. **机制/方法**：最小例子：两条回答、两个二值奖励，总分组合共 6 种（0-0、0-1、0-2、1-1、1-2、2-2 的配对）。先加总再归一化后，(0,1)、(0,2)、(1,2) 三种全变成 $\pm 0.71$ ，另三种全变成 0——6 种情况坍缩成 2 种，「对了一半」和「一条全对一条全错」拿到完全相同的训练信号。组放大到 12 条、两个奖励时，GRPO 能区分的优势组合只有约 50 种。GDPO 三步修法：每个奖励单独在组内归一化；归一化后的优势相加；整个 batch 再归一化一次，防止奖励越多优势数值越大。回到例子：(0,1) 仍是 $\pm 0.71$ ，(0,2) 变成 $\pm 1.41$ ，终于分开。
3. **关键证据或数字**：工具调用任务上 Qwen2.5-1.5B（字幕口径）准确率 30.18 → 32.81、格式正确率 76.33 → 80.66；数学上 DeepSeek-R1-1.5B 的 AIME 23.1 → 29.4、MATH 83.6 → 86.2，超长输出比例 10.8% → 6.5%。稳定性是更大的差异：GRPO 约 400 步后正确性奖励下滑、回答长度暴涨（训崩），GDPO 一路稳步上升。对照实验：学 Dr. GRPO 去掉标准差只多分出一点点信号，且工具调用任务上格式正确率直接掉到零、训练失败。
4. **结论/判断**：还有一个难度悬殊时的实操细节：长度奖励很容易、正确性很难时，模型会先把容易的刷满，光调权重没用；正确做法是把简单奖励绑到难奖励上——只有答对了才给长度奖励，否则一律零。这一招让 AIME 再涨 4.4 分、超长率再降 16.9 个百分点。代码改动就是几行：按奖励各自归一化、再相加、再 batch 归一化。

## 可迁移

- 任何多奖励 GRPO 管线（正确性 + 格式 + 长度 + 工具调用成功率）先检查归一化顺序：先加总再归一化就是在主动抹平信号。
- 奖励难度悬殊时不要只调权重，把易得奖励 gate 在难奖励之后，是防 reward hacking 的便宜招。
