## 一句话总结

RFT 让模型自己高温采样、只保留被规则验证答对的轨迹做 SFT，是介于静态 SFT 与完整 RL 之间、可多轮迭代的轻量自举闭环。

## 核心

1. 问题/背景：SFT 数据是静态的，有什么训什么，人工标注成本高；推理能力提升又不想一上来就搭 RL 全套机制。
2. 机制/方法：五步闭环——准备只有 prompt、没有标准答案的可验证题目（数学、代码等）；对每个 prompt 用高温采样生成多个回答以增加多样性；用规则验证对错（数学比答案、代码跑测试）；只保留正确回答作为训练数据；拿这批数据做 SFT。训完后可用更强的模型重新采样，进入下一轮。
3. 关键证据或数字：每个 prompt 的采样数建议在 8–32 之间；若某批题正确率低于 10%，说明难度过高、需要掺入简单题；每轮做 1–3 个 epoch 的 SFT；通常迭代 2–3 轮、每轮收集几万到几十万条正确轨迹后收益就趋于饱和。
4. 结论/判断：RFT 本质是 RL 的极简版——用对/错二值信号做一次性筛选代替逐步 reward，不需要 reward model、不需要 critic、也不需要 PPO 那套机制；代价是只利用了正确轨迹、丢掉了错误轨迹里的负信号，上限低于完整 RL。但因为学的是模型在自身能力分布内走通的路径，比套用外部标准答案更贴合模型实际水平，工程性价比最高。

## 关键数字

| 项 | 取值 |
|---|---|
| 每 prompt 采样数 $N$ | 8–32 |
| 题目正确率下限（低于此加简单题） | 10% |
| 每轮 SFT epoch | 1–3 |
| 迭代轮数 | 2–3 |
| 每轮正确轨迹量 | 几万–几十万条 |

## 可迁移

- 数据 curation 主线：在可验证任务上，先跑通 RFT 自举闭环再考虑上 RL，是成本最低的推理数据生产线；迭代时每轮都要重新评估难度分布，避免只剩简单题。
- 面试要点：RFT 与 RL 的区别可一句话说清——RFT 是离线二值筛选 + SFT，没有 critic 与 advantage 估计；与 Best-of-N / 拒绝采样的关系也常被追问。
