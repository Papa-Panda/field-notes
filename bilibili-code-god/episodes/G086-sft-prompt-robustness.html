3核心

  1. 问题/背景：线上常见投诉是同一需求换个说法、模型答得完全不同。先定义指令敏感性：同一任务写 $N$ 种意思相同的指令（如「总结这段话」「用一句话概括」「提炼要点」），分别跑一遍取分数的标准差；标准差大即对措辞敏感。该指标与任务无关、凡有分数的任务都能算。敏感的根源是指令分布覆盖问题：措辞决定模型进入哪个模式，预训练里不同说法出现的上下文不同、先验不同；SFT 只见过一种说法的指令，另一种说法就是分布外。
  2. 机制/方法：在 Qwen3 多个规模上做实验（任务为 MS MARCO 类，并用其他模型交叉验证），比较 SFT 前后的敏感性；同时对比两种打分协议：自由生成（生成答案再判分）与似然/强制选择（给定候选比较概率）。
  3. 关键证据或数字：1.7B 与 4B 上 SFT 稳定把敏感性降低 54%–71%；8B 上单次训练的变化与零无统计差异（方向在随机种子间一致，但幅度小到不显著）——模型越大，SFT 对措辞鲁棒性的改善越小，因为大模型本来就不那么敏感、或 SFT 改不动它。更麻烦的是评测协议：同一模型、同一组改写指令，生成式与似然式可能得出定性相反的结论，即使模型生成有效标签的比例近乎完美；原因是似然比较看内部偏好、生成看采样结果，两者对措辞的敏感程度不同。
  4. 结论/判断：鲁棒性要测、不能假设。实操：上线前每个任务备 $N$ 种改写指令算标准差；评测方式必须与线上一致（线上是生成就用生成测，别拿似然结论当鲁棒性结论）；小模型可依靠 SFT 改善，大模型要靠数据端——SFT 数据里把指令做多样化改写；把敏感性纳入回归指标、每次迭代都测。

规模 SFT 后敏感性变化
1.7B / 4B 降低 54%–71%

5可迁移

  • 评测协议一致性原则：任何离线鲁棒性/质量结论，先确认打分方式与线上 serving 路径一致，否则结论可能反号——这条对 judge/rubric 评测同样成立。
  • 数据侧解法：指令多样化改写进 SFT 数据，是比加训练量更对症的鲁棒性投入，尤其对大模型。
