2一句话总结

多轮交互 RL 里 GRPO 混组比较会把「裁判的风格偏好」当成信号学走，ARC 用按策略分组消掉策略间方差，FACA 则把模拟用户的下一句话变成免费的局部奖励。

3核心

  1. 问题/背景：客服、工具类 Agent 要与（模拟）用户来回多轮，同一请求往往有多种都成立的应对策略（直接回答、先澄清、先汇报进度、行动前确认），但奖励模型对风格有系统性偏好。GRPO 把不同策略的回答混在同一组里比高低，模型学到的可能不是「何时该澄清」，而是「裁判喜欢哪种风格」。
  2. 机制/方法：优势方差可拆为策略内方差与策略间方差，后者来自裁判偏好、加大采样量也消不掉。ARC 给每条样本标注策略类别、按策略条件采样、只在同策略组内算优势，并用 answer 标签把用户可见回复与不可见的推理/工具调用分开。FACA 从另一头挖信号：让冻结的用户模拟器给每句话附带私有行为标签，映射为推进（+1）、无效（0）、倒退（−1）三值，对齐到前一段 Agent 动作、组内归一化后以不超过 0.5 的系数加到结果优势上，不加 critic、不加额外模型。
  3. 关键证据或数字：ARC 在 τ-airline 上 31.33 → 44.00（+12.67），其他骨干与基准普遍上涨，平均约 +5.37，首次响应延迟 4.91 秒 → 1.27 秒；普通 GRPO 训练中期见顶后回落，ARC 曲线保持平稳。FACA 在 8B 上 34.66 → 40.57（+5.91），14B 上 42.51 → 52.73（+10.22）；把反应标签的正负号随机打乱后成绩跌到基线以下，证明增益来自信号本身。另有一个反直觉现象：训练期用的策略提示在部署时保留反而掉分（41.73 → 39.85），它只是控方差的训练期脚手架，上线要撤。
  4. 结论/判断：多轮 RL 的稠密信号一直藏在对话过程里——策略分组负责去噪，用户反应负责补局部奖励；两者的前提都是一个先校准好的用户模拟器（如把 LLM 模拟用户放进工具 RL 回路、用「像不像真人」训模拟器等工作）。

5可迁移

  • 做多轮 Agent RL 时，先检查组内样本是否混了多种合法策略：混组优势里有一块消不掉的策略间方差，按策略分组是近乎免费的修法。
  • rollout 里模拟用户的反应是现成的过程信号：映射成三值、系数压在 0.5 以内、对齐到前一段动作，比再训一个过程奖励模型便宜得多。
