## 一句话总结

RetNet 用带指数衰减矩阵的 retention 机制替代注意力，同一个公式既能写成训练时的并行矩阵运算、又能展开成推理时的 O(1) 递推，是对「训练并行 / 推理 O(1) / 高精度」不可能三角的第一个严肃挑战。

## 核心

1. **问题/背景**：序列建模有个不可能三角——训练并行、推理 O(1)、高精度只能取其二：Transformer 占了前两者但推理要维护越攒越大的 KV cache；RNN 推理 O(1) 但状态必须逐步算、训练无法并行。
2. **机制/方法**：retention 与注意力形式几乎一样，差别只在衰减矩阵 $D$ ：其元素满足 $D_{ij} = \gamma^{i-j}$（ $i \geq j$ 时生效，否则为 0），即离当前位置越远的 token 贡献按 $\gamma$ 的幂次指数衰减， $\gamma$ 典型取 $0.9$ 到 $0.99$ 、每个头不同且固定不学习。核心公式：

$$ \mathrm{Retention}(X) = (QK^\top \odot D) V $$

   同一个公式有两种等价算——训练用并行形式，整段做矩阵运算，和 Transformer 一样快；推理用递归形式，状态按 $S_n = \gamma S_{n-1} + K_n^\top V_n$ 更新、输出为 $Q_n S_n$ ，状态大小与序列长度无关，故每步严格 O(1)。
3. **关键证据或数字**：6.7B 规模实测，RetNet 推理吞吐约为 Transformer 的 8 倍、显存省约 70%（都源于状态固定不膨胀）；语言建模 perplexity 与零/少样本下游任务与同规模 Transformer 基本持平、个别指标略优。
4. **结论/判断**：同赛道还有 Mamba（状态空间模型 + 硬件感知扫描，长序列最猛）与 RWKV（RNN 现代化、极简），三家目标一致路线不同，胜负未分。RetNet 的短板在超长距离精细建模可能不如全量注意力，且生态工具链远不如 Transformer 成熟，生产替换需谨慎。

## 可迁移

- 面试讲架构演进时，用「不可能三角 + 同一公式两种模式」概括 RetNet，比逐项罗列结构更容易讲清其设计本质。
- 推理 infra 视角：固定大小状态意味着显存与序列长度解耦，长上下文服务的成本模型与 KV cache 路线完全不同。
