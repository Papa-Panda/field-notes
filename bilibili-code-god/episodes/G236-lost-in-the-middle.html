Lost in the Middle（Liu et al., 2023，斯坦福团队）

2一句话总结

长上下文里模型对信息的利用呈 U 型分布：开头和结尾看得清、中间是盲区，RAG 重排的价值之一就是把关键文档挪到模型看得见的位置。

3核心

  1. 问题/背景：上下文窗口越做越大，但「能塞进去」不等于「能用得上」。实验做法是把一摞文档中唯一含答案的那篇分别放在开头、中间、末尾，其余条件不变，测答对率随位置的变化。
  2. 机制/方法：两个根因。其一是训练养成的位置偏好——训练数据里 system prompt 恒在最前、用户问题恒在最后，模型学到「重要信息在头尾」。其二是注意力稀释：上下文越长，每个 token 分到的注意力权重越少，中间位置最吃亏，相当于聚光灯照不到的区域。
  3. 关键证据或数字：答案在开头时准确率约 73%，挪到中间最低跌到约 48%，挪回末尾又回到约 73%，头尾与中间相差 20 多个百分点。更极端的是对照实验：答案放在中间时，模型的表现甚至不如完全不给文档、只凭参数记忆作答——文档给了反而被周围干扰信息带偏。
  4. 结论/判断：长上下文不是堆得越长越好；RAG 的重排步骤把最相关的文档放到靠后位置，等于把答案送回模型的「可见区」，这是 RAG 在长上下文时代仍不可替代的理由之一。

4关键数字

实验条件 准确率
答案文档在开头 约 73%
答案文档在中间 约 48%（最低点）
答案文档在末尾 约 73%
答案在中间 vs 闭卷（不给文档） 给文档反而更低

5可迁移

  • 做 RAG / 长上下文应用时，检索后必须重排：把 top 文档放在上下文末尾或开头，不要按检索原序平铺；评测时也要专门测「答案在中间」的情形，别只看平均分。
  • 面试谈长上下文能力时，能点出 U 型曲线和两个根因（位置偏好 + 注意力稀释），比只说「窗口不够大」深一层。

6疑问 / 下一步

  • 这一现象在新一代长上下文模型（如用大量长文档继续训练过的）上衰减到什么程度，值得找近两年的复现实验对照看。
