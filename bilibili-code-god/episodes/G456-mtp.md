## 一句话总结

MTP 让同一隐藏状态同时预测未来多个 token：训练端监督信号变密、逼模型提前规划表示；推理端把 MTP 模块当自带草稿机做投机解码，DeepSeek-V3 实测接受率 85%–90%、解码吞吐约 1.8 倍。

## 核心

### 1. 问题/背景

自回归生成天生串行：生成长度 $T$ 的文本要跑 $T$ 次前向，GPU 再强也只能一步步等；同时训练时每步只猜下一个 token，监督信号稀疏、数据利用率低。

### 2. 机制/方法

结构是四层：共享词嵌入层之上，串 $K$ 个独立模块（各自带归一化与一个 Transformer 块），每个模块负责一个预测深度——第一个猜下一个、第二个猜下下一个，依次成链、严格保持因果；最上面是共享输出头，把每个模块的结果变成概率分布。

推理有两种玩法：其一，丢掉全部 MTP 模块只留主模型，速度不变但因训练得更好而质量白赚；其二，自投机解码—— $K$ 个模块一口气生成 $K$ 个草稿 token，拼回原序列做一次前向并行验证，一致的采纳、遇第一个不一致处截断重来。

### 3. 关键证据或数字

理论上草稿全被接受时，每 $K$ 个 token 只需预测一步加验证一步，生成 $T$ 个 token 从 $T$ 步降到 $\frac{2T}{K}$ 步， $K = 4$ 即提速一倍。DeepSeek-V3 实测：第二个 token 接受率 85%–90%，解码吞吐提升约 1.8 倍。

### 4. 结论/判断

MTP 是少有的训练、推理双赢设计：训练目标变难（多步预测）反而学到更好的表示，推理又能零额外模型地自给草稿，把投机解码的草稿模型成本降为零。

## 关键数字

| 项目 | 标准自回归 | MTP |
|---|---|---|
| 生成 $T$ token 步数 | $T$ | 约 $\frac{2T}{K}$（全接受时） |
| 第二 token 接受率 | — | 85%–90% |
| 解码吞吐（V3 实测） | 基线 | 约 1.8× |
| 额外草稿模型 | 需要 | 不需要（自投机） |

## 可迁移

- RL rollout 是解码密集型负载：MTP 式自投机不用额外部署草稿模型就能提吞吐，是推理栈选型时值得算的一笔账。
- 面试讲投机解码时，MTP 是「草稿从哪来」这个问题的第三种答案：小模型草稿、早退草稿之外，还有训练时就内置的多头草稿。
