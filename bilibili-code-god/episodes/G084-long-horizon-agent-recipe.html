2一句话总结

长程工具 Agent 的 RL 配方由五个轴决定且结论多反直觉：数据约 1K 条、难度 4:3:3 混合最优；奖励密度要匹配模型容量（小模型课程式、大模型稠密+普通 GRPO）；环境工具故障率超 10% 训练直接崩。

3核心

  1. 问题/背景：长程工具 Agent 要连续调用十几步工具（查航班、酒店、景点、算预算），每步输出是下一步输入，最后交付满足全部约束的计划。难点：奖励只在最后、中间步对错难分，工具会失败，样本贵。论文用 TravelPlanner 做测试床，把设计空间拆成五轴逐一消融。
  2. 机制/方法：五轴分别是数据量、奖励形式、四种奖励对比、算法、环境稳定性、模型规模。奖励四种：Dense（各指标加权求和、每步有信号）、里程碑式（只在约束里程碑给分）、Sparse（只看最终成败）、Curriculum（按 epoch 从 dense 过渡到里程碑再到 sparse）。
  3. 关键证据或数字：数据从 100 涨到 1K 成功率快速上升，1K→2K 域内只微涨、域外泛化反而下降（开始记任务模式），约 1K 是甜点；难度须易中难 4:3:3 混合——全难题开局全失败、奖励饥饿学不动，全易题学不到复杂约束。奖励按规模分化：1.5B/3B 受益于课程式奖励与强探索，7B 用简单稠密奖励收敛最好。算法同理：1.5B 上探索增强型算法约 37.5% / 36.9%，GRPO 只有 30.1%；到 7B 标准 GRPO 以 62.8% 最高且更省算力——而万亿参数的 Kimi-K2.5 在该任务只有 15%，差别在配方不在模型。环境注入工具失败：5% 以内影响很小，10% 所有指标一起崩（奖励信号被饿死）。第五轴规模：基座越强越好，加算法不如加参数。
  4. 结论/判断：先定规模、再定奖励：奖励密度匹配容量；约 1K 条高质量样本够用，多了过拟合任务模式；训练期环境错误率压到 5% 以下，工具挂了先修环境再训模型。

4关键数字

变量 设置 结果
数据量 1K → 2K 域外泛化下降，1K 为甜点
算法（1.5B） 探索增强型 vs GRPO 约 37.5% / 36.9% vs 30.1%
算法（7B） 标准 GRPO 62.8%（Kimi-K2.5 仅 15%）
工具故障率 ≤5% vs ≥10% 影响小 vs 全指标崩溃

5可迁移

  • Agent RL 立项清单：数据先备约 1K 条、难度按待训模型实测通过率分层配比；小模型才值得上课程奖励/探索算法，大模型优先稠密奖励+标准算法，把预算留给基座。
  • RL infra 监控：把工具故障率做成训练前置门禁指标（<5%），与奖励曲线分开看，避免把环境问题误诊为算法问题。

6疑问 / 下一步

  • 1K 甜点与 4:3:3 配比是在 TravelPlanner 单一任务上得到的，迁到代码类长程任务时甜点位置是否平移，需要自有消融验证。
