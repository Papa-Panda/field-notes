## 一句话总结

用信息量算账：RL 每条轨迹只给约 1 比特监督，rank 1 的 LoRA 容器就装得下，所以与全参微调等效；而 $\alpha/r$ 缩放决定了 LoRA 最优学习率约为全参的 10 倍，且必须加在所有线性层。

## 核心

1. **问题/背景**：LoRA 用两个瘦长矩阵的乘积表示权重改动，rank $r$ 决定参数容器大小。SFT 里 rank 越低越早掉队（数据信息量超过容器容量），为什么 RL 里 rank 1 反而够用？
2. **机制/方法**：关键是两种训练的信息量不同。SFT 一条样本每个 token 都是监督信号，几百 token 就是几百次纠正；策略梯度 RL 一条完整轨迹跑完只回一个好/坏，约 1 比特。DeepSeek-R1-Zero 约 530 万个 episode 也只约 530 万比特，常见 RL 数据集（1 万题 × 32 采样）只有 32 万比特；而 Llama 8B 上 rank 1 LoRA 有约 300 万参数，容器远大于要装的信息。学习率之谜在缩放系数 $\alpha/r$ ：B 初始化为零、A 随机时，每个 rank 分量的更新期望相同，除以 $r$ 后总更新量与 $r$ 无关；同时 LoRA 每步对原矩阵的改动天然比全参小得多，必须用约 10 倍学习率才走同样的距离。
3. **关键证据或数字**：14 个 Llama/Qwen 模型扫学习率，LoRA 最优值稳定为全参的 9.8 倍且几乎不随 rank 变。指令数据（Tulu 3）上全参与 rank 256 LoRA 的 loss 曲线几乎重合，低 rank 起步跟得上但更早掉队。落位实验：只加注意力层（rank 256，2.5 亿参数）明显落后于只加 MLP 层（rank 128，2.4 亿参数）——MLP 参数占大头、影响力最大，正解是所有线性层都加。LoRA 对大 batch 更不耐受：batch 超 512 与全参差距持续扩大，加 rank 也救不回，有效 batch 建议 32 以内。
4. **结论/判断**：TRL 已把结论做成官方配置——GRPO：rank 小（1 起步）、 $\alpha = 32$ 、target modules 全部线性层、学习率 $1\times10^{-5}$（全参对照 $1\times10^{-6}$ ），奖励曲线与全参重合而显存低一大截；SFT 则 rank 256、 $\alpha = 16$ 。

## 可迁移

- 面试被问 LoRA 的劣势，先反问场景：RL 与 SFT 的 rank 结论相反，根源是监督信息量差了两个数量级。
- RL infra 实践：小 rank LoRA + 10 倍学习率 + 全部线性层 + 小 batch，是低成本跑 GRPO 消融的默认起点。
