## 一句话总结
BLT 扔掉固定词表分词器，让模型直接读原始字节，用一个小模型预测下一字节的熵来动态切 patch——难预测处切细、易预测处切大块，算力按内容难度分配。

## 核心
1. **问题/背景**：主流大模型先用固定词表把文字切成 token 再查编号，但词表训练前定死：对语言不公平（英文常一词一 token，中文与小语种被拆得七零八落），数字与少见拼写也常切乱。直接逐字节建模虽免词表，但字节序列是 token 的好几倍，计算量随长度平方增长，硬算贵到跑不动。
2. **机制/方法**：破局点是按熵切分。先用一个很小的字节级模型预测下一个字节并算出熵（不确定性）：词开头或陌生内容处熵冲高，常见词中间下一个字节几乎闭眼能猜、熵很低。BLT 顺着这条熵曲线切 patch——熵高处切一刀开新 patch，熵低处把好猜的字节合成一大块，切多切少由内容自己说了算。整体三段式：轻量局部编码器把字节串打包成 patch；大而强的主 Transformer 只在 patch 层级计算（patch 数远少于字节数，省下大量算力）；局部解码器再把 patch 还原成字节输出。
3. **关键证据或数字**：实验规模做到 8B 参数、4T 字节训练，效果追平同级别分词模型，推理计算量最多省下一半；同时拼写、数字等细节更稳。
4. **结论/判断**：固定词表是拿一把死尺子量所有内容；BLT 让内容自己决定怎么切——对所有语言字符一视同仁，算力自动往难处倾斜，天生更公平也更可扩展。

## 可迁移
- 「按熵/不确定性分配计算」是一个通用设计模式：patch 切分、动态深度、自适应计算本质同源，面试聊高效架构时可互相印证。
- 评估新架构时注意 BLT 的对照口径：不在 token 层级比，而在等字节/等 FLOPs 下比——这也是它论文里强调 compute-controlled 对比的原因。
