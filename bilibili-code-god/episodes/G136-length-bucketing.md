## 一句话总结

算力不是被长序列吃掉的，是被 padding 吃掉的：按长度分桶、同桶组 batch，再配合先短后长的课程与 packing/varlen，浪费可逐级压下去。

## 核心

1. 问题/背景：训练数据长度差异巨大（几十到上万 token），混在一个 batch 里全部 pad 到最长，短样本的算力被白白浪费。
2. 机制/方法：长度分桶把数据按长度区间分组，每个 batch 只从同一桶采样，同 batch 内长度接近，padding 自然降到最低；边界按长度分布的分位数切，保证每桶样本量均衡。
3. 关键证据或数字：极端例子是一个 batch 里 4000 token 与 50 token 的样本同存，后者要补 3950 个 pad token，浪费高达 98%。DeepSeek 在 V2/V3 中还叠加了分阶段策略：先短序列打基础、再逐步引入长序列扩上下文，效率与长文本能力兼顾。
4. 结论/判断：落地四步——画长度直方图按分位数切 3–5 个桶、同桶组 batch、先短后长渐进拉长、再叠 packing 与变长 attention 把 padding 再降一档；同时监控每桶的训练 loss 防止某桶欠训。

## 关键数字

| 项 | 数值 |
|---|---|
| 极端 padding 浪费 | 50 token 样本在 4000 长度 batch 中约 98% |
| 推荐桶数 | 3–5 个（按分位数切分） |

## 可迁移

- RL rollout 阶段同样受长度长尾支配：group 内长度参差时 padding/等待的浪费与训练侧同源，分桶（按 prompt 难度/预期长度分组采样）是可直接迁移的思路。
- 面试回答训练效率优化时，先量化浪费来源（padding 占比）再谈方案，比直接背 packing 名词更有说服力。
