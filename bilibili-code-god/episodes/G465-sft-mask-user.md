## 一句话总结

SFT 只训练「给定上下文生成助手回答」这一件事：把系统提示、用户输入、工具返回的 label 全设为 -100 让损失跳过，梯度只落在助手回复上，训练目标才与真实推理对齐。

## 核心

1. **问题/背景**：一段训练对话含系统提示、用户问题、助手回答三部分，但模型真正要学的只有「看着前文、写出好回答」；用户说什么、模板怎么写、工具查到什么，都是外部给定、推理时由别人提供的内容。
2. **机制/方法**：实现极简——把非助手部分每个位置的 label 改为 -100，交叉熵按约定跳过 label 为 -100 的位置（不计损失、不回传梯度）；这些 token 模型看得见、可作上下文，但不学着生成。
3. **关键证据或数字**：不 mask 的后果是目标错位：模型会学着模仿用户口吻、在回答前复读问题；会把固定系统提示一字不差背下来、换个模板就失效；会去记忆工具返回的易变事实，而不是学如何组织语言转述。mask 规则一句话：凡外部给定、不用模型生成的内容一律 mask。
4. **结论/判断**：mask 带来四点收益——梯度全用在组织回答上、防提示词复读、任务边界清晰、训练与推理彻底对齐（推理时模型本就只需续写回答）。

## 关键数字

| 对话部分 | 是否 mask | 原因 |
| --- | --- | --- |
| 系统提示 | 是 | 防背诵模板、保泛化 |
| 用户输入 | 是 | 外部给定，不学模仿用户 |
| 工具返回 | 是 | 外部事实易变，只学转述 |
| 助手回答 | 否 | 唯一训练目标 |

## 可迁移

- 数据管线落地：拼 SFT 样本时同步生成 label mask 是数据 curation 的基本功，多轮对话、工具调用轨迹都要按「谁生成谁计损」逐段标注。
- 面试追问点：prompt 部分不计损不等于不参与计算——它仍走前向、提供上下文，只是没有梯度信号教模型生成它。

## 疑问 / 下一步

- Agentic SFT 中环境返回的 observation 长度占比很高，全 mask 是否会让长程轨迹的有效训练信号过稀，值得对照实际轨迹数据评估。
