2一句话总结

NaN 会沿计算链扩散污染全部参数，根因只有三类——脏数据、梯度爆炸、混合精度溢出，先看 loss 曲线形态分型，再逐层定位。

3核心

  1. 问题/背景：NaN 一旦在某步前向出现，后续所有梯度与权重更新都被污染，整个 run 报废；它不是某个位置的局部问题，而是链路级连锁崩溃。
  2. 机制/方法：三路根因——① 脏数据最常见：空文本、超长截断后变空、除零、 $\log 0$ 等非法运算，用出事的 step 反推定位具体样本删掉即可；② 梯度爆炸：学习率过大或某层梯度范数飙升把参数推向 inf，表现为变 NaN 前 loss 先出现巨大尖峰，解法是梯度裁剪；③ 精度溢出：FP16 最大值只有 65504，超限变 inf 再变 NaN，解法是 loss scaling 或直接换 BF16（动态范围与 FP32 相当）。
  3. 关键证据或数字：分型判据来自曲线形态——loss 突然直降为零多半是数据问题；先尖峰再 NaN 多半是梯度爆炸。定位手段是在每层输出与梯度上加 NaN 检测钩子，找最早出现的那一层。
  4. 结论/判断：预防组合是标配：梯度裁剪 + BF16 + 数据预清洗 + 实时监控报警，出事立即回滚到上一个健康 checkpoint 并跳过问题数据续训。

4可迁移

  • RL 训练同样适用：reward/KL 突然 NaN 时先按「数据（rollout 样本）→ 梯度尖峰 → 精度」三路分型，不要先怀疑算法实现。
  • 训练框架里预置 NaN 钩子与自动回滚，是把「几小时 run 报废」变成「跳过一个 batch」的关键工程投资。

5疑问 / 下一步

  • 检测钩子逐层加会拖慢训练，生产中更常用抽样层 + 梯度范数监控的轻量组合，阈值怎么定值得实测。
