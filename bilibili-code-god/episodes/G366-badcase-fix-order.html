2一句话总结

处理 badcase 先按类型对症、再按成本阶梯下手：先动嘴（提示词）、再动手（前后置模块与 Agent）、最后才动模型（微调、预训练），乱序只会白烧钱。

3核心

  1. 问题/背景：badcase 先分三类再谈解法。第一类是复读、基础逻辑错误（如 9.11 与 9.9 谁大答错），属基座能力不足，提示词和微调都救不了，只能靠提升预训练数据的质量与规模，成本极高。第二类是该拒绝没拒绝、话术判断不准（安全/客服场景），可构造专门数据集：badcase 当负样本、正确回答当正样本，用 SFT 或 RL 微调让模型记住该怎么答。第三类是话术单一、翻来覆去，属最轻的一类，调温度、top-k 等多样性采样参数即可。
  2. 机制/方法：除改模型外还有两道兜底防线——前置处理（问题进模型前拦截、用分类模型把关、或先让模型改写问题）与后置处理（输出后二次过滤、用检索与规则揪失控内容、或让模型自检一遍）。核心是那张从便宜到贵的优先级阶梯：① 先调提示词与上下文学习，几乎零成本；② 加前置/后置模块兜底；③ 上 Agent、function call、MCP 增强能力；④ 再不行才微调，且优先用数据蒸馏构造 badcase 数据集来训，要 SFT 就全参、别图省事用 LoRA；⑤ 微调可选 RL 或 DPO；⑥ 最贵的一级是从预训练调起，小公司不要碰。
  3. 关键证据或数字：黄金原则四条——能不微调就不微调（贵且容易训崩）；真要微调，SFT 能上全参就不用 LoRA；badcase 别浪费，它们是最好的负样本，用数据蒸馏做成微调数据；从头预训练是巨头才玩得起的游戏。
  4. 结论/判断：这套顺序本质是成本与风险排序：越往后越贵、越容易引入新问题；工程上先用最便宜的手段把 80% 的 badcase 挡在模型之外，剩下的再喂回训练闭环。

4关键数字

阶梯 手段 相对成本
1 提示词 / 上下文学习 几乎为零
2 前置拦截 + 后置过滤 低
3 Agent / function call / MCP 中
4–5 数据蒸馏微调（SFT 全参 / RL / DPO） 高
6 从预训练调整 极高，小公司勿碰

5可迁移

  • 面试问「线上 badcase 怎么修」：先分类（能力/对齐/多样性）、再报阶梯、最后落到「badcase 本身就是最好的训练数据」，是完整的业务答法。
  • 自己做 post-training 时同理：先改数据与提示侧，再考虑动训练；把线上失败样本蒸馏成负样本数据集是性价比最高的一招。
