## 一句话总结

loss 尖峰的危害不止当下那一步：异常梯度会残留在 Adam 的动量 buffer 里持续污染后续更新，尖峰后自动衰减动量即可加速恢复。

## 核心

1. **问题/背景**：训练中 loss 或梯度范数偶尔会突然飙升（脏数据、坏 batch 等）。尖峰过去后 loss 看似回落，但训练状态并未真正恢复，后续更新方向被带偏，严重时连锁发散。
2. **机制/方法**：根因是 Adam 的一阶、二阶动量 buffer 是指数滑动平均，尖峰步写入的异常值会按衰减系数在 buffer 里残留很多步，持续扭曲每一步的更新方向和步长。Spike-Aware Adam 在标准 Adam step 之外加一层尖峰检测：当 loss 或梯度范数突然超过正常波动范围（以若干倍标准差为阈值）时，自动衰减动量 buffer，把残留异常值压下去。不改优化器架构、不引入额外超参，属于即插即用的补丁。另外讨论了一个常见疑问：尖峰后要不要干脆 reset 整个 optimizer state——检测 + 衰减是比全量重置更温和的选择。
3. **关键证据或数字**：视频称该方法让尖峰后的恢复速度提升约 50%。
4. **结论/判断**：排查「尖峰后训练再也回不到原来轨迹」时，先怀疑动量 buffer 残留，而不是数据或模型本身；动量衰减是低成本的第一响应。

## 可迁移

- RL 训练同样会遇到 reward/loss 尖峰：除了回滚 checkpoint、跳过坏 batch，还可以考虑对优化器动量做衰减处理，避免尖峰污染后续几十步。
- 面试聊训练稳定性时，这是一个「优化器状态也是状态」的具体例子：发散不一定来自当前步的梯度，也可能来自历史残留。
