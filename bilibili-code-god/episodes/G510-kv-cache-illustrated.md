## 一句话总结

自回归生成时只有当前 token 的 Q 在变、历史 K 和 V 恒定不变，把它们缓存下来用空间换时间，单步复杂度从平方降到线性，代价是随上下文线性膨胀的显存。

## 核心

1. **问题/背景**：用 ChatGPT 时第一个字总要等好几秒、之后吐字速度却稳定下来，背后就是 KV Cache。没有它时，每生成一个新 token，整段历史都要重新过一遍注意力，前面 token 的 K、V 矩阵被反复重算，浪费严重。
2. **机制/方法**：看注意力公式就清楚：每一步真正变的只有当前 token 的 Q，历史的 K 和 V 每步都一样，既然不变就不必重算——每一层维护 K、V 两块缓存矩阵，新 token 只算自己那一行的 QKV，把新 K、V 追加进缓存，再用新 Q 和完整缓存做一次注意力，全程不损失任何精度。完整推理因此分两段：prefill 一次性并行算出 prompt 全部 token 的 KV 塞进缓存（你感受到的首字延迟就是它的耗时），decode 每步只算一个新 token、复用缓存续写（后面的吐字速度就是它的单步耗时）。
3. **关键证据或数字**：天下没有免费的午餐，代价是显存：缓存大小等于 2 倍的序列长度乘层数、乘头数、乘每头维度、乘数据类型字节数。量级感受：LLaMA-7B 在 4K 上下文约需 2 GB，LLaMA-70B 推到 32K 就要 70 GB 以上——长上下文场景里 KV Cache 经常比模型权重本身还吃显存。
4. **结论/判断**：省显存有两条路线。一是缓存淘汰：全保留最准但最贵；滑动窗口只留最近若干 token，但把起始 token 逐出去性能会塌方；StreamingLLM 保留开头几个 attention sink token 加滑动窗口，又稳又快。二是从结构上减小 KV 本身：MHA 每个 Q 头独享一组 KV，GQA 让几个 Q 头分组共享一组、显存降数倍，MQA 所有 Q 头共用一组最省但表达力稍弱；主流模型几乎都选 GQA 作为显存与质量的甜点（视频举了 LLaMA-3、Qwen2 为例）。

## 关键数字

| 项 | 量级 |
|---|---|
| LLaMA-7B，4K 上下文 KV Cache | 约 2 GB |
| LLaMA-70B，32K 上下文 KV Cache | 70 GB 以上 |
| 单步注意力复杂度 | 由 $O(n^2)$ 降到 $O(n)$ |

## 可迁移

- 估算推理显存时别只算权重：KV Cache 按「2 × 序列长度 × 层数 × KV 头数 × 头维度 × 字节数」单独成项，长上下文下它才是大头。
- 面试讲推理优化可按「缓存复用 → 淘汰策略 → 结构压缩（GQA/MQA）」三层展开，正好对应时间、显存、模型结构三个层次。
