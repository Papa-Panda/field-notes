## 一句话总结

解码策略就是「每步从概率表里按什么规矩挑词」：贪心短视、beam search 留多条候选逼近整句最优、采样靠截断换多样性，选型取决于任务要忠实还是要有趣。

## 核心

1. **问题/背景**：模型每步只输出一张「下一个词」的概率表，整句质量约等于每步挑中概率的连乘；挑词规矩不同，同一模型输出质量天差地别。
2. **机制/方法**：贪心每步只取概率最高的词，快但短视，局部最优凑不出整句最优；Beam Search 每步保留束宽 $B$ 条候选，逐层展开比较整句总分再剪枝；随机采样先截断候选集（Top-K 取前 $K$ 个、Top-P 取累积概率刚够的一小撮）再按概率抽取，避免抽到离谱词的同时引入多样性。
3. **关键证据或数字**：同一模型只把解码从贪心换成 beam，整句总分与通顺度、忠实度明显上一个台阶；但 beam 用在开放生成上会一味挑最安全的词，结果保守、重复、无聊。
4. **结论/判断**：没有万能解码——翻译、摘要等有标准答案、必须忠实的任务交给 beam；聊天、写作等开放生成果断上采样。

## 可迁移

- RL rollout / 评测时解码配置是变量而非背景：pass@k 用采样、确定性评测用贪心，混用会让指标不可比。
- 面试答法可直接套用「概率表 → 挑词规矩 → 整句连乘」这条链，再按忠实/多样二分选型。
