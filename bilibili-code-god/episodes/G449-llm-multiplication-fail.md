## 一句话总结

大模型算不对乘法是机制注定的三重错位：分词把数字切成块打乱位对齐、自回归从左往右写而进位从右往左传（写高位时缺未来信息）、概率生成对确定性问题；正解是调工具而非硬背算式。

## 核心

1. **问题/背景**：能过律考、会写代码作诗的模型，算六位数乘法十有八九出错——不是笨，是底层机制天生不擅长精确算术。
2. **机制/方法**：其一，分词错位：GPT 类分词器习惯把数字每三位切一块（如 216456 切成「216」「456」两个 token），竖式要求的位对位对齐先乱了套；改成一位一个 token（如早期 LLaMA）算术明显变强，但只是「看得见」。其二，方向冲突：竖式从最低位算起、进位自右向左，模型却从左往右生成答案，写最高位时需要后面所有位的进位总量——那是还没算出来的未来信息；模型只能靠「往后瞄一位估进位」的近似，连环进位立刻失效。
3. **关键证据或数字**：典型错误形态是答案首位常蒙对、末位也对（个位不受进位影响），唯独中间几位稀烂——「两头容易中间难」全卡在进位上。
4. **结论/判断**：根子是世界观冲突——数学要确定性唯一解，模型本质是猜下一个 token 的概率机器。破法不是逼它背乘法表，而是让它识别出精确计算需求后写代码丢进 Python 沙盒执行：模型管意图与调度，工具管分毫不差。

## 可迁移
