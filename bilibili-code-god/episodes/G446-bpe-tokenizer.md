## 一句话总结

BPE 靠反复合并最高频相邻对练出子词词表；中文更费 token 是字节级编码（汉字 3 字节、表情 4 字节）叠加英文为主的语料很少合并中文组合的结果。

## 核心

### 1. 问题/背景

同样一句话，中文问比英文问贵好几倍，一个庆祝表情能顶好几个英文单词。根子在分词：按词切则词表爆炸且撞生词，按字符切则序列又长又碎、几乎不带语义，折中方案是子词——常见词整块留、生僻词拆成有意义的片段。

### 2. 机制/方法

BPE 训练极朴素：词表起初只有基础字符，然后反复统计语料中哪一对相邻单元挨在一起出现最频繁，就把这一对合并成新单元加进词表，一轮轮并到设定大小为止；所有合并规则按顺序记下，就是分词器的全部家当，切新句子时照规则回放。同一家族另外两家：WordPiece（BERT 用）不看纯频率，看合并后语言模型似然是否更优；Unigram（T5/ALBERT 用）思路反过来，先铺超大词表再用概率模型自顶向下裁掉最没用的子词。

### 3. 关键证据或数字

字幕演示的小语料里冠军对出现 20 次便先被合并。实际切分对比：英文高频词早被合并成一整块、1 个 token 搞定；「你好」两字占 2 个 token，一个小表情被切成 3 个 token。原因是字节级分词器眼里没有字、只有字节：英文字母 1 字节，汉字 3 字节，表情 4 字节；而训练语料以英文为主，英文组合被反复合并压得很短，中文与表情的字节组合很少被合并，只能逐字节摊开。

### 4. 结论/判断

中文费 token 不是模型偏心，而是「字节天生多 + 合并没轮上」两笔账叠加。选分词器时词表大小、语料配比直接决定各语言的实际成本。

## 关键数字

| 对象 | 字节数 / token 表现 |
| --- | --- |
| 英文字母 | 1 字节，高频词常 1 token |
| 一个汉字 | 3 字节，「你好」= 2 token |
| 一个表情 | 4 字节起，切分演示中 = 3 token |

## 可迁移

- 做中文/多语种 post-training 数据预算时，先用目标分词器实测 token/字比再估成本，别按英文的经验值套。
- RL/推理成本同理：同样的语义内容，token 数直接决定 rollout 与 KV cache 开销，分词效率是 infra 账的一部分。
