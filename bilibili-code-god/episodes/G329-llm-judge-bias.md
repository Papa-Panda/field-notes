## 一句话总结
用强模型当裁判是当前评估的事实标准，但 MT-Bench 实测显示裁判带有位置、冗长、自我偏好、风格四种系统性偏差，根源是其训练数据中人类偏好的统计偏见，只能靠交换顺序、多模型投票与显式评分细则来缓解。

## 核心
1. **问题/背景**：排行榜与论文评估普遍用 GPT-4 级模型当裁判，但裁判的公正性从未被默认成立——同一对回答换个呈现方式，结论就可能翻转。
2. **机制/方法**：四大偏差逐个看——位置偏差：多数裁判显著偏好先出现（个别偏好最后出现）的回答，源于注意力锚定；冗长偏差：回答长度与得分高度相关，长篇车轱辘话常胜过短而准，源于 RLHF 标注阶段人类对"详细"的偏好；自我偏好：裁判给自家模型输出打分显著偏高，因为自家文本在自身分布里概率最高、显得更自然，用模型评估并迭代自己会形成自我强化的闭环；风格偏差：内容相同的两段回答，带 markdown、列表与 emoji 的包装版压倒性胜出，格式被误当作质量的代理特征。
3. **关键证据或数字**：MT-Bench 的对抗办法成为工业范本：成对评估时交换顺序各测一次、两次不一致即判平局；长度作为协变量做归一化或在 prompt 中显式声明不以篇幅论质量；跨家族选裁判（评 GPT 用 Claude/Gemini，反之亦然），绝不让模型给自己打分；prompt 中显式声明只看正确性、深度与有用性，忽略格式与风格。
4. **结论/判断**：四大偏差不是模型的 bug，而是它忠实继承的人类偏好数据特性；没有完美的裁判，只有知道偏差之后正确使用裁判的人。

## 可迁移
- 搭自动评测流水线时默认三件套：顺序交换取一致、多裁判 ensemble 投票、评分 rubric 显式剥离长度与风格信号。
- 用 LLM judge 做 RL 奖励或数据筛选时要警惕自我偏好闭环：裁判与被训模型同源会放大风格漂移。

## 疑问 / 下一步
- 冗长偏差目前无根除方法，长度归一化在多大程度上会误伤"确实需要长"的高质量回答，值得查 MT-Bench 后续工作的量化结果。
