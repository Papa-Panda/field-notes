## 一句话总结

R1-Zero 证明从基座直接用 GRPO + 纯规则奖励（对不对、跑不跑得通）就能涌现长推理与自我反思；R1 再用冷启动、拒绝采样造数据、全场景 RL 四步把可用性补齐，而小模型的最优路线是蒸馏而非自己做 RL。

## 核心

1. **问题/背景**：传统 RLHF 依赖 reward model 打分，既贵又可能被讨好（reward hacking）。DeepSeek 想验证：不用 reward model、只告诉模型对不对，纯 RL 能走多远。
2. **机制/方法**：R1-Zero 从 V3 基座直接上 GRPO，不做 SFT，奖励全是规则：数学比对答案、代码跑测试、外加格式分。R1 则分四步：先用几千条长推理数据做冷启动 SFT，再做推理 RL 并加语言一致性奖励，然后用拒绝采样攒出 80 万条数据做 SFT，最后做全场景 RL。
3. **关键证据或数字**：R1-Zero 训练中 AIME 从 15.6% 涨到 71.0%，64 次多数投票达 86.7%；过程中回答越写越长、自发出现反思与换方法，论文称之为顿悟时刻；代价是可读性差、中英混杂——这正是 R1 冷启动与语言一致性奖励要修的问题，R1 最终 AIME 达 79.8%。另一个关键对照：32B 模型自己做 RL 得 47 分，蒸馏 R1 的数据得 72.6 分。
4. **结论/判断**：两条可迁移的判断——大规模 RL 里规则奖励足以替代 reward model 驱动推理能力涌现；小模型先蒸馏强模型的推理数据，比自己从头做 RL 划算得多。

## 关键数字

| 指标 | 基线 | 结果 |
|---|---|---|
| AIME（R1-Zero，纯 RL） | 15.6% | 71.0%（多数投票 86.7%） |
| AIME（R1 四阶段） | — | 79.8% |
| 32B 模型 | 自己做 RL 47 分 | 蒸馏 R1 数据 72.6 分 |

## 可迁移

- 面试讲 R1 按「Zero 证明可能性、四步补可用性、蒸馏定小模型路线」三段组织，并能报出 15.6 → 71.0 → 79.8 与 47 vs 72.6 两组对照数字。
