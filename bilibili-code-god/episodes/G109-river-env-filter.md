## 一句话总结

终端 Agent 的 RL 学的主要是把已有技能组合、路由起来的高层行为，而非新技能，所以奖励质量决定上限：River 把合成环境审计过滤到不足 30%，再加行为正则，RL 增益反而翻倍。

## 核心

1. 问题/背景：终端 Agent 任务（修 bug、配环境、处理文件）靠环境给奖励，每个环境 = 任务描述 + 验证器。合成环境能批量造几万个，但验证器可能写错、任务可能不可完成，奖励即噪声。
2. 机制/方法：论点是 RL 学的是行为层（何时先探索目录、何时先跑测试、失败后怎么回退），低层技能在预训练与 SFT 里已有。River 做两件事：一是环境过滤审计，删掉验证器不可靠、任务不可完成、奖励不稳定的环境，只留不到 30%；二是行为正则，在结果奖励之外加过程级行为信号，强化「先看再改、失败回退」这类好的决策模式，让奖励反映真实行为质量。
3. 关键证据或数字：Terminal-Bench Lite 上用不到 30% 的环境，RL 增益 ， $+106\%$ ；Terminal-Bench 2.1 上 2B 到 27B 模型普遍约 ， $+30\%$ ；在开源 8B RL 模型里四个基准最好，且跨模型规模、架构与 RL 目标都成立。
4. 结论/判断：扩环境之前先审计——抽样跑验证器，看假阳性、假阴性与不可完成率；过滤标准只认验证器质量，不可靠宁可删。若诊断出模型缺低层技能，应先补 SFT，别指望 RL。

## 关键数字

| 项 | 基线 → 结果 |
|---|---|
| 保留环境比例 | 100% → 不到 30% |
| Terminal-Bench Lite 的 RL 增益 | 基线 → +106% |
| Terminal-Bench 2.1（2B–27B） | 约 +30% |

## 可迁移

- RL 环境工程：环境数量是虚荣指标，验证器的假阳/假阴率才是奖励质量的直接度量，上线新环境前先做审计报表。
- 面试可讲：RL 与 SFT 的分工——SFT 补技能、RL 做行为组合与路由，这个判断决定数据预算往哪边投。
