## 一句话总结

max response length 是思维链 RL 里最贵的旋钮，本质是一笔要跟着模型当前推理长度走的预算：推理本来短的基座（蒸馏小模型）应分阶段放开长度，一步到位又慢又不如短起步；本来就会长推理的基座则应直接大长度起步、再靠推理期外推。

## 核心

1. 问题/背景：max response length 是 rollout 时允许模型写多长。开太大有三个代价：rollout 时间随长度线性甚至更糟地涨、组内回答长短差异大导致梯度方差高收敛慢、每步烧的算力翻倍；开太小，推理写到一半被截断、本来能对的题拿零分，reward 全是噪声。
2. 机制/方法：DeepScaleR 的三段阶梯（基座 DeepSeek-R1-Distill-Qwen-1.5B，算法 GRPO）：第一段 8K、0–1040 步、8 张 A100、batch 1024，AIME24 从 22.9% 到 33%；第二段 16K、1040–1520 步、扩到 32 张 A100、batch 2048，33% 到 43%；第三段 24K、1520 步以后，切换后先回落到 38% 再爬到 43.1%，超过 o1-preview。要点是前 1040 步用 8K 的便宜价格打基础，长上下文的钱只在后期才付。Skywork-OR1 把这套做成标配：8K 训 0–600 步、16K 训 600–1400 步、32K 训 1400–1680 步，每次切换都在上一阶段收敛之后。切换时机看三个信号：平均长度贴近上限、截断率上升、reward 到平台；切换前把被截断的样本过滤掉或软惩罚，别让截断噪声进梯度。温度也随阶段升高（0.7→1.0→1.1）保持探索。
3. 关键证据或数字：Skywork-OR1 的 32B 平均从 57.8% 到 72.8%（+15），7B 从 43.6% 到 57.5%（+13.9）。但 Polaris 给了反例：Qwen 34B 基座本来就会长推理，短起步反而压着它，直接从 40K 起步常常更好；他们还做了训短推长——训练最长 52K、推理时用 RRN 因子 1.5 外推到 96K，长轨迹准确率从 26% 涨到 50% 以上（RRN 是推理器的位置编码缩放，不用重训）。
4. 结论/判断：判断规则只有一条：看基座会不会长推理。蒸馏小模型推理本来短的，分阶段放开；已经会长推理的，一步到位加推理外推。各家的步数和卡数是各自设置，不能跨模型照抄。

## 关键数字

| 方案 | 长度阶梯 | 结果 |
|---|---|---|
| DeepScaleR 1.5B | 8K → 16K → 24K | AIME24 22.9% → 43.1% |
| Skywork-OR1 32B | 8K → 16K → 32K | 平均 57.8% → 72.8%（+15） |
| Polaris 34B | 40K 起步，训 52K 推 96K | 长轨迹准确率 26% → 50%+ |

## 可迁移

- RL 训练排期可直接套用：长度阶梯 + 三个切换信号（平均长度贴上限、截断率上升、reward 平台期），截断样本切换前过滤或软惩罚，避免噪声梯度。
- rollout 成本建模时把 max length 当预算变量：早期用短长度买步数、后期再买长度，比全程大长度省得多。
