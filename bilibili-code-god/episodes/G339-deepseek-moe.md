## 一句话总结
把大专家切细（8 个大专家 → 160 个小专家、top-k 提到 6~8）让路由更精准，再留 1~2 个所有 token 必经的共享专家兜底通用知识——同等激活参数下比标准 MoE 强 10%–15%。

## 核心
1. **问题/背景**：标准 MoE 每层 8~64 个大专家、top-2 激活；单个专家动辄上亿参数，内部要同时学代码、数学、诗歌，路由粒度粗、专家专门化不够，这是它的天花板。
2. **机制/方法**：两个创新。其一细粒度专家：总参数不变，把每个大专家切成多个小专家（如 8 个切成 160 个，每个只有原来 1/20），路由改选 top-6~8——一个 token 可同时命中「代码 + 数学」两个维度，每个小专家只需学一小撮知识。其二共享专家：单独留出少量专家（V2 为 2 个）让所有 token 无条件经过，专学基本语法、常见词汇等通用知识，免得每个小专家重复学一遍。最终输出 = top-k 细粒度专家的加权和 + 共享专家输出。
3. **关键证据或数字**：DeepSeek-V2 用 160 个细粒度专家 + 2 个共享专家、每层 top-6，总参数 236B、每 token 激活 21B；V3 升级到 256 个细粒度专家 + 1 个共享，总参数 671B、激活 37B。论文对比显示同等激活参数下 DeepSeekMoE 比标准 MoE 提升 10%–15%。
4. **结论/判断**：代价在工程侧：专家数从 8 涨到 160，all-to-all 通信次数暴增、跨卡负载均衡棘手；DeepSeek 的解法是无辅助损失（aux-loss-free）的偏置动态调整均衡，其他视频另有专讲。细粒度让路由更精准，共享让通用不浪费。

## 关键数字
| 项 | 标准 MoE → DeepSeekMoE |
|---|---|
| 专家数（V2 每层） | 8~64 个大专家 → 160 个细粒度 + 2 个共享 |
| 激活方式 | top-2 → top-6 |
| V2 规模 | 总参 236B / 激活 21B |
| V3 规模 | 总参 671B / 激活 37B |
| 同等激活参数性能 | 提升 10%–15% |

## 可迁移
- MoE 设计的两个正交旋钮：专家粒度（决定专门化上限）与共享专家（决定通用知识是否被重复学习），面试讲 MoE 进阶必提。
- RL infra 视角：细粒度 MoE 的瓶颈从计算转到通信与负载均衡，专家并行/容量规划要按 160+ 专家、top-6~8 的路由形态重新估算。
