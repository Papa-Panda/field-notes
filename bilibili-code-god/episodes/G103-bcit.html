2一句话总结

后训练经验不能只记「涨了几分」：一个更新的效果取决于 parent 模型、数据与训练阶段，BCIT 把经验绑定来源上下文、用「来源强度 × 当前兼容度」打分，再用不超过 20% 预算试跑验证，把有害授权率从 62.5% 降到 25%。

  1. 问题/背景：自动化后训练系统的循环是提出更新、训候选、评测、决定下一步，系统会记住「上次这个更新涨了 2 分」并在类似情况直接复用。但更新效果取决于它作用的 parent 是谁、用的什么数据、处在哪个训练阶段，三者一变，历史成功只是一条记录而不是许可。盲目复用不止浪费算力，还会把坏 checkpoint 晋升上去、污染后续训练轨迹。
  2. 机制/方法：BCIT 三步。第一，记录必须带上下文：数据构成与来源、训练阶段、优化设置、证据等级（A 为有匹配对照的复现，B 为单次比较，C 为外部报告）以及目标指标的有符号变化。第二，复用前打分：来源强度按证据等级打折（A 取 1.0、B 取 0.75、C 取 0.5），当前兼容度是五项检查的平均（能力匹配、数据可得、运行时兼容、parent 阶段、评测协议），两者相乘——历史再好也补不了不兼容；硬冲突只在某个命名的必要条件被明确违反时才否决，缺原数据不算否决。第三，有界试跑：预算不超过全量的 20%，用同一个 parent、评测数据与全量指标不重叠，结果分 pass / fail / inconclusive 三路，试跑 checkpoint 无论如何不晋升。
  3. 关键证据或数字：论文回溯 24 个曾在来源环境有效的更新，换环境后 13 个目标效应变负；11 个目标涨了的里面只有 3 个同时保住两项保留指标。实验在 Qwen3-4B 上做三组迁移（ThinkQA→TAKUA、Spider→BDSX、LAM→BFCL），IFEval 作保留约束、每回合 36 GPU 小时、六组配对种子：有害授权率 25.0% 对基线 62.5%（降 2.5 倍），有意候选覆盖 90% 对 80%，跨任务均分 47.0 对 44.4（ $p = 0.03$ ），晋升率 74.2% 对 44.4%；20% 预算试跑与全量训练的方向一致率为 83.3%。
  4. 结论/判断：经验要带着上下文一起存；兼容度低的候选，历史收益再高也别直接全量跑。这套思想对人工迭代同样适用：新基座上的旧配方先当假设，不当结论。

5可迁移

  • 自己的实验记录（实验台账、run log）应固定带四元组：parent、数据、阶段、证据等级，否则跨基座复用时无从判断可信度。
  • 试跑 checkpoint 永不晋升这条纪律，适合写进任何自动调参/配方搜索流水线。
