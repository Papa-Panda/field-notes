## 一句话总结

多轮 agent 只有一个终局分数时，CrEST 把两种监督拆开：verifier 用轮分段优势决定每轮更新的方向，特权自教师只在 token 级调幅度，再用方向门与熵门防越界、防梯度坍塌，BFCL v3 多轮上 Qwen 4B 从 GRPO 的 43.6 涨到 52.0。

## 核心

1. **问题/背景**：十轮工具调用最后只有一个分，有两个结构性问题。轮间稀释：第三轮订对机票、第七轮改错时间，一个总分把功过平均，好轮没被记住、坏轮没被单独惩罚。轮内不透明：就算知道第七轮错了，这一轮几百个 token 里是参数写错还是工具名选错，标量奖励分不出来。老路各有一个坑：只用 verifier 信号对但稀疏；on-policy 蒸馏信号稠密，但老师说的未必对，可能把策略带向 verifier 认为错的方向（越过可验证奖励的界），且信号集中在少数 token 时梯度会坍塌。
2. **机制/方法**：第一层轮分段已验证优势：第 $k$ 轮的优势在 $G$ 条 rollout 的同轮位置单独归一化（该轮奖励减组内该轮均值、除以标准差），每轮功过独立、符号由 verifier 决定，这就是方向。第二层熵门控自教师调制：教师是同一模型的特权版本，能看到前几轮工具调用的真实结果；师生在每个 token 上的对数概率差经温度缩放得到 token 级信号 $\delta_t$ ，再过两道门——方向门：教师信号与 verifier 符号相反就压掉；熵门：只在学生不确定（高熵）的内容 token 上放大调制，低熵格式 token 不动，防止梯度集中坍塌。最终 token 优势 = 该轮已验证优势 × 调制因子，调制因子由 $\delta_t$ 决定。
3. **关键证据或数字**：BFCL v3 多轮平均准确率（Qwen 4B）：GRPO 43.6、OPD 44.5、OPSD 38.8、CrEST 52.0；38B 从 43.3 到 50.0。WhileToolBench 会话级准确率：8B 从 5.5 到 9.4，4B 从 4.7 到 7.0。4B 消融很干净：只做轮分段 47.9、只做教师调制 48.8、两者一起 52.0；去掉方向门 46.8、去掉熵门 46.3、两门全去回到 43.5。
4. **结论/判断**：稠密信号可以要，但不能决定方向、只能决定幅度；两道门缺一不可，拆掉任何一个收益大半消失。

## 可迁移

- 多轮 agent RL 的默认动作：先把优势按轮分段归一化，这一步不需要任何老师就能拿到轮级方向。
- 想在 RL 里加蒸馏类稠密信号时的护栏设计：用同模型 + 特权信息当老师、只调幅度，并给教师信号加与 verifier 对齐的方向门和高熵门控。
