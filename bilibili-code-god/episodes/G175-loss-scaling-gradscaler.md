## 一句话总结

Loss scaling 是给 FP16 打的补丁：先把 loss 放大让小梯度脱离下溢区、反向算完再缩回；BF16 动态范围与 FP32 相同，根本不需要。

## 核心

1. 问题/背景：FP16 能表示的最小正数约为 $6\times10^{-5}$ ，而大模型训练中大量梯度在 $10^{-7}$ 量级甚至更小，在 FP16 下直接下溢成零，这一步等于没学——问题不在精度而在动态范围不够。
2. 机制/方法：反向传播前把 loss 乘一个大系数（如 $65536$ ），由链式法则梯度同比放大进入安全区间；算完梯度后再除以同一系数还原真实值，方向和相对大小不变。PyTorch 的 GradScaler 自动动态调这个系数：连续多步无 inf/NaN 就逐步加大，出现溢出就缩小。
3. 关键证据或数字：两种故障模式——scale 过大，放大后的梯度超过 FP16 最大值（约 $65504$ ）变 inf，该步梯度被丢弃、跳过更新，偶发无妨、频繁则须调小；scale 过小，梯度虽不下溢但舍入误差大、训练不稳。BF16 有 8 位指数（与 FP32 相同），最小可表示约 $10^{-38}$ ，不会下溢；代价是尾数只有 7 位（FP16 为 10 位），精度略低。
4. 结论/判断：A100/H100 都原生支持 BF16，后训练优先用 BF16，省去 scaler 的一整套调参与状态管理；只有被迫用 FP16 时才需要 GradScaler。

## 关键数字

| 项目 | 数值 |
|---|---|
| FP16 最小正数 | 约 $6\times10^{-5}$ |
| FP16 最大值 | 约 $65504$ |
| 典型初始 scale | $65536$ |
| BF16 指数位 / 尾数位 | 8 位 / 7 位（FP16 为 5 位 / 10 位） |

## 可迁移

- 面试高频题「FP16 与 BF16 区别」的完整答法：差别在指数位与尾数位的分配——FP16 精度高但范围小（要 loss scaling），BF16 范围同 FP32 但精度低（不用 scaling），大模型训练优先保范围。
- 排查 FP16 训练 loss 不降或频繁跳步时，先看 scaler 的 scale 曲线与溢出频率，再怀疑其他超参。

## 疑问 / 下一步

- 视频没提 scale 系数与梯度裁剪（clip）的先后顺序关系：实际 GradScaler 需在 unscale 之后再 clip，否则裁剪阈值会被放大倍数扭曲，值得在自己的训练脚本里核对。
