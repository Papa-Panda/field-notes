## 一句话总结
不用单独的草稿模型：在原模型最后一层并排多接几个轻量解码头各自预测未来第 $k$ 个词，候选组合成树，再用树注意力一次前向验证整棵树、接受最长前缀，无损加速约 2.2 倍起。

## 核心
1. **问题/背景**：自回归解码一次只吐一个 token，每步都要把整个模型权重从显存搬一遍，天生慢。经典投机解码用小草稿模型先猜、大模型验证，但草稿模型要单独训练、对齐并常驻显存，维护成本高。
2. **机制/方法**：三步——① 多解码头：在主干最后一层原输出头旁并排加几个小头，第 $i$ 个头负责预测往后第 $i$ 个词，主干可完全冻结、只训小头，几小时即可；② 候选树：每个头给出若干 top 候选，逐层组合成一棵候选树，每条根到叶路径就是一串可能的续写；③ 树注意力：把树上所有节点拍平成一个序列，配特制注意力掩码，规矩只有一条——每个节点只能看见从根到它自身路径上的祖先，其他分支一律不可见，从而每条路径保持正确因果顺序、分支互不串扰，一次前向算出全树所有节点的概率。
3. **关键证据或数字**：验证后从根向下接受模型认可的最长前缀，一步可前进多个 token；候选全被否也至少稳拿一个 token，绝不倒退；验证用的是原模型本身，所以生成质量无损。冻结主干只训头约 2.2 倍加速，主干与头联合训练可达 2.3–3.6 倍。
4. **结论/判断**：Medusa 把投机解码的「草稿」内化进模型自身，省掉第二个模型的显存与对齐维护；代价是树越大单步算力越浪费在被否分支上，树形配置需要按场景调。

## 可迁移
- 推理 infra：树注意力本质是「自定义 attention mask + 拍平多分支序列」，与投机解码、并行采样共享同一套批量验证思路；评估加速方案时要同时看接受长度分布，而不只看峰值加速比。
- 面试链条：自回归为什么慢（访存受限）→ 投机解码（猜 + 验证）→ Medusa 去掉草稿模型（多头 + 树注意力 + 最长前缀接受），是解码加速的标准叙事线。

## 疑问 / 下一步
视频未提树规模（每头候选数、树深）与 batch size 的交互——大 batch 下树验证的算力开销可能吃掉收益，落地前需按实际负载压测。
