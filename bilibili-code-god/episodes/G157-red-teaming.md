## 一句话总结

安全不是训完就有的：上线前组织红队以攻击者视角主动找漏洞，防御侧用「前置安全分类器（高召回）+ RLHF/DPO 内化对齐」双保险。

## 核心

1. **问题/背景**：SFT 与 RLHF 只能教会模型按已知模式安全回答，而攻击者的创造力不受训练分布约束，必须在上线前主动模拟攻击、先于真实攻击者发现漏洞。
2. **机制/方法**：四类常见攻击手法——角色扮演（让模型扮演无限制角色）、多轮诱导（逐步越界）、编码绕过、指令注入（在正常请求中嵌入隐藏指令）。组织流程闭环：先定义安全边界（什么不能输出），再招募红队、设计覆盖全部手法的攻击策略，大规模执行（每人每天数百条），记录所有成功攻击，随后修复并回归。
3. **关键证据或数字**：防御两层。其一，安全分类器：红队成功的攻击 prompt 作负样本、正常 prompt 作正样本，训二分类器部署在模型前面先行过滤，取向高召回、宁可误杀不可漏放。其二，RLHF 安全对齐：收集安全偏好数据，用 DPO 或 PPO 让模型本身不愿输出有害内容，而非只靠外挂分类器；Constitutional AI 是这一路线的代表。
4. **结论/判断**：分类器是外层护栏、对齐是内层本能，两者缺一不可；红队流程要形成「组队—攻击—修复—回归」的闭环并常态化。

## 可迁移

- 评估 Agent 系统时可复用同一框架：先定义不可输出/不可执行的边界，再用注入类攻击做红队，护栏（输入过滤）与策略本身（对齐）分开验收。
- 面试谈 AI 安全时，按「攻击手法分类 → 红队流程 → 双层防御」的结构讲，比泛泛谈对齐更有说服力。

## 疑问 / 下一步

- 安全分类器的高召回必然带来误杀率，误杀率与召回的权衡阈值如何定量设定，视频未给经验值。
