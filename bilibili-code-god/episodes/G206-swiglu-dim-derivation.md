## 一句话总结

$8/3$ 不是经验玄学，而是「与标准 FFN 参数量拉平」这一公平对比约束解方程的必然结果。

## 核心

1. **问题/背景**：标准 FFN 有两个矩阵，先从 $d$ 升到 $4d$ 再降回 $d$ ，参数量是 $4d^2 + 4d^2 = 8d^2$ ；SwiGLU 多了一条门控支路，共三个矩阵（gate、up、down），中间维度记为 $h$ ，参数量是 $3dh$ 。
2. **机制/方法**：令两者参数量相等解出 $h$ ：

$$3dh = 8d^2 \Rightarrow h = \frac{8}{3}d$$

若 SwiGLU 直接沿用 $4d$ ，参数量会变成 $12d^2$ ，比标准 FFN 多 50%，效果更好也说不清是结构优势还是参数占便宜，所以必须先把参数拉平再比真实差距。
3. **关键证据或数字**：LLaMA 的 $d = 4096$ 时， $\frac{8}{3} \times 4096 \approx 10922.67$ ，再按硬件效率取 256 的倍数得 11008，与 LLaMA 配置文件里的 intermediate_size 完全对上。
4. **结论/判断**：PaLM、LLaMA 都采用这一取值；看到奇怪分数先找背后的守恒约束，往往是等参数/等计算量对比推出来的。

## 关键数字

| 项目 | 数值 |
|---|---|
| 标准 FFN 参数量 | $8d^2$ |
| SwiGLU 参数量 | $3dh$ |
| 等参数解 | $h = \frac{8}{3}d$ |
| $d = 4096$ 实际取值 | 11008（256 倍数） |

## 可迁移

- 面试高频题：能现场从参数量守恒推出 $8/3$ 并对上 LLaMA 的 11008，是「懂推导」而非「背配置」的直接证据。
- 自己改 FFN 结构做消融时同样要先拉平参数量（或 FLOPs），否则消融结论不可信。
