## 一句话总结
RoPE 不给 token 加位置向量，而是把 Q、K 按位置旋转一个角度；两个向量做内积时各自的绝对角度相消，只剩相对距离，于是用绝对旋转实现了相对位置感知。

## 核心
1. 问题/背景：注意力本身对顺序不敏感，不注入位置信息就分不清词序先后。老办法是把位置向量加到 token 向量上；RoPE 换了个思路，用旋转代替加法，把位置编码进向量的朝向里。
2. 机制/方法：把 Q、K 的维度两两分组，每组当作平面上的二维向量，位置 $ m $ 处的向量按角度 $ m\theta $ 旋转。不同维度组用不同频率：低维组频率高转得快、高维组频率低转得慢，像一排快慢不一的时钟指针，兼顾相邻位置的精细区分与远距离感知；频率按基数 10000 的幂次衰减排布。
3. 关键证据或数字：位置 $ m $ 的 query 与位置 $ n $ 的 key 做内积时，结果只依赖角度差，即只依赖相对距离 $ m - n $ ，与各自的绝对位置无关——这是 RoPE 能做相对位置感知、且对长度外推友好的根本原因。
4. 结论/判断：实现只需六步：算各组频率、生成位置索引、位置乘频率得到角度并取 cos/sin、把向量按奇偶位拆成两半、套二维旋转公式、交错拼回。

## 可迁移
- 面试手撕 RoPE 时按「分组—转角—内积只剩相对距离」的主线讲，再落到六步代码，比背公式稳得多。
- 理解频率的快慢分工，就能顺势解释 NTK/YaRN 等长度外推方法为什么动的是频率缩放。
