2一句话总结

让模型对简单题快答、难题深想，三条路线由浅入深：看不确定性的规则、单独训一个决策器、用多阶段 RL 把难度感知练进模型本身。

3核心

  1. 问题/背景：推理模型习惯把自我反思、自我验证全塞进思考过程再给答案，复杂题受益，但简单题也跟着长篇大论，又慢又费 token。最早靠用户手动开关思考模式，频繁切换很麻烦，于是目标变成让模型自己判断这道题值不值得深想。

  2. 机制/方法：

  3. 不确定性规则：生成前先估把握。量化方式有两种——算预测分布的熵，熵越大越没底；或看最高与第二高预测概率的差值，差值越小说明越纠结。没把握就启动深度思考，有把握就直接答。简单轻量、无需额外训练。
  4. 决策器：用各厂积累的用户历史数据（什么问题上用户开了思考、什么问题上关了）训一个二分类模型，输入问题、输出「思考/不思考」，替主模型做决定。还有个巧门：在提示里插入省略号能随机触发两种模式，给动态切换留了口子，但这种切换是随机的，并不以难度为依据。

  5. 多阶段 RL（以 AutoThink 为例，用 GRPO 分三阶段）：第一阶段用精心设计的奖励平衡两种模式——不思考就答对给最高奖励（+2），思考后答对给 +1 ，不思考却答错惩罚最重（−1），导向是「能不思考就别思考，但答不对就老实思考」；第二阶段放开用原始奖励，让两种模式各自把准确率练扎实；第三阶段加长度奖励精炼，答对了惩罚啰嗦、答错了反而鼓励多想。

  6. 关键证据或数字：AutoThink 第一阶段的奖励梯度很说明问题：快答对 +2 > 想透答对 +1 > 快答错 −1 ，把「效率优先但不能瞎蒙」的偏好直接编码进奖励。

  7. 结论/判断：规则法和决策器都是外挂式的判断，真正彻底的是多阶段 RL——把难度感知从外部逻辑变成模型内生的能力，好钢用在刀刃上。

5可迁移

  • 做推理服务时可以先上最便宜的方案：用熵或 top-2 概率差做门控决定是否走长思考链路，不必一上来就重训模型。
  • 设计 RL 奖励时可借鉴这种分阶段思路：先用塑形奖励立规矩（平衡模式），再放开练能力，最后用长度类奖励做精炼，而不是把所有目标挤进一个奖励函数。
