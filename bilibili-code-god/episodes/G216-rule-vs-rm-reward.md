## 一句话总结

奖励来源只有两类：规则奖励靠预设规则判定、奖励模型靠偏好数据学出来；有标准答案的任务优先规则（准确、便宜、不可作弊），需要主观判断的任务才上 RM，工业实践通常是两者混用。

## 核心

1. 问题/背景：做 RL 训练时第一个问题是奖励从哪来——数学题有标准答案可判对错，开放对话则没有唯一正确答案，两种情形需要不同的奖励来源。
2. 机制/方法：规则奖励（rule-based reward）用确定性规则判分：数学对答案、代码跑测试、格式查 JSON 合法性。奖励模型（reward model）用人类偏好标注训练一个打分模型，对输出整体质量评分。
3. 关键证据或数字：规则奖励的优势是准确无偏差、成本极低（无需标注）、不可作弊（编译器不会被骗）、完全可复现；短板是覆盖窄（只适用于有标准答案的任务）、无法评估主观质量、只有终局信号导致奖励稀疏。RM 的优势是覆盖广（开放对话、创意写作、安全性都能评）、能捕捉细粒度主观偏好、可以给中间步骤密集打分；短板是需要大量偏好标注、可能被策略 over-optimization 钻漏洞、本身有偏差且不可验证。
4. 结论/判断：选型原则一句话——有标准答案用规则，没标准答案用 RM；实际系统常混用，如 DeepSeek-R1 用规则奖励训推理基础能力，再用 RM 微调对话风格。
