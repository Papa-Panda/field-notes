## 一句话总结
Embedding 就是一张可训练的 $V \times D$ 查找表，把离散 token 编号索引成连续向量；相加位置编码前先乘 $\sqrt{d}$ ，是为了把初始化时量级很小的嵌入放大到与位置编码同量级，避免被淹没。

## 核心
1. **问题/背景**：模型不认字，只认数字。文本先被切成 token 并发一个整数 id，但 id 只是门牌号——编号相邻纯属巧合，不携带任何语义，神经网络无法直接使用。
2. **机制/方法**：Embedding 本体是一张大表，行数等于词表大小 $V$ 、列数等于模型维度 $D$ ；所谓查表就是拿 id 当行号把整行向量抽出来，没有乘法、没有复杂计算，就是一次索引。这张表是模型参数的一部分，随机初始化后随训练调整，练到最后意思相近的词向量自然聚到一起。
3. **关键证据或数字**：Embedding 只知道「是什么词」、不知道「在第几位」，所以必须再给每个位置造一个向量（正弦/余弦位置编码，幅值落在 $-1$ 到 $1$ 之间）与之相加，否则「猫追狗」和「狗追猫」无法区分。嵌入初始化方差小、数值紧贴 0，若直接与幅值约 1 的位置编码相加会被彻底盖过；乘 $\sqrt{d}$ 后两者同量级。经典设置 $d = 512$ 时， $\sqrt{d} \approx 22.6$ 。
4. **结论/判断**：乘 $\sqrt{d}$ 一是量级对齐，让词义信息和位置信息相加时谁也不吃亏；二是与注意力里除以 $\sqrt{d}$ 的缩放在设计精神上遥相呼应，共同维持整个网络数值量级的稳定，不让激活逐层爆炸或消失。

## 可迁移
- 面试高频题「为什么 embedding 要乘 $\sqrt{d}$ 而注意力要除 $\sqrt{d}$ 」：前者是把小量级嵌入抬到与位置编码可比，后者是压住点积方差随维度增长——一抬一压，都是量级管理。
- 写代码时留意：查表等价于 one-hot 乘嵌入矩阵，但实现上用索引 gather，别真去做矩阵乘。
