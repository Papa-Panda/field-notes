## 一句话总结

Self-RAG 训练模型在生成文本的同时吐出四种反思 token，把「要不要检索、资料相不相关、回答有没有依据、整体有没有用」四个决定权交还给模型自己，实现按需检索与边生成边自我审查。

## 核心

1. **问题/背景**：普通 RAG 是无脑流水线——不管什么问题先固定检索、拼进上下文、照单全收。三个毛病：翻译、闲聊这类题检索纯属浪费还引入噪声；检索内容与问题相不相关没人把关；答完有没有真用上资料、有没有胡编也没人检查。
2. **机制/方法**：模型在正常生成之外额外输出四种反思 token：① 检索 token——开口前自判知识够不够，够则直接答、需要事实依据才触发检索；② 相关性 token——逐段评判检索内容与问题是否沾边，不相关的直接丢弃；③ 支持度 token——每答一句回头对照资料核查，有依据才放行、无依据判为幻觉当场拦截；④ 有用性 token——对整体回答打 1–5 分。进阶用法：对多段检索资料并行各生成一版答案，把相关、支持、有用三项分数相加，选综合分最高的一版。
3. **关键证据或数字**：视频未给具体 benchmark 数字，强调的是定性收益——按需检索省下无效检索开销，多段并行比对挑最靠谱的资料，整个过程省、准、可控，并可人为调节各环节的严格程度。
4. **结论/判断**：普通 RAG 是「先检索再照单全收」，Self-RAG 是「按需检索 + 边生成边批判」。代价是需要专门训练模型学会生成并服从这些反思 token，不是纯提示词方案。

## 关键数字

| 维度 | 普通 RAG → Self-RAG |
|---|---|
| 检索触发 | 每题固定检索 → 模型自判按需触发 |
| 资料把关 | 无 → 相关性 token 过滤 |
| 幻觉拦截 | 无 → 支持度 token 逐句核查 |
| 答案选择 | 单版直出 → 多段并行生成、综合评分择优 |

## 可迁移

- 设计生产级 RAG 时可借鉴其分工：把「是否检索、资料过滤、引用核查、答案打分」拆成显式环节，即使不用反思 token，也可用分类器/小模型/规则分别实现，形成可观测的流水线。
- 面试谈 RAG 优化时，这是从「固定管线」进阶到「自适应检索 + 自我批判」的代表工作，可与 query 路由、引用校验（citation check）等工程手段对照讲。

## 疑问 / 下一步

- 反思 token 的判断本身也会出错（尤其支持度误判时可能放行幻觉或误杀好答案），其错误率与基座模型规模的关系值得查原论文的消融。
