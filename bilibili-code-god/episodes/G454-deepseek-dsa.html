预填充省一半

DSA 用一个 FP8 低精度「闪电索引器」先给全部历史 token 打相关性分，只挑 top-2048 交给主注意力精算，把长文本注意力复杂度从 $L^2$ 降到 $L \times k$ ，128K 预填充省一半、解码省八成，效果与稠密版持平。

3核心

1. 问题/背景

DeepSeek-V3.2 相比上一版架构只改了一处：换上 DSA。动因是标准注意力平方级开销——上下文到十几万时，每解码一个 token 都要与全部历史算一遍，成本爆炸。

2. 机制/方法

核心思路是「先筛选再计算」，三步走：

  • 索引：闪电索引器是一个很轻的小网络（FP8 低精度、索引头很少），只负责算当前 query 与每个历史 token 的相关性分数，不碰真正的注意力计算，因此又快又省；
  • 选择：细粒度选择机制按分数挑出 top-2048 个 token，只保留它们的 KV；
  • 注意力：主注意力只在这约 2000 个 token 上认真计算，整套结构建在 MQA 之上与上一版无缝衔接。

训练分两阶段：第一阶段冻结主模型、只训索引器，保留稠密注意力，用 KL 散度逼索引器模仿主注意力的「眼光」（只花 1000 步、21 亿 token）；第二阶段放开全部参数正式启用稀疏选择，训了 9400 多亿 token 让模型适应稀疏。

3. 关键证据或数字

128K token 下预填充成本只有稠密版的 1/3 到 1/2，解码成本砍掉八成以上，且成本随长度增长的速度远慢于稠密版；整体效果与上一版持平，部分任务反超。

4. 结论/判断

DSA 的价值不在省 FLOPs 的数字本身，而在「侦察兵挑重点、主力只打这一仗」的两级结构：打分环节必须足够便宜（FP8 + 少量头），选择环节必须可训练对齐（KL 蒸馏主注意力分布），两者缺一，稀疏就会掉点。

5可迁移

  • 面试讲稀疏注意力时抓住一条主线：瓶颈是 KV 访存与平方级计算，解法是「低成本打分 + top-k 选择 + 稀疏精算」；能说清索引器为什么用 FP8、为什么要先用 KL 对齐稠密注意力，就是加分项。
  • 对 RL rollout 的长上下文推理同样适用：解码阶段省八成的量级，正是 rollout 吞吐的决定项。
