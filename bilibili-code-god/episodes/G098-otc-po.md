## 一句话总结

只按答案对错给奖励会训出「认知卸载」——调工具对正确率单调不减，策略梯度便一路强化过度调用；OTC-PO 把工具生产率（正确答案数除以总调用数）写进奖励，在正确率不变的前提下让调用最多减少 68.3% 。

## 核心

1. 问题/背景：工具增强 Agent 每一步可选自己推理或调工具（搜索、计算器、代码执行），而 RL 奖励只看最后答案对不对。问题在于：多调一次工具不会让答案更错、偶尔还能救回来，即调用对正确率单调不减，于是策略梯度把「多调工具」当成安全策略一路强化，最后变成有疑问就调、连两位数加法也要调计算器——模型把本该自己做的推理外包给工具，即认知卸载。代价有三：每次调用都是 API 或沙箱执行的延迟与费用，线性上涨；工具返回塞进上下文越调越长，模型被历史噪声带偏；内部推理能力得不到锻炼，越依赖越不会自己想。
2. 机制/方法：先定义指标——工具生产率 = 正确答案数 / 总工具调用数，衡量每次调用的含金量。再做工具集成奖励：把答案正确性与工具使用行为一起算；直觉上每道题存在一个最优调用次数（需要查资料的题调一两次是必要的，纯推理题零次最好），奖励设计成在答对的前提下、调用次数越接近最优越高，调多了打折。该方法可在 PPO 和 GRPO 上实例化，不改算法框架、只改奖励。
3. 关键证据或数字：在 Qwen2.5 与 Qwen-Max 系列、多个 QA 基准上，正确率与只看正确性的基线相当，工具调用次数最多减少 68.3% ，工具生产率最多提升 215.4% 。即模型学会了先用内部推理、真需要时才调工具。这与企业后训练复盘里「函数调用专家过度调用」的作弊是同一个问题，那边的修法是加无关样本与目标配比，这边是把效率直接写进奖励。
4. 结论/判断：实操四条——奖励里显式惩罚不必要的调用，只讲正确必训出过度调用；定义并监控工具生产率，与正确率一起看；鼓励先内部推理再调工具，对零调用答对的题给满分；但不是禁止调用，需要外部信息的题该调还得调，目标是最优次数而非最少次数。一句话：调用也是成本，奖励要算账。

## 可迁移

- Agent RL 奖励设计：凡是「做了不亏」的动作（调工具、加长推理、请求澄清）都会被只看结果的奖励放大，必须把单位成本写进奖励或约束里，并把「产出/成本」类比率指标与主指标并行监控。
- 面试要点：能解释过度调用的成因时，要点出单调性论证——当某个动作对成功率单调不减且无成本项时，策略梯度必然把它推向过度使用。
