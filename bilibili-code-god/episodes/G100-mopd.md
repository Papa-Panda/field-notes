## 一句话总结

多域能力融合的老办法是混训 RL（各域打架）或串行 RL（跷跷板遗忘）；MOPD 先让每个域独立 RL 出一个教师，再在学生自己的 rollout 上做多教师在线蒸馏，而朴素实现的真正瓶颈不是梯度冲突、是 token 级优化预算错配，修好后上限恢复率从 35.6% 升到 83.4% 。

## 核心

1. 问题/背景：一个模型要同时会数学、代码、Agent、对话。传统两条路都有病：混训 RL 把所有域数据放一个 batch，各域奖励互相拉扯、容易打架；串行 RL 先训数学再训代码，训后面的忘前面的，是跷跷板。两条路都把「各域怎么练」和「怎么合成一个模型」耦合在了一起。
2. 机制/方法：MOPD 把全流程拆成两阶段。第一阶段，每个域独立做专项 RL 得到一组教师——数学教师、代码教师、Agent 教师各自用最适合本域的配方并行开发、互不干扰。第二阶段，学生自己采样 rollout，按 prompt 所属的域路由到对应教师，教师在这条 rollout 的每个 token 上给概率，学生用 OPD 的方式逐 token 贴近教师。教师是同一基座 RL 出来的 checkpoint，不是外部大模型。这样稳有三点：信号密集（每个 token 都有教师监督，而非一条轨迹一个 0/1）；完全在学生自己的 rollout 分布上训练，构造上没有暴露偏差，学生几乎能继承每个教师的全部能力；同源教师与学生分布近、优化稳定，还能多轮师生进化（学生变强后再当下一轮教师）。
3. 关键证据或数字：在 Qwen3-30B-A3B 上 MOPD 优于混训 RL、串行 RL、离线微调与参数合并。2026 年 8 月的 Open-MOPD 开源复现先定了一个上限——按域路由的 oracle 集成（每域都用对应教师回答能拿多少分），朴素多教师 OPD 只恢复了这个上限的 35.6% ，指令跟随掉得最厉害。诊断出的根因不是各域梯度打架，而是 token 级优化预算被错配，三个来源：各域序列长度差异大，长序列域吃掉大部分 token；各域学习率与收敛速度不同，产生漂移；异步更新时教师的奖励是陈旧的。
4. 结论/判断：对应三条修法——token 份额均衡（让每个域拿到的 token 数按目标分配，而不是按序列长度自然分配）；差距感知的动态预算（学生离哪个教师差得远，就多给哪个域预算）；学生奖励刷新（定期用最新学生重算，消除陈旧）。三条一起把上限恢复率修到 83.4% ，且普通硬件就能跑通配方与评测。一句话：能力融合的瓶颈不是冲突，是预算。

| 实现 | oracle 上限恢复率 |

| 朴素多教师 OPD | 35.6% |
| Open-MOPD（份额均衡 + 差距感知预算 + 奖励刷新） | 83.4% |

## 可迁移

- 后训练系统设计：多域/多任务训练先诊断「预算错配」再怀疑「梯度冲突」——按 token 而非按样本数统计各域实际吃到的优化量，并把各域与各自上限的差距做成预算分配的反馈信号。
- 面试要点：讲多教师蒸馏为什么稳，抓三点——token 级密集信号、学生分布上训练无暴露偏差、同源教师可多轮进化；再补一句 MOPD 已进入前沿模型（MiMo-2-Flash、DeepSeek-V4）的公开配方。

## 疑问 / 下一步

- 域的划分粒度（按任务类型、按数据来源还是按能力探针聚类）会直接决定教师数量与路由质量，Open-MOPD 的配方在域数大幅增加时份额均衡是否还成立，值得关注后续复现。
