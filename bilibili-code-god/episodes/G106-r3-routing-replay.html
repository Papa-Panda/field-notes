2一句话总结

MoE 做 RL 容易崩的系统层原因是训推两套引擎的路由不一致——94% 的 token 至少有一层选了不同专家，重要性权重随之不可靠；R3 把推理时的 top-k 专家 mask 记下来在训练时重放（router 梯度照常），开销不到 3%，让 60 步就崩的 GRPO 全程不崩。

3核心

  1. 问题/背景：MoE 每层 router 给每个 token 挑 top-k 专家；训练引擎与推理引擎的 kernel 精度、并行方式不同，router 分数有微小差别，但 top-k 是硬选择，差一点选中的专家就换了。Qwen3-30B-A3B 上约 10% 的 router 决策训推不一致，累积到整条序列，94% 的 token 至少一层走了不同专家，平均每个 token 有约 6 个 router 不一致；训推 KL 约 $1.5 \times 10^{-3}$ ，同尺寸 dense 模型只有约 $6.4 \times 10^{-4}$ ，极端 token 比例高一个数量级。
  2. 机制/方法：RL 训练要用重要性采样权重（训练策略概率除以推理策略概率），两个引擎算的本该是同一个模型、权重应接近 1；路由不一致后某些 token 的概率相差几倍甚至几十倍，权重爆炸，且差异随训练增长，崩溃几乎总伴随训推 KL 与极端 token 比例的异常升高，TIS 类截断只能拖延。R3 的做法很直接：推理引擎在 rollout 时把每层每个 token 选中的专家记成 mask，随 prefix KV cache 一起缓存；训练时不再自己选专家，强制套用这个 mask。注意重放的只是 mask 不是路由概率——专家权重仍由训练引擎的 logits 在 mask 内做 softmax 得到，router 照常有梯度可学。
  3. 关键证据或数字：R3 开销不到 rollout 延迟的 3%；训推 KL 从约 $1.5 \times 10^{-3}$ 降到约 $7.5 \times 10^{-4}$ ，接近 dense 水平，极端 token 少一个数量级。主表（mini step = 10）：GRPO 平均 62.2、60 步崩；加 TIS 66.2、105 步崩；加 R3 71.8 且全程不崩；TIS 与 R3 叠加 70.1 无额外收益。off-policy 更强（mini step = 8）时：GRPO 48.8、120 步崩，GSPO 66.8，GRPO+R3 68.1，GSPO+R3 69.0；多轮 SWE-bench 类任务从 31.8 涨到 38.6 且不崩。
  4. 结论/判断：R3 与 GSPO 是两条路——一个改重要性采样的粒度，一个直接对齐路由。但 R3 不是万能的：Mini2L 的理论指出完全 on-policy 时强制对齐本身引入偏差，收益消失甚至更差；应按 off-policy 程度选——on-policy 不重放，小 off-policy 用只重放训练引擎自身第一个 mini-batch 路由的 R2，大 off-policy（4–8 倍）用 R3，均需配 clip。固定重放的路由还会随策略演化变陈旧，PR2 改成预测路由把 AIM-124 从 35.7 涨到 47.7。无论哪档，训推重要性采样修正永远要开，去掉立即崩；重放还要求训推用同一套路由结构与 top-k，量化改变 router 输入时可能失效。

5可迁移

  • MoE RL 的可观测面板应常驻两个指标：训推 KL 与极端 token 比例，目标是压到 dense 水平；这与 G061 里 MoE 路由不重放导致训推相关骤降是同一问题。
  • 面试答 MoE RL 稳定性时，GSPO 之外补上路由重放这条系统路线，并按 on-policy 程度分档（不用 / R2 / R3）。
