## 一句话总结

图像进大模型要走「切 patch → ViT 编码 → 投影层对齐」四步变成视觉 token，patch 数直接决定 token 账单，所以分辨率与算力的取舍是所有 VLM 躲不掉的命题，动态分辨率正是为此而生。

## 核心

1. **问题/背景**：大模型只认识 token 序列，图片是二维像素块没法直接塞入，中间必须有个「翻译官」把图像翻译成模型认识的 token。
2. **机制/方法**：
- 切块：把图像切成固定大小的小方块（如 $16 \times 16$ 像素），每块称一个 patch，相当于图像界的「字」。
- 编码：每个 patch 拉平后过线性层做 patch 嵌入，再加位置编码标明它在图中的位置，全部 patch 送入 ViT 做自注意力，得到融合全局信息的特征。
- 投影对齐：ViT 输出的特征维度与语言模型的词向量空间对不上，中间用投影层（可以是两层小网络，也可以是专门的压缩模块）把视觉特征翻译进语言模型的向量空间，产物就是视觉 token，与文字 token 首尾相连一起喂入大模型。
- 各家差异：经典路线是 CLIP 练出的 ViT、固定分辨率；SigLIP 换了更高效的训练损失成为新一代主流视觉塔；真正的分水岭是动态分辨率（如 Qwen-VL 按原图大小切图，大图多给 token、小图省着来），另一派把大图切成网格小图再拼，专治高清长图。
3. **关键证据或数字**：视频算了一笔账：边长 336 的图、patch 大小 14，切出 $24 \times 24 = 576$ 个视觉 token；分辨率翻倍，patch 数翻四倍——看得越清，token 越多、上下文越长、算力越贵。
4. **结论/判断**：视觉塔的演进主线就是从「一刀切固定分辨率」走向「看图下菜的动态分辨率」，本质是在清晰度和成本之间动态权衡。

## 可迁移

- Post-training / 多模态 infra：估算 VLM 训练与推理成本时，视觉 token 数（由分辨率与 patch 大小决定）往往比文本 token 更 dominant，做预算和上下文规划必须单列。
- 面试：被问「图像怎么喂给大模型」时按四步链（patch → ViT → projector → 视觉 token）答，并主动补 token 账与动态分辨率的取舍。
