## 一句话总结

Sequence 粒度负载均衡损失以每条序列为统计单元，用「专家实际负载 × 平均门控概率」构造可导的纠偏信号，逼门控把 token 均匀分给所有专家。

## 核心

1. **问题/背景**：MoE 的门控自由选专家会产生马太效应：少数专家一开始表现好就被越选越多、越练越强，冷门专家长期没活干、得不到训练直至废掉，结果一半参数白白浪费、路由还极不稳定。
2. **机制/方法**：均衡的统计尺度是关键。只在 batch 层面算均衡，整体平均好看，但具体到每条序列可能极度偏科；而推理时用户输入不可控，一条内容高度集中的序列就会死盯少数专家、负载立刻失衡。所以把每条完整序列当作独立统计单元：统计专家 $i$ 的实际负载 $f_i$ （本序列中被路由到该专家的 token 比例）和平均门控概率 $P_i$ （所有 token 给该专家的门控分均值），损失取两者乘积求和再乘专家数与系数。用 $f \times P$ 的组合是因为 $f$ 来自离散的选中计数、不可导，而 $P$ 连续可导，两者相乘后梯度能顺着 $P$ 流回去，专门压低那些「既被过度选中、门控分又高」的专家。
3. **关键证据或数字**：损失公式见下；当所有专家负载完全相等时损失取最小值。工程上它只在训练阶段加入总损失，权重系数 $\alpha$ 通常很小（如 $0.01$ ），只轻轻推一把、不干扰主任务；推理阶段完全去掉；且与 token drop（超容量丢弃）并行工作，统计量照样在剩下的 token 上算。
4. **结论/判断**：答这道题要答出三层：为什么需要均衡（马太效应）、为什么是 sequence 粒度（推理时序列不可控）、为什么是 $f \times P$ （ $f$ 给负载、 $P$ 给梯度）。

损失公式如下：

$$L_{aux} = \alpha \cdot N \cdot \sum_{i=1}^{N} f_i \cdot P_i$$

## 关键数字

| 量 | 含义 | 理想值 |
|---|---|---|
| $f_i$ | 专家 $i$ 在本序列的实际负载比例 | 各专家相等 |
| $P_i$ | 专家 $i$ 的平均门控概率 | 各专家相等 |
| $\alpha$ | 辅助损失权重 | 约 $0.01$ ，只训练期加入 |

## 可迁移

- 这套「不可导统计量 × 可导概率」的构造是通用技巧：凡是想用梯度去调一个离散计数指标，都可以找一个与之对齐的连续代理量相乘。
- 训练 MoE/RL 模型时监控每专家负载分布（而不只是全局平均）能提前发现路由坍塌，sequence 级均衡对应到日志上就是按序列看专家命中直方图。
