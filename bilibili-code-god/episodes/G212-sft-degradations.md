## 一句话总结

SFT 上线后常见的重复、啰嗦、幻觉加剧三类退化各有根因，对应从数据、解码、学习率三处下手，并混入通用数据保住原有能力。

## 核心

1. **问题/背景**：模型 SFT 之后反而出现生成质量退化：同一句话反复说、回答越来越长、编造内容更理直气壮。这三类退化不能用一个「过拟合」打包解释。
2. **机制/方法**：逐类拆根因——重复生成源于自强化式的解码退化：模型一旦生成某片段，其条件概率被自己抬高，循环放大直至复读；啰嗦源于偏好/奖励环节对长回答的系统性偏爱，长答案在标注与打分中更容易显得「全面」，模型学会用长度换分数；幻觉加剧源于 SFT 教会模型的「自信模仿」：示范数据都是语气笃定的回答，模型学会了不知道也要用确定的口吻编下去。
3. **关键证据或数字**：排查步骤是对比 SFT 前后的输出、归纳 bad case 的模式，先定位属于哪一类退化，再对症修，而不是盲目重训。
4. **结论/判断**：四招组合修复——提升数据质量，去掉模板化回答；调整解码参数，加 repetition penalty 与合适的 temperature；调低学习率，减少对预训练已有知识的覆盖；混入通用数据，保持原有能力分布。四招一起用能有效缓解退化。

## 可迁移

- 这套「先按 bad case 模式分类、再对根因下药」的流程可以直接迁移到 RL 上线后的行为退化排查（如长度膨胀、格式坍塌），避免把所有问题都归因于 reward 设计。
- 「自信模仿」提醒数据侧：SFT 数据里应保留适量的拒答与不确定性表达，否则模型学到的不只是格式，还有不该有的笃定语气。

## 疑问 / 下一步

- 视频把啰嗦归因于 RLHF 的偏好偏差；若管线里只有 SFT 没有 RLHF，啰嗦更可能来自示范数据本身的长度分布，排查时应先确认退化出现在哪一阶段之后。
