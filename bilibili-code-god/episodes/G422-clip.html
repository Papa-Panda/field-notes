2一句话总结

把图像和文字编码进同一向量空间，用一个 batch 的图文对拼出 $N \times N$ 相似度矩阵、双向 InfoNCE 把对角线拉近、非对角推远；分类时把类别名写成一句话当分类器，实现零样本分类。

3核心

  1. 问题/背景：传统图像分类模型只认训练时见过的类别，想多认一类就得重新标注、重新训练。目标是让模型没见过标注、只凭类别名的一句话就认出新类别。
  2. 机制/方法：图像编码器和文本编码器把图和文映射到同一空间，配对的靠近、不配对的远离。训练时取 $N$ 个图文对，两两算相似度拼成 $N \times N$ 矩阵，对角线是正确配对、其余全是错误配对；损失（InfoNCE）本质是分类：对每一行做 softmax 逼模型选出对角线格（图找文），再对每一列同样做一次（文找图），双向对齐把配对锁死。
  3. 关键证据或数字：推理端零样本分类只需几行代码——把「猫/狗/车」套进「一张 X 的照片」模板编码成文本向量，图片向量与哪句最像就分哪类；换类别只改几个字，一张图都不用重新标注。训练数据是几亿条网络图文对，规模换来了通用性。
  4. 结论/判断：CLIP 的图像编码器因此成了通用视觉底座，今天很多多模态大模型的视觉塔直接取自这类对比预训练编码器——大模型学会看图的地基往往就是它。

4关键数字

项 数值
相似度矩阵 一批 $N$ 个图文对 → $N \times N$
正确配对占比 仅对角线 $N$ 格，其余 $N^2 - N$ 格为负样本
预训练数据量级 几亿条网络图文对

5可迁移

  • InfoNCE 式对比对齐是通用工具：post-training 里做图文/代码-文本检索、embedding 模型训练，乃至用偏好对构造对比信号，底层都是「正样本拉近、负样本推远 + 双向归一化」这一套。
  • 面试讲 zero-shot 时要点出分类器来自文本端：类别描述写得越准（模板与同义词）精度越高，这是 prompt 工程在分类任务上的最早形态。

6疑问 / 下一步

  • batch 内负样本全是随机错配，难负样本（语义相近的错配）占比低，CLIP 的细粒度区分能力上限在哪？可对比 SigLIP 等后续改法。
