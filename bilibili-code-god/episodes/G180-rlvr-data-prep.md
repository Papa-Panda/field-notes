## 一句话总结

RLVR 的数据就是「prompt + 可被机器判对错的答案」，门槛极低；真正的准备工作在三处：要不要冷启动、监控反思 token 频率、以及由易到难的课程编排。

## 核心

1. 问题/背景：DeepSeek-R1 之后 reasoning RL 成为热点，但其数据准备与 SFT 完全不同——不需要人工标注答案详解，需要的是可验证的奖励信号。
2. 机制/方法：RLVR 的奖励来自规则而非训练出来的 reward model：数学题直接比对答案、代码题直接编译运行。数据格式因此极简：一道题（数学或编程）加一个可验证答案，不需要预标注推理链，也不需要 chosen/rejected 偏好对，模型自己探索推理路径、答对即得奖励。是否预给推理链有两条路线：纯 RLVR 不给（R1-Zero 路线，推理行为自发涌现）；或先用少量带推理链的 SFT 冷启动教基本格式、再用 RLVR 精化（R1 正式版路线），基座推理能力弱时应选后者。
3. 关键证据或数字：现成数据集即可起步——GSM8K 约 8000 道数学题、MATH 约 12000 道。训练中有个特色监控指标：反思类 token 在输出中的出现频率，持续上升说明自我检查能力在增强，突然归零则可能是 mode collapse（模型找到取巧路径、不再反思）。课程学习上，先用一两步可解的简单题让模型频繁拿到奖励，简单题正确率稳定超过 80% 后再加中等难度、最后加难题。
4. 结论/判断：RLVR 爆发的原因就是数据门槛低；其数据准备的难点不在找题，而在答案能否被机器可靠判对错，以及难度编排能否避免奖励全稀疏导致学不到东西。

## 可迁移

- RL 数据管线设计：选题第一标准是「答案可自动验证」，验证器的可靠性（等价答案、格式变体）直接决定奖励质量，应先于算法调参投入。
- 可观测性：把反思 token 频率、按难度分桶的正确率做成训练面板，是低成本的健康检查（与 failure taxonomy 式观测思路一致）；频率异常比 reward 曲线更早暴露取巧与坍缩。
