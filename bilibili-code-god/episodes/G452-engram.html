2一句话总结

Engram 把语言建模里的「静态查找」从 MoE 里剥离出来做成条件记忆模块：n-gram 哈希 $O(1)$ 查表取记忆、当前上下文门控去噪、检索可预测故可 offload 到主机 DRAM，同参数全面超 MoE、NIAH 84.2 → 97.0 。

  1. 问题/背景：语言模型同时干两类活——动态思考（多步推理，必须现场计算）与静态查找（固定短语、事实，直接查表即可）。现有稀疏化全靠为动态思考设计的 MoE，拿它查字典既能力过剩又浪费网络深度，如同用超算查字典。
  2. 机制/方法：四层设计：① n-gram 稀疏检索：先归一化分词把同义异形词并成一个编号（12 万词表压缩 23% ），再多头哈希把局部上下文映射到嵌入表取向量、多哈希头减冲突；② 上下文感知门控：以聚合了全局上下文的隐藏状态为 query 、记忆向量为 key/value 算门控系数，对得上才放行、冲突则压到近零去噪，其后再叠浅层因果卷积扩大感受野；③ 融入多分支架构、经残差挂到骨干；④ 计算与内存解耦（见下）。
  3. 关键证据或数字：关键差异在可预测性——MoE 激活哪个专家取决于运行时隐藏状态，无法预知；而 n-gram 查哪条记忆只取决于输入 token 序列，前向之前就能算出，于是巨型嵌入表可放进便宜大容量的主机 DRAM：训练按 GPU 数线性分片，推理经 PCIe 异步预取，GPU 显存与算力全留给真推理。27B 同参数对比全面超 MoE 27B（知识、推理、阅读理解、代码、数学）；同等训练损失下多查询 NIAH 84.2 → 97.0 ，变量追踪 77 → 87.2 ；只用 82% 算力长文本困惑度即追平 MoE。
  4. 结论/判断：静态记忆与动态计算在结构上彻底分开，是「以存储换算力」的干净实现——省算力与涨性能两头都占，长文本检索是其主场。

5可迁移

  • 「检索索引只依赖输入、可离线/提前算」是把任何查表结构 offload 到 CPU/DRAM 的通行证——推理系统做 KV/记忆分层时同理，先问可预测性再谈放置。
  • 与 RAG 的分工值得想清：Engram 是参数内的静态短语记忆（训练时写入），RAG 是参数外的可更新知识，两者不是替代关系。

6疑问 / 下一步
