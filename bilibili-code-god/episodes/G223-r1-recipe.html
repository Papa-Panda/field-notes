2一句话总结

R1 的四阶段配方是：base 直接 RL（R1-Zero）让推理涌现 → 少量高质量长 CoT 冷启动 SFT 把输出变规整 → 大规模推理 RL + 拒绝采样全量 SFT 补回通用能力 → 全场景 RL 收尾，再把推理轨迹蒸馏给小模型。

3核心

  1. 问题/背景：OpenAI o1 不开源，DeepSeek 要复现推理模型；核心疑问是推理能力能否不靠 SFT、纯靠 RL 从 base 模型里"长"出来。
  2. 机制/方法：阶段一 R1-Zero：base 模型直接上 RLVR（数学判答案、代码跑测试等可验证奖励，无需 RM），用 GRPO 组内比较算优势、砍掉 critic 省显存。阶段二冷启动：少量高质量长思维链范例做一次 SFT，只立规矩——统一格式、理顺语言。阶段三：在冷启动模型上把数学/代码/逻辑等可验证任务的推理 RL 拉满，之后用该强推理模型对大量问题采样多条回答、只留答对的（拒绝采样），混入写作/问答/翻译等通用数据做全量 SFT。阶段四：全场景 RL 扩展到安全与通用对话，得到最终 R1；另把 R1 的推理轨迹 SFT 蒸馏给小模型。
  3. 关键证据或数字：纯 RL 阶段出现了未被教过的自我反思行为（训练中途模型自发回头验证，即所谓 aha moment），但代价是输出混乱、中英混杂，研究上惊艳、产品上不可用——这正是冷启动存在的理由。蒸馏覆盖 1.5B、7B、32B 等小模型。
  4. 结论/判断：RL 负责涌现推理，SFT 负责规整输出，拒绝采样负责补回通用，蒸馏负责下放小模型；且对小模型直接蒸馏大模型轨迹比让它自己跑 RL 更好更便宜，因为监督信号密度远高于稀疏的 RL 探索。

4关键数字

阶段 做法 解决的问题
一 R1-Zero base + RLVR + GRPO，无 SFT 推理涌现（含自发反思）
二 冷启动 少量高质量长 CoT 做 SFT 格式混乱、中英混杂
三 推理 RL + 拒绝采样 可验证任务拉满 RL；采样只留答对轨迹 + 通用数据全量 SFT 推理与通用双强
四 全场景 RL + 蒸馏 安全/对话 RL；轨迹蒸馏至 1.5B / 7B / 32B 对齐收尾与小模型下放

5可迁移

  • 这是理解"为什么 RLVR 不需要 RM"的标准案例：奖励可程序化验证时，GRPO + 规则奖励即可闭环，能省掉整个 RM 训练与对齐税。
  • 自建推理模型 pipeline 可直接借这套分工：先小规模验证 RL 能否涌现目标行为，再用冷启动和拒绝采样做产品化修整，不要一上来全量 SFT。

6疑问 / 下一步
