## 一句话总结

代码与数学数据的占比对能力是倒 U 型：0% 和 100% 都差，峰值在 20%–40%，通用模型取代码 15%–25% + 数学 5%–10%，且数据质量比比例本身更重要。

## 核心

1. 问题/背景：代码与数学数据结构化强、逻辑严密、推理密度高，被认为能提升推理，但加多少合适没有直觉答案，加过头会挤掉通用语言能力。
2. 机制/方法：代码练的是强结构、长逻辑链与可验证性，数学练的是从条件到结论的多步推导链；两者迁移到通用推理靠的是这种「拆解能力」。数学数据（如 GSM8K、MATH）需重构成推理链格式再加入，直接混原始题面效果有限。
3. 关键证据或数字：梯度实验把代码比例从 0% 扫到 100%——纯代码模型代码最强但通用差，纯自然语言模型代码差，最优区间约 20%–40%，此时代码能力接近纯代码模型且通用能力保留，超过 50% 通用能力开始下降。DeepSeek 在 V2/V3 大幅提高代码比例（未公布确切数字），观察到代码越多数学与通用推理也越强。
4. 结论/判断：配比按目标定——通用模型代码 15%–25%、数学 5%–10%；代码特化模型代码可到 40%、数学更高；用消融验证，同时监控 HumanEval、GSM8K、MMLU 保平衡；退火阶段可再为高质量代码留一手。最后强调质量高于比例，低质量代码不如高质量网页。

## 可迁移

- 后训练混训配比（代码/数学/通用对话）可借这条倒 U 直觉做先验，但要用自己评测集的消融复核，不能直接套预训练的数字。
- 面试被问「代码为什么能提升推理」时，按结构、长逻辑链、可验证三点答，再补倒 U 曲线与峰值区间，有机制有数据。
