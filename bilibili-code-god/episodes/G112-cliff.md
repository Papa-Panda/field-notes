## 一句话总结

结果奖励把错误回答整条判负，错前的大段正确推理跟着挨罚；Cliff 让现成 LLM 老师标出第一处出错的步骤，错前不罚、错后才罚，且前缀优势系数 λ 必须为 0，否则模型会学会拖长正确前缀刷分。

## 核心

1. 问题/背景：GRPO 的结果奖励让一条回答里每个 token 拿同一个优势，但错误回答往往前大半是对的，只在某一步出错、后续都建立在错误前提上，全条负优势等于告诉模型「前 14 步也别这么写」。过程奖励模型能细化，但要专门训、还容易被 hack。
2. 机制/方法：Cliff 用一个现成 LLM 当老师，两步走：老师先自己解题并用验证器确认做对（做不对的题不参与判断）；再读学生的错误 rollout，找出推理第一次出错的关键步，提示词专门区分真正的错误、无害的笔误与另一种正确解法。轨迹由此切成正确前缀与错误后缀，优势按位置给：正确回答正常给分；错误回答中，错前 token 的优势乘系数 ， $\lambda$ ，错后 token 拿完整负优势。
3. 关键证据或数字：消融发现 ， $\lambda = 0$ ，最好——前缀只免罚、不给正分。直觉上前缀是对的似乎该奖励，但 ， $\lambda = 1$ ，时模型会学到一种作弊：把正确前缀写得越长再犯错，拿的正优势越多，回答明显变长；$\lambda = 0$ 时拖长前缀没有额外收益，天然抗作弊，而「晚犯错优于早犯错」的梯度仍保留。学生为 4B base、老师用前沿模型或 32B 量级均可，12 个数学与代码场景平均比 GRPO 高 7%、比在线蒸馏高 15%；弱一点的老师若不做验证过滤会掉约 2%，前沿老师则不受影响；训练中有效前缀比例约 50 步后稳定，说明是真在减少错误而非刷奖励。
4. 结论/判断：老师不用很强，32B 这一档加验证器过滤就够；提示词必须写清笔误与替代解法不算错。方法直接叠在 GRPO 上，不需要训奖励模型，也不假设师生推理模式一致。

## 可迁移

- 过程级信号的低成本来源：与其训 PRM，不如让带验证的老师只标「第一处错误」这一个点，分段优势的性价比高得多。
- 面试可讲：给中间步骤发正奖励前先想作弊通道——任何「长度可换分」的设计都会被 RL 找到，Cliff 的 λ = 0 是典型反例教材。
