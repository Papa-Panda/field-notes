## 一句话总结

ICL 不更新任何参数，它做的是推断而非训练：预训练埋下海量候选任务，提示词里的几个例子是「证据」，模型用贝叶斯推断定位出目标任务再按其规律续写——所以格式与分布比标签对错更重要。

## 核心

1. **问题/背景**：参数冻得死死的、一个数都不变，模型凭什么只看三五个例子就当场学会新任务？这是 ICL 的核心谜题。
2. **机制/方法**：预训练时模型为预测下一个词，被迫在内部学会成千上万种潜在任务与概念（翻译、分类、摘要……），像一面墙待命的灯。给出的例子不是训练数据而是证据：模型做贝叶斯推断——后验正比于似然乘先验——哪盏灯最能解释眼前这几个例子，就点亮哪盏；锁定任务后，剩下的只是按该任务的规律续写。全程三步：预训练埋候选、例子作证据定位、按定位到的任务生成；没有梯度，没有训练。
3. **关键证据或数字**：乱标签实验：故意把示范的标签打乱配错（如正面评论标成负面），模型准确率几乎不掉。说明模型借例子定位靠的是格式、输入分布与标签空间这组信号，而不是背例子里的对错映射。另一派解释认为 Transformer 一次前向约等于在例子上隐式做了几步梯度下降，与贝叶斯视角并不矛盾。
4. **结论/判断**：既然本质是定位，写示范时就应给足定位信号：格式统一、覆盖所有可能的标签、输入分布像真实数据，这样才能一击命中目标任务。

## 可迁移

- 写 few-shot prompt 的工程准则直接从机理导出：格式一致、标签空间全覆盖、示范分布贴近真实输入；标签本身的对错反而不是第一位的。
- 面试答「ICL 为什么有效」：贝叶斯任务定位这条链（预训练埋候选 → 例子作证据 → 后验定位 → 按任务续写）最完整，再补乱标签实验作证据、隐式梯度下降作另一视角。
