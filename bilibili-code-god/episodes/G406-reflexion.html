2一句话总结

Reflexion 让 Agent 在失败后先用自然语言写一段反思存入记忆、下次带着教训重试，全程不改一个参数，靠「语言化强化」把失败变成可复用的经验，成功率随尝试轮次一路爬升。

3核心

  1. 问题/背景：ReAct 式 Agent 边想边做，但失败后不总结教训，下次遇到同样的坑还会照踩，单次轨迹内的聪明换不来跨尝试的进步。
  2. 机制/方法：失败或收到不及格反馈后，先让模型写下反思——错在哪、下次怎么改；反思存入记忆库，下一轮尝试时塞进上下文当提醒，形成「尝试 → 失败 → 写反思 → 再尝试」的闭环。奖励信号来自外部真实反馈（如单元测试是否通过），不靠人工标注。
  3. 关键证据或数字：写代码场景最典型：首版代码测试红了，模型读报错写下「边界情况没处理、空输入会崩」的反思，带着它重写后测试全过；多轮迭代下决策、推理、编程类任务的成功率随尝试次数明显上升。
  4. 结论/判断：改进发生在记忆与上下文层面而非权重层面，所以 Reflexion 也被称为「语言强化」——成本远低于梯度更新，代价是每轮都要多花推理算力，且反思质量取决于模型自身的复盘能力。

4可迁移

  • Agent 工程：给自己的 coding agent 加一层「失败 → 结构化复盘 → 注入下一轮 prompt」的记忆，比单纯加大重试次数更划算；反思要写成可执行的检查项而非感想。
  • 与 post-training 对照：Reflexion 是推理时的经验积累，适合快速上线；要把经验固化进模型，仍需把成功轨迹沉淀成数据做 SFT/RL。

5疑问 / 下一步

记忆库无限增长时如何筛选、压缩旧反思，避免上下文被过期教训污染，是落地时要解决的问题。
