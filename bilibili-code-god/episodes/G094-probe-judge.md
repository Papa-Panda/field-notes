## 一句话总结

rubric RL 的瓶颈在裁判：每条回答要按十几条准则逐一判定，生成式裁判又慢又贵；把判断改成从 1.7B 小模型隐藏层上训一个线性探针头、一次前向出全部准则，奖励质量反超 8B 生成式裁判，裁判时间还省 10.7 倍。

## 核心

1. **问题/背景**：写作、科学解释这类开放任务没有标准答案，主流做法是 rubric——给每道题列十几条准则（是否给出机制解释、是否引用正确定律、有没有事实错误等），逐条判是/否、加权求和当奖励。但裁判成本爆炸：一个 batch 几百条回答 × 十几条准则就是几千次裁判调用，8B 生成式裁判要先写理由再给结论（慢），API 则贵且有速率限制，裁判成为 RL 的瓶颈。
2. **机制/方法**：论文比较了从小模型取判断的三种方式——生成式裁决（生成是/否加理由，最慢）；logprob 裁决（只看「是」「否」两个 token 的对数概率差，不生成，快一些）；探针（把回答与准则一起喂进模型，取隐藏层表示，在上面训一个准则级线性分类头，一次前向同时输出十几条准则的判断）。探针不需要生成、也不需要模型会「说」，只需要它内部「知道」。它能赢的两个原因：判断与表达是两回事——表示里往往已编码了「这段话有没有事实错误」，但用文字说出来会引入生成噪声，探针直接读表示绕过了这层噪声；探针是有监督训出来的，用少量准则级标注对齐了人的判断标准，而生成式裁判靠提示词、标准不稳。代价是要一点标注数据训探针头。
3. **关键证据或数字**：Qwen3-1.7B 的探针裁判在准则级一致性上最好；拿它做奖励训练，科学解释类基准的 rubric 分从 0.232 涨到 0.643，超过用 8B 生成式裁判做奖励的 0.594；裁判时间省 10.7 倍。且探针给出的准则级奖励结构在不同任务与领域间保持一致，不像生成式裁判随提示词漂移。
4. **结论/判断**：实操四条：选 1.7B–4B 小模型当裁判底座、冻结只训探针头；准备少量准则级标注（几百条回答 × 十几条准则的是/否标签）；探针一次前向出全部准则，把裁判成本从生成级降到毫秒级，省下的预算可以多采样；注意边界——数字来自单一 rubric 基准，换 rubric 集要重验，且探针替代的是生成式裁判，不是可验证任务的验证器。

## 关键数字

| 对比 | 结果 |

| 8B 生成式裁判做奖励的 RL 后 rubric 分 | 0.594 |

## 可迁移

- RL infra / 奖励系统：开放任务的奖励通道可以拆成「冻结小模型 + 线性探针头」，把裁判从生成式调用降级为一次前向，吞吐和稳定性都更好；这也是奖励要便宜才能多采样的直接抓手。
- 面试准备：「判断 ≠ 表达」是解释探针裁判为何以小胜大的关键句，配合生成噪声与提示词漂移两个机制点。
