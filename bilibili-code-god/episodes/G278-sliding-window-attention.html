2一句话总结

滑动窗口注意力让每个 token 只看最近固定窗口内的历史，把复杂度从平方降到线性；信息靠多层堆叠逐层接力传递，窗口 × 层数即理论感受野，再配环形缓存让 KV 显存恒定。

3核心

  1. 问题/背景：标准注意力每个新 token 都要和全部历史逐个计算，长度翻倍计算量翻四倍（平方级）；且为避免重复计算，全部历史的 K、V 都要存进显存，缓存随文本无限膨胀，上下文拉到几万显存先扛不住。
  2. 机制/方法：每个 token 只看自己前面最近的一个固定窗口（如 4096），注意力矩阵变成贴着对角线的一条带子，计算量只与窗口大小成正比。远处信息并没丢：第一层每个位置吸收左侧一个窗口的信息，第二层再往左看一个窗口时，邻居身上已装着更左边的信息，如接力棒逐层右传——与 CNN 堆深扩大感受野同理。工程上配环形缓存：固定开一个窗口大小的缓存，新 token 按位置对窗口取模落槽、转满后覆盖最旧的，显存从此恒定。
  3. 关键证据或数字：经典配置窗口 4096、堆 32 层，理论感受野 ， $4096 \times 32 = 131072$ ，约 13 万 token。处理 32000 token 的长文本时，标准做法要缓存全部 32000 个位置，滑动窗口只留 4096 个，缓存量差 8 倍。
  4. 结论/判断：本质是用一点近处视野换极划算的长距离能力：每层只是小窗，叠起来是整面落地窗；推理更快、显存恒定，同卡能塞进的上下文成倍增长。

5可迁移

  • 推理 infra：环形缓存是定长 KV 管理的经典实现，理解"位置取模落槽"有助于看懂 vLLM 等框架中滑动窗口模型的缓存处理；也与 attention sink / StreamingLLM 的"保留开头 + 最近窗口"做法同源。
  • 面试要点：被问"窗口这么小怎么看到远处"，答"逐层接力、感受野 = 窗口 × 层数"即抓住核心。

6疑问 / 下一步

  • 窗口外信息只能间接逐层传递，强度会衰减；对需要精确远距离检索（如大海捞针）的任务，纯滑动窗口与全注意力的差距值得查实测数据。
