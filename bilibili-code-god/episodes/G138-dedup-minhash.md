## 一句话总结

加数据之前先去重是性价比最高的一步：精确哈希去完全重复，MinHash 签名 + LSH 分桶抓近似重复，band/row 组合就是相似度阈值旋钮，亿级规模必须分布式并行跑。

## 核心

1. 问题/背景：全网爬取的数据天然含大量重复（同文多站转载、改写），不去重会让模型反复背同一批数据、浪费算力且更容易过拟合/背诵；去重带来的 loss 下降往往比继续加数据还明显。
2. 机制/方法：三层递进——精确匹配（整串或 URL 哈希，便宜快速）去掉完全重复；近似匹配用 MinHash：文本切成 n-gram 集合后用 100–200 个哈希函数生成签名，再用 LSH 把签名分桶，只在同桶内两两比对确认；SimHash 是另一条近似路线。
3. 关键证据或数字：LSH 的 band 与 row 组合本质在调相似度阈值，阈值要靠抽样检查撞桶样本来校准、把误杀控制住；通常能去掉 10%–30% 的数据；字幕给出 FineWeb 15T token 去重约耗 200 GPU 小时的量级参考。还有一条纪律：训练集与验证集之间必须跨集去重，否则验证分数是假的。
4. 结论/判断：落地顺序是精确去重 → MinHash+LSH 近似去重（n-gram 取 3–5 元）→ 跨集去重 → 抽检调阈值；亿级数据用 Spark 或 datasketch 这类库并行处理，单机跑不动，全程监控去重比例与去重后的 loss 变化。

## 关键数字

| 项 | 数值 |
|---|---|
| MinHash 签名哈希数 | 100–200 |
| 典型去重比例 | 10%–30% |
| n-gram 切分 | 3–5 元 |

## 可迁移

- 后训练数据同样要去重：SFT/RL 题库与评测集之间的近似重复就是数据污染源，MinHash+LSH 这套管线可直接复用做 train/eval 交叉去重。
- 面试讲数据管线时把「跨集去重保验证可信」单列一条，是区分背概念和真做过的人的细节。
