## 一句话总结

在受控的 token 预算下，强行让推理模型跳过显式思考、把省下的算力改投并行多次采样加投票，常能用更少 token、更低延迟追平甚至反超完整思考的准确率——显式思考的必要性被高估了。

## 核心

1. **问题/背景**：o1、R1 类推理模型作答前先生成一大段显式思考（试错、纠正，动辄上千 token），业界默认「想得越久答得越准」，代价是 token 成本和延迟随思考长度线性上涨。
2. **机制/方法**：NoThinking 的做法极简——在模型开口前预填一段空的思考块（只留一句「已想完」），直接进入答案段。在此之上再把预算拆给并行采样：同一题独立生成多遍短答案，最后投票选最优或取第一个通过检验的答案，靠「多试几次至少对一次」的概率累积替代单条长链。
3. **关键证据或数字**：在固定预算下对比，低预算区（几百 token 量级）NoThinking 明显占优：某组数学竞赛题在约 700 token 预算时跳过思考答对约一半，认真思考却不足三成——长思考链还没写完预算就耗尽。在多个数学与定理证明任务上，「NoThinking + 并行采样」以更少总 token 追平完整思考，延迟最高可压低近 9 倍。
4. **结论/判断**：显式思考不是开关而是成本-效果权衡题：简单和中等难度题跳过思考足够且更省；题目越难、预算越大，完整思考仍可能更稳。工程上先问「这份算力该买一条长链还是买多次采样」。

## 关键数字

| 场景 | 思考模式 → NoThinking + 并行采样 |
|---|---|
| 约 700 token 预算的数学竞赛题答对率 | 不足 30% → 约 50% |
| 延迟（数学/证明任务） | 基线 → 最低压至约 1/9 |
| 总 token 消耗 | 完整思考 → 更少且准确率持平或反超 |

## 可迁移

- RL rollout / 推理服务做预算分配时，把「单条长 CoT」与「并行采样 + 验证/投票」当作可替换的算力投放方式比较，别默认拉长思考。
- 面试聊 test-time scaling 时能给出完整图景：纵向加长思考、横向并行采样是两条轴，NoThinking 是横向轴的代表性证据。
