## 一句话总结

标准注意力贵在每个 token 都要看全部 token，格子数随长度平方爆炸；Longformer 用滑动窗口加全局注意力把大部分格子留空，BigBird 再补随机注意力，三种稀疏拼图叠出线性复杂度，且理论上不损失表达力。

## 核心

### 1. 问题/背景

标准自注意力让每个 token 与所有 token 两两算关联，注意力矩阵是 $n \times n$ 的方格表：100 个 token 是 1 万个格子，1 万个 token 直接飙到 1 亿个。序列每变长 10 倍，计算量涨 100 倍——模型读短句秒回，读整本书就卡死爆显存，根子就在这个平方复杂度。

### 2. 机制/方法

思路是让每个 token 只看一部分，分三招：

- **滑动窗口**：每个 token 只盯左右相邻的邻居，在方格表上是沿对角线的窄带，专管局部关系；窗口还可以拉开间隔跳着看（膨胀窗口），用同样开销覆盖更宽范围。
- **全局注意力**：挑极少数关键 token（如开头的特殊标记），让它看所有 token、也被所有 token 看，相当于会场主持人，专管汇总全局；表上是整行整列点亮的十字。窗口加全局就是 Longformer 的方案。
- **随机注意力**：每个 token 再随机瞄几个远处伙伴，补上「相距远但恰好相关」的连接，表上是零星散落的亮点。三种叠加就是 BigBird。

远距离信息靠层数传递：第 1 层只认识直接邻居，第 2 层邻居的邻居也间接连上，感受野像涟漪一样逐层扩散，多层之后照样覆盖整条序列——局部里长出全局，这是稀疏敢只看一部分的底气。

### 3. 关键证据或数字

- BigBird 的稀疏拼图已被理论证明仍是通用逼近器，几乎不损失标准注意力的表达力。
- 成本上，稀疏方案每个 token 要看的数量固定，总开销只与序列长度成正比；同样的显存，标准注意力大约只能读 500 来个词，稀疏方案能一口气读几千个词。

### 4. 结论/判断

长文本的第一代解法不是硬扛全注意力，而是按功能分工的稀疏化：局部关系、全局汇总、随机补漏各司其职，复杂度从平方压到线性，长文本的大门才打开。

## 关键数字

| 项目 | 标准注意力 | 稀疏注意力（Longformer / BigBird） |
| --- | --- | --- |
| 注意力格子数（$n$ 个 token） | $n^2$（$n$ = 1 万时约 1 亿） | 约 $O(n)$ ，每 token 只看固定数量 |
| 同等显存可读长度（视频口径） | 约 500 词 | 数千词 |
| 表达力 | 基准 | BigBird 理论证明仍为通用逼近器 |

## 可迁移

- 面试讲长上下文时可先用「格子数」把平方复杂度讲直观，再按局部/全局/随机三类归置稀疏方法，比罗列模型名更有结构。
- 这套「窗口 + 少量全局 token」的分工在后来的滑动窗口注意力（如 Mistral）里仍在用，是理解现代长上下文设计的起点。

## 疑问 / 下一步

- 稀疏模式在真实硬件上未必省时间（不规则访存），它与 FlashAttention 这类 IO 优化路线的取舍值得对比一期。
