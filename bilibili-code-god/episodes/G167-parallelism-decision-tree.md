## 一句话总结

并行选型是在显存、通信与气泡之间挑一个付得起的代价：单卡放得下用 DDP，放不下逐级上 ZeRO，千亿级用 DP + TP + PP 的 3D 并行并按硬件拓扑切分。

## 核心

1. **问题/背景**：模型大到单卡放不下，必须切到多卡。四种策略切的东西不同——切数据、切状态、切层内矩阵、切层——代价也不同。
2. **机制/方法**：
   - **DDP（数据并行）**：每卡存完整模型、处理不同数据，反向后 all-reduce 同步梯度求平均。最简单，但每卡都要装下全模型，70B 级别直接出局。
   - **ZeRO**：对数据并行的显存逐级切分——Stage 1 切优化器状态（Adam 动量与方差），Stage 2 再切梯度，Stage 3 连权重也切。显存逐级断崖下降，代价是通信逐级增加；ZeRO-3 可让 70B 模型在 8 卡上跑起来。
   - **TP（张量并行）**：层内切分，如把 4096 维线性层切成 4 份 1024 维分到 4 卡、各自计算后 all-reduce 合并。通信极频繁，只适合节点内走 NVLink；代表框架 Megatron-LM。
   - **PP（流水线并行）**：按层切分（如 80 层模型每卡 20 层），数据流水式依次通过。通信少（只传层间激活），但有流水线气泡——前面的卡算完时后面的卡在等；micro-batch 填充与 DualPipe 等方案可把气泡减半。
   - **3D 并行**：千亿级模型标配 DP + TP + PP 组合，按拓扑切分：节点内 TP（NVLink 带宽高），跨节点 DP 与 PP。实操常见组合是 DeepSpeed ZeRO + Megatron 的 TP/PP。
3. **关键证据或数字**：决策树三段——单卡放得下 DDP；放不下 ZeRO；千亿以上 3D 并行。
4. **结论/判断**：选型先看显存是否装得下，再看互联带宽决定 TP 放哪一层，最后用 PP 切跨节点部分；没有银弹，只有与硬件拓扑匹配的组合。

## 关键数字

| 策略 | 切分对象 | 主要代价 |
| --- | --- | --- |
| DDP | 数据 | 每卡存完整模型 |
| ZeRO-1/2/3 | 优化器状态 / +梯度 / +权重 | 通信逐级增加 |
| TP | 层内矩阵 | all-reduce 频繁，限节点内 NVLink |
| PP | 层 | 流水线气泡（可减半） |

## 可迁移

- 估算训练显存时按 ZeRO 三个 stage 分项算（权重、梯度、优化器状态），能快速判断给定卡数下该开哪一级。
- 面试答并行选型用这棵决策树展开，再补一句拓扑原则（TP 不出节点），基本完整。
