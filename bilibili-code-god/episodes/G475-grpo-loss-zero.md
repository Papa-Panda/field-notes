## 一句话总结

GRPO 初始 loss 精确为 0 不是 bug：启动时参数未更新，新旧策略比率为 1 使组内标准化优势求和天然为零，K3 形式的 KL 项在比率为 1 时也恰好为零。

## 核心

1. **问题/背景**：用 GRPO 训练时，刚启动 loss 就精确等于 0，容易让人怀疑代码写错。实际上这是数学上的必然，源于 GRPO 损失的两个组成部分在初始时刻同时归零。
2. **机制/方法**：关键前提是启动瞬间参数一次都没更新，当前策略、采样用的旧策略、参考策略三者是同一个模型。优势项里新旧策略概率比率因此精确等于 1 ，优势项化简为组内标准化优势的平均；而每个优势都减去了组内均值，一组数各自减均值后求和必然为 0 。KL 项 GRPO 用 K3 估计省算力，其形式为参考与当前策略之比减去该比值的对数再减 1 ；初始比率为 1 时即 $1 - 0 - 1 = 0$ 。
3. **关键证据或数字**：无需实验数字，两处归零都是代数恒等式：标准化优势之和恒为 0 ，K3 估计在比率为 1 处取值恒为 0 。随着参数更新、比率偏离 1 ，优势不再抵消，loss 才从 0 慢慢涨起来。
4. **结论/判断**：起点 loss 为 0 说明第一步没有任何意外，是平稳且健康的开局；面试回答抓住三点即可：比率等于 1 、组内标准化优势和为零、K3 在比率为 1 时等于零。

## 可迁移

- 排查 RL 训练日志时，GRPO 首步 loss 非零（或优势项非零）反而是信号：多半是采样策略与当前策略权重不一致（如 rollout 引擎与训练引擎权重同步出了问题）。
- 面试被问到时按「比率 =1 → 优势抵消；比率 =1 → K3 归零」的结构回答，比背公式更能显示理解。
