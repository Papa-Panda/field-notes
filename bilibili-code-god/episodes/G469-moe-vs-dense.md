## 一句话总结

MoE 与 Dense 参数量、显存相同，差别只在每个 token 实际算多少：Dense 全部神经元必算，MoE 经路由器只激活少数专家，于是同等参数规模下推理计算量大幅下降。

## 核心

1. **问题/背景**：MoE 常被误以为「参数多所以慢/省显存」，需要一个最小例子把 Dense 与 MoE 的账算清楚。
2. **机制/方法**：Dense（全连接）里每个 token 必须过完所有神经元；MoE 把神经元拆成若干专家，加一个路由器（本质是输出类别数等于专家数的小分类网络，与模型一起训练），每个 token 只过被选中的专家。显存上两者没有区别——参数总量一样、都要全部装进显存；省的是每 token 的计算量。
3. **关键证据或数字**：玩具例子中输入维度 6、8 个神经元：Dense 需 48 次乘法 + 48 次加法；MoE 拆成 4 个专家（每个 2 个神经元），路由器打分 24 乘 + 24 加、被选专家 12 乘 + 12 加，合计 36 乘 + 36 加，即便算上路由开销仍更省，专家越多、越大差距越明显。真实模型 Qwen 30B-A3B 总参数 30B、128 个专家、每 token 激活 8 个，实际参与计算的只有 3B 参数，显存却与 30B Dense 相同。
4. **结论/判断**：MoE 的核心优势是「总参数决定能力上限与显存，每 token 激活参数决定速度」；附带好处是专家可各专一类知识。代价是引入了专家负载均衡等 Dense 没有的新问题。

## 可迁移

- 面试讲 MoE 先把「显存看总参数、速度看激活参数」这句立住，再展开路由器与负载均衡，不容易被追问带偏。
- 做推理容量规划时，MoE 模型的显存估算按总参数算（同 G468 公式），吞吐估算才按激活参数算。
