2一句话总结

输入 embedding（ $V \times d$ 查表）与输出 LM head（ $d \times V$ 打分）形状互为转置、本质是同一套「词 ↔ 语义向量」对应关系，共享一块权重能省上亿参数并顺带正则化，但解绑自由度更高，是道按场景取舍的权衡题。

3核心

  1. 问题：语言模型一头一尾各有一个大矩阵——输入端把词编号变成向量，输出端把隐藏向量变回词表上的分数；两者居然可以共用同一块权重，反直觉但面试区分度高。
  2. 机制：输入端就是查表——embedding 矩阵每行对应一个词，来一个编号就整行取出当词向量；输出端是打分——拿最终隐藏向量与输出矩阵每一列做点积得到各词 logits，再过 softmax 选词。输入矩阵形状 $V \times d$ 、输出矩阵形状 $d \times V$ ，恰好互为转置：共享时输入端用它查表，输出端把它转置后逐行点积打分，一块权重两处复用。
  3. 关键证据或数字：以词表 $V = 32000$ 、隐藏维度 $d = 4096$ 估算，一块 embedding 就有约 $1.3$ 亿个参数，共享直接省掉一整块，且词表越大省得越狠；附带好处是输入输出活在同一向量空间天然对齐、还起正则化作用。
  4. 结论：共享派（GPT-2 等经典模型默认）在中小模型、大词表、参数吃紧时最划算；解绑派（LLaMA 等）让输入输出各学各的、表达更自由、某些设置下还能再提一点——没有绝对对错，看参数预算与表达需求。

5可迁移

  • 面试答法链条现成：形状互为转置 → 本质同一对应关系（词找向量 vs 向量找词）→ 省参数 + 空间对齐 + 正则 → 反面是解绑更自由，按模型规模与词表大小取舍。
  • 读开源模型 config 时留意 tie_word_embeddings 一项，它直接决定参数量口径，算模型大小时漏了会差出一整块 embedding。
