## 一句话总结
GRPO 对「好 token」的权重分配是反的——已学会的猛强化、没学会的不理睬，导致熵崩塌与复读；ASPO 把好 token 的重要性比率取倒数翻转权重，再配掩码与双重裁剪稳住训练。

## 核心
1. **问题/背景**：结果监督 RL 里整串 token 共享同一优势值，答案对则全串是好 token。重要性比率本应如实矫正新旧策略分布偏差，但 GRPO 的权重恰好配反：好 token 概率越高（已学会）权重越大，被反复强化直至熵崩塌、输出复读；概率低（还没学会）的好 token 权重却很小，短板无人补，上限被卡死。
2. **机制/方法**：ASPO 三步——①token 掩码：优势已足够、更新过度的 token 直接挡住不再更新；②权重翻转：坏 token 照旧，好 token 的重要性比率取倒数，高概率降权、低概率升权，配合 stop-gradient 让梯度只从该走的路径回传；③双重裁剪：对翻转后出现的极端权重做软裁剪，只限数值不丢梯度。
3. **关键证据或数字**：Qwen 系列实验，数学基准 1.5B 模型从 GRPO 的 53.5 提到 59.3，30B MoE 从 68.8 提到 71.8，代码任务亦稳定提升；熵曲线上 GRPO 一路狂跌很快崩塌，ASPO 下降平缓、停在更高水平，探索能力得以保留。
4. **结论/判断**：问题不在算法框架而在权重分配方向；一个倒数翻转就把「强者愈强」改成「重点补短板」，且不牺牲稳定性。

## 可迁移
- 排查 RL 训练熵崩塌时，除了调温度/熵 bonus，还应检查优势加权是否在系统性偏爱已掌握的 token——权重分配方向本身可能是病灶。
- 「取倒数翻转」是低成本修正权重错配的通用技巧：先定位哪类样本被过度/不足加权，再定向反转，而非全局改采样分布。
