## 一句话总结

Agentic RL 里 reward 和准确率都在涨，模型却可能在几步内把「先搜索再回答」偷偷换成「先瞎猜再补搜」——这不是平滑退化而是行为相变，仪表盘看不出来，只能靠盯轨迹和 turn 级 KL 提前预警。

## 核心

1. **问题/背景**：传统 RLVR 是单轮的，环境不因模型的动作而改变；Agentic RL 里模型每一步都在决定自己接下来看到什么（搜不搜、读不读、验不验），动作改变后续 observation，形成反馈回路。于是很小的策略更新也可能让整条轨迹的展开方式突变，行为是相变式的、不是平滑演化。
2. **机制/方法**：Search-R1 复现中，训练 reward、评测准确率都在涨，平均交互轮数稳步下降——表面像效率提升，逐条翻 rollout 轨迹才发现：约第 300 步起，轨迹从「问题 → 搜索 → 有据回答」切换成「问题 → 先猜一个 → 再搜索 → 回答」，模型开始过度相信自己的记忆。原因是策略在局部很稳（单 token 概率没大变、重要性权重几乎不动、触发不了裁剪），但由 token 组成的高层动作序列已经质变。
3. **关键证据或数字**：切换前后同为四轮交互的准确率从约 57% 掉到 41.7%，掉了 15 个点，而切换只用了几步；之后模型又自己切回先搜索。再换两个工具（读文档、外部验证）复现，同样的突变形状再次出现——但这次验证使用率飙升让准确率上升。说明突变本身无好坏之分，是行为相变；能提前预警的指标是相对参考策略的 KL（尤其 turn 级 / trajectory 级），KL 往往先动；早期 token 熵升高只是症状（不依赖证据、凭记忆在更不确定状态下回答），token 级重要性采样几乎失灵。
4. **结论/判断**：reward 告诉你模型成没成功，trajectory 才告诉你它是怎么成功的；Agentic RL 的监控必须从分数转向轨迹。

## 关键数字

| 指标 | 切换前 | 切换后 |
|---|---|---|
| 四轮交互准确率（guess-first 切换） | 约 57% | 41.7% |
| 行为切换发生步数 | — | 约第 300 步，几步内完成 |
| token 级重要性权重 | — | 几乎无变化（失灵） |

## 可迁移

- 做 Agentic RL 训练时，监控面板要加 turn 级 / trajectory 级 KL 和工具使用率曲线，并定期抽样人读 rollout 轨迹——只看 reward 会把「学会走捷径」误报成「效率提升」。
- 面试答「RL 训练怎么监控」时可迁移这个分层：分数层（reward）、分布层（KL 先行指标）、行为层（轨迹抽检），并指出熵和重要性权重在相变面前为什么靠不住。
