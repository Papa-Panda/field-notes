## 一句话总结

Self-Refine 让同一个模型用三顶「提示词帽子」轮流扮演生成者、批评者和修订者，在单个任务内闭环迭代，不训练、不加新模型就能把输出质量平均拉高约 20%。

## 核心

1. **问题/背景**：模型的第一版回答往往不是其能力上限。过去想提升质量只有三条老路——再训练、换更大的模型、请人逐句修改——都不便宜。而人类写稿的经验是：初稿之后先自读、圈问题、再改。Self-Refine 就是把这个循环搬给模型自己走。
2. **机制/方法**：三步闭环——① 生成初稿；② 把初稿原样喂回同一模型，换上「挑毛病」的提示词产出反馈；③ 把初稿与反馈一起交给模型修订，新版本可再送回第 ② 步，直到满意或达到轮数上限。关键点是三个角色共用同一套权重，区别只在提示词，没有第二个模型、没有参数更新。
3. **关键证据或数字**：在改写、对话、代码优化、数学推理等多类任务上，质量随迭代轮次稳步上升，前一两轮提升最猛、之后逼近天花板，综合约 20% 的绝对提升，且全程零训练。视频用代码例子演示：一版能跑但慢的函数被「批评者」指出双重循环是平方复杂度、可用集合优化，修订后又对又快。
4. **结论/判断**：方法的成败完全取决于反馈质量——反馈必须具体、可执行（指出哪段重复、哪处该换数据结构），笼统的「这里不太好」等于没说。若模型本身看不出问题，反馈质量就是整个方法的天花板。它与 Reflexion 的区别在于：Self-Refine 只待在当前任务内、靠模型自反馈；Reflexion 用外部环境反馈并带跨任务记忆。

## 可迁移

- 面试/方案设计中，「不花训练成本提升输出质量」的标准答案之一：生成—反馈—修订闭环 + 强调反馈要 actionable；可自然衔接到 test-time compute 与迭代式 agent 工作流。
- 工程落地时，反馈提示词的设计（结构化、定位到具体缺陷）和迭代轮数上限是主要调参面；反馈环节也可以替换为工具/校验器信号，成为更可靠的混合方案。

## 疑问 / 下一步

- 当模型的自我批评能力弱于其生成能力时（如小模型或专业领域），闭环是否会原地打转甚至越改越差？值得用一个可验证任务实测迭代曲线。
