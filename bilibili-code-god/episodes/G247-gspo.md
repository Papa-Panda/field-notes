## 一句话总结

把重要性比率从逐 token 改成整条序列一个：对各 token 的 log 比率取均值再取指数（几何平均），尖刺被平均掉，裁剪粒度与序列级奖励对齐，更新更稳。

## 核心

### 1. 问题/背景

PPO / GRPO 对每个 token 单独算重要性比率（新策略概率 ÷ 旧策略概率）。逐 token 比率波动极大：多数贴近 1，个别能暴涨到数倍。一个极端 token 就能把整条序列的更新带偏，训练不稳定；而且逐 token 裁剪与「按序列/按组发放」的奖励粒度对不上。

### 2. 机制/方法

GSPO 只算一个序列比率：先对每个 token 求 log 比率，相加后除以序列长度，再取指数——等价于所有 token 比率乘积开长度次方，即几何平均。裁剪也随之升级到序列级：一个比率最多裁一次，裁剪力度与奖励力度对齐。

### 3. 关键证据或数字

手算示例：6 个 token 的 log 比率分别为 $+0.6$ 、 $-0.2$ 、 $+0.1$ 、 $-0.3$ 、 $+0.2$ 、 $0$ ，和为 $0.4$ ，均值约 $0.0667$ ，序列比率 $S \approx 1.069$ 。另一组含 $2.8$ 暴涨与 $0.5$ 暴跌的比率，几何平均后约为 $0.99$ ，稳稳贴在 1 附近。而逐 token 裁剪在 6 个比率里有 3 个越界就要裁 3 次，力度碎片化。

### 4. 结论/判断

逐 token 比率方差大、易被尖刺牵制；序列级几何平均把尖刺平均掉，得到单一、稳定、可解释的更新系数。

## 关键数字

| 项 | 逐 token（PPO/GRPO） | 序列级（GSPO） |
|---|---|---|
| 比率个数 | 每 token 一个 | 每序列一个 |
| 含尖刺示例的结果 | 单 token 可达 $2.8$ | 几何平均约 $0.99$ |
| 裁剪次数 | 多个 token 分别裁 | 至多一次 |

## 可迁移

- 面试讲 GRPO 稳定性时，可用「比率粒度应与奖励粒度对齐」这条原则串起 GSPO 的动机，比背公式更有说服力。
- 自己跑 RL 时若见个别 token 比率尖刺导致 loss 抖动，序列级比率 / 长度归一化是现成的排查方向。

## 疑问 / 下一步
