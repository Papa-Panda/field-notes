## 一句话总结

梯度裁剪给梯度范数设上限：超阈值就整体等比缩短、只改长度不改方向，从而摁住偶发梯度爆炸的尖刺；主流是按范数裁剪，阈值常取 1.0，PyTorch 里一行代码，是大模型训练的默认保险。

## 核心

1. **问题/背景**：序列特别长、网络特别深或学习率过大时，某一步的梯度范数会突然暴涨到原来的成千上万倍，参数被一步推飞到毫无意义的位置，loss 直接变 NaN，前面的训练全白费。
2. **机制/方法**：把梯度看作一根箭头，方向指路、长度决定步幅。裁剪先量总长度：没超阈值照旧；超了就把整根箭头等比例缩到刚好落在阈值上。关键是只缩长度、不改方向，参数仍朝正确方向走，只是这一步不再迈疯。两种做法：按范数裁剪整体缩放、方向纹丝不动，是实践主流；按值裁剪把每个分量单独砍到上限，各砍各的会把方向带歪，几乎没人用。
3. **关键证据或数字**：loss 曲线对比直观：不裁剪时曲线时不时窜起尖刺、严重时直接断掉；开启裁剪后尖刺被摁住，曲线一路平滑下行。阈值最常用 1.0；更讲究的做法是先打印梯度范数、观察其平时分布，再取略高于正常水平的值，既拦得住暴涨又不误伤正常梯度。
4. **结论/判断**：裁剪与训练初期的学习率预热、更小的初始化配合，梯度爆炸基本绝迹；成本一行代码，属于必开项而非可选项。

## 可迁移

- RL 训练里序列长、奖励偶发尖峰，梯度爆炸风险比 SFT 更高：范数裁剪 + warmup 应作为训练脚本的默认配置，并在日志里常态监控 grad norm 分布以便校准阈值。
- 面试答梯度裁剪：定义（范数上限、等比缩放）→ 按范数 vs 按值（保不保方向）→ 阈值怎么定（经验 1.0 或按分布略高取）→ 与 warmup/初始化的配合。
