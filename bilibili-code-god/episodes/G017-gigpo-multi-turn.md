## 一句话总结

多轮 Agent 只有最终 0/1 奖励时，标准 GRPO 让整条轨迹共享一个优势、做对与做错的轮次同分，信号极稀；解法收成四条路——轮级优势、门控累积奖励、拆解奖励、课程与提示——而所有加分项都必须门控在最终正确之内，这是防 reward hacking 的第一原则。

## 核心

1. **问题/背景**：让 agent 连续调用十轮工具修一个 bug，最后只有「修好 1 分、没修好 0 分」一个信号。标准 GRPO 对同一任务采样一组轨迹、按最终得分算每条轨迹的相对优势、轨迹内所有 token 共享这个优势；单轮问答没问题，但一条轨迹有十几轮、几千个 token，做对的轮被错误动作连累、坏动作被最终成功掩盖，模型要么学不动、要么学到一条碰巧成功的捷径。
2. **机制/方法**：四条路——① 轮级优势（GiGPO）：不额外采样，而是在一组轨迹里把落到相同环境状态的动作再分成一组互相比较，轨迹组给宏观信号、锚点状态组给微观信号，两级叠加；显存和 rollout 数完全不变。② 门控累积奖励（G-RA）：即时奖励与长期目标经常错位、模型会为中间分偏离最终目标，所以只有当长程奖励达到阈值（最终任务真的推进了）才把这一路的即时奖励累加进去，否则中间分一分不给。③ 拆解奖励：把奖励拆成格式分、过程分、结果分加权，最容易落地，但格式分单独给有个经典陷阱——模型会学会不做题、只把格式写对，所以所有加分项必须门控在最终答对之内。④ 课程与提示：任务太难时组内全错、一点梯度都没有，先从简单任务或给一半答案的提示开始，让采样命中率从零变非零，再逐步撤掉提示；2026 年的方向是把两件事分开：verifier 决定每一轮该往哪个方向走，拥有特权信息的自教师只调节 token 级的幅度（以熵来门控，与本合集 CrEST 的思路呼应）。
3. **关键证据或数字**：GiGPO 在 Qwen2.5 的 1.5B 到 7B 上，ALFWorld 比 GRPO 高 12 个点以上、WebShop 高 9 个点以上，成本不变。G-RA 在软件工程任务上把任务完成率从 47.6% 涨到 93.8%（另一个基准从 22% 涨到 86%）——注意这是「把流程跑完」的完成率口径，真实修改率的提升要小得多，看数字时要分清口径。
4. **结论/判断**：落地时的三个工程坑——① 多轮 rollout 的 loss mask 必须把用户消息和工具返回的观察段 mask 掉，只在模型自己生成的 token 上算梯度；② 轮级分组同样会出现全对/全错组，还是要过滤或补采；③ 锚点状态分组依赖状态可识别，网页、游戏这类离散环境好用，开放式对话未必有相同状态，要先看任务再选算法。

## 可迁移

- 给多轮 agent 设计奖励时先问一句：这个中间分如果被模型单独优化，会不会偏离最终目标？会，就必须加门控（最终正确才结算）。
- GiGPO 式的「相同状态分组比较」是零额外 rollout 成本的信用分配升级，适合状态可识别的工具调用环境优先试点。
