## 一句话总结

RL 训练约 70% 时间耗在 rollout 的逐 token 串行生成上；用同系列小模型作 draft 先猜一串、目标策略一次前向验证接受/拒绝，接受率做到约 70% 时端到端接近 2 倍加速，且因最终由目标模型验证，分布无损。

## 核心

1. **问题/背景**：RL 每步要生成大量回答，自回归逐 token 生成的速度受显存带宽限制，rollout 占整个训练约 70% 的时间，是最值得下手的瓶颈。
2. **机制/方法**：投机解码搬进 rollout——用当前策略的一个小版本（同架构/同系列或蒸馏出的小模型）作 draft，先快速草拟若干 token，目标模型一次前向并行验证，接受正确的、从第一个被拒处重新生成。命中率三要素：draft 与目标模型分布要足够像（同系列天然接近）、采样温度不要太高、draft 长度别贪长（太长后面必错、白增开销）；接受率掉下来就是 draft 跟不上策略更新的信号，该刷新 draft。
3. **关键证据或数字**：某团队实测：以目标模型的 1/3 规模模型作 draft，rollout 提速约 2 倍、命中率约 75%，整体 RL 单步从 120 秒降到 70 秒；经验区间上，draft 长度取 2–4 个 token 时命中率最高（另一处口径给出 K 设 4–8 的草拟长度），接受率目标约 70%，低于 50% 就应换更好的 draft。
4. **结论/判断**：投机采样不牺牲输出分布——它只是把串行等待并行化；落地要点是 draft 选同系列小模型、温度适中、持续监控命中率并在接受率下滑时刷新 draft。

## 关键数字

| 项 | 基线 → 投机解码 |
|---|---|
| RL 单步耗时（实测案例） | 120 秒 → 70 秒 |
| rollout 速度 | 约 2 倍（命中率约 75%） |

## 可迁移

- 自己的 RL 训练管线里，rollout 引擎（如 vLLM）开投机解码前先算账：rollout 占比、draft 的接受率随策略更新的衰减速度，决定刷新 draft 的频率；这也是 RL infra 面试里「rollout 加速」一题的标准答法骨架。

## 疑问 / 下一步

- on-policy 训练中策略每步都在变，draft 与目标的分布漂移速度有多快、多久刷新一次 draft 最划算，视频未给量化曲线。
