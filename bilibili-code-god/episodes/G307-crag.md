## 一句话总结
普通 RAG 对检索结果照单全收，一篇垃圾文档就能污染答案；CRAG 在检索与生成之间加一个轻量评估器做质检，按相关性分三档，分别走精炼提纯、丢弃上网重搜、或两者结合。

## 核心
1. **问题/背景**：普通 RAG 把检索回的几篇文档连同问题一股脑塞给大模型，默认它们都靠谱；但检索质量参差不齐，只要混进一篇不相关的，模型就可能被带偏——垃圾进，垃圾出。
2. **机制/方法**：加一个轻量检索评估器（很小的模型）给每篇文档打相关性分，分三档处理。相关档：不代表整篇都是干货，做知识精炼——把文档拆成细小知识点逐条打分，过滤跑题与重复，只把精华重拼成干净知识。不相关档：本地知识库指望不上，整批丢弃，把问题改写成搜索关键词，转头去互联网重新搜。模糊档（分数卡在中间）：不赌，精炼与网搜两条路一起上，双保险。
3. **关键证据或数字**：视频未给基准数字，卖点是结构性的：评估器很轻、几乎不增加成本；且即插即用，不用重训大模型，把纠错工序插在检索与生成之间即可升级任何现成 RAG。示例：冷门问题本地文档全跑题，评估器判定不相关、当场触发联网搜索，答案从胡说变靠谱。
4. **结论/判断**：喂给模型的永远是筛过洗过的高质量知识——差别全在生成之前那一道纠错：检索完先质检，差的就纠错。

## 可迁移
- 生产 RAG 里「检索质量门控」是性价比极高的一层：一个小评估器 + 三档路由，就能把单篇噪声文档的污染风险拦在生成之前。
- 面试答「怎么让 RAG 更靠谱」时，CRAG 给出区别于换 embedding/加 rerank 的答案维度：在管线里显式承认检索会翻车，并设计纠错回路（含外部兜底数据源）。

## 疑问 / 下一步
