## 一句话总结

大模型算不对多位数乘法不是智力问题，而是三重结构性错位：数字被 tokenizer 切碎、从左到右的生成方向与从低位进位的乘法方向相反、本质在做模式匹配而非执行算法；把数字逆序输入让生成方向与进位方向对齐，准确率即可显著提升。

## 核心

1. 问题/背景：早期大模型能写代码、过律师考试，却频繁栽在多位数乘除、进位加法这类小学算术上，反差说明瓶颈不在推理能力，而在底层处理方式与算术规则不匹配。
2. 机制/方法：三重根因层层递进。其一，tokenizer 按频率切分，不保证数字完整，如 3789 可能被切成「37」「89」两个 token，模型看到的是碎片而非一个数值。其二，竖式乘法从低位算起、进位向高位传递，而自回归生成从左到右先吐高位，高位结果却依赖尚未算出的低位进位，只能猜。其三，next-token 预测学的是训练数据的统计规律，见过的数字组合能蒙对，没见过的只能猜，本质是模式匹配、不是在执行算术规则。
3. 关键证据或数字：解法实验是把乘数逆序输入（如把 3789×4213 写成 9873×3124 的形式喂入），此时模型的生成顺序恰好从低位到高位、与进位方向一致，实测多位数计算准确率显著提升；这不能根治问题，但反证了方向错位确实是主因之一。
4. 结论/判断：新一代模型的改善走三条路线——推理模型用长思维链把计算拆成显式步骤并自我验算；新 tokenizer 按位切分数字、至少保证不被乱切；最重要的是工具调用，精确计算直接交给计算器或代码解释器。结论：大模型的数学是背出来的、不是算出来的，推理链加工具才是正解。

## 可迁移

- 这是解释「LLM 是统计模式匹配而非符号计算」的标准面试案例：tokenizer 碎片化、生成方向与算法方向冲突、训练分布覆盖，三点可迁移到一切精确计算/计数类失败（如数字母个数）的归因。
- 做 agent 系统时得到一条硬规则：凡需精确数值结果的步骤，默认走工具调用或代码执行，不要让模型心算后直接采信。
