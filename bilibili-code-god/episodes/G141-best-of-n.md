## 一句话总结
Best-of-N 是不训练、只在推理期多采样再挑最优的「用算力换效果」手段，挑出的好答案回流做 SFT 就构成 RFT 自进化闭环。

## 核心
1. **问题/背景**：想提升回答质量又不想动训练时，最便宜的杠杆是对同一 prompt 多次采样再择优，代价只是推理成本随 N 线性增长。
2. **机制/方法**：用较高温度生成 N 个候选，再用四种方式之一挑选——奖励模型打分、规则验证（数学对答案、代码跑测试）、LLM-as-judge、多数投票（Self-Consistency）。视频将其定位为 RL 的简化版：不更新参数、只在推理时择优，两者还能组合（先 Best-of-N 收集好数据再做 RL）。
3. **关键证据或数字**：实操区间为 N 取 4–8、温度 0.7–1.0；收益随 N 呈对数增长，翻倍只多买几分，所以先看预算。
4. **结论/判断**：优先用于离线高价值任务（数据合成、批量评测、蒸馏采集）；能验证的场景优先规则验证，便宜且不会被奖励模型式地骗分；温度与随机种子要保住候选多样性，否则 N 个回答长得一样、择优无意义。

## 可迁移
- 面试答「推理期 scaling」时可把 Best-of-N 与 RFT 串成一条线：采样择优 → 正确回答落地为 SFT 数据 → 模型变强后重复，LLaMA/Qwen 都用过这类 pipeline。
- RL infra 视角：Best-of-N 的成本模型就是 rollout 吞吐，N 与温度直接决定生成侧算力预算。
