2一句话总结

普通 RAG 靠向量捞几段文本，天生答不了全局主题问题；GraphRAG 离线把文档织成知识图谱、切成社区并预写摘要，查询时汇总各社区摘要作答。

3核心

小社区聚成大社区，如街道
→
城区
→
城市
  1. 问题/背景：普通 RAG 把问题向量化后按相似度捞回最相关的几段文本。局部事实问题（如某公司哪年成立）答案藏在一两段里，一捞一个准；但「整份资料在讲哪些主题」这类全局问题，答案零散分布在成百上千段里，只捞几段拼不出全貌。
  2. 机制/方法：分两期。索引期（离线）：让大模型通读全部文档，抽取实体（人物、公司、概念）与实体间关系，连成知识图谱；再用社区检测算法（Leiden）把图切成联系紧密的社区，且分层组织（小社区聚成大社区，如街道→城区→城市）；最后让大模型为每个社区单独写一段摘要。查询期（在线）：全局问题走「从局部到全局」路线——对每份社区摘要先各生成一个部分答案（map），再汇总提炼成最终答案（reduce）；局部小问题则直接定位相关实体、沿邻居查一圈即可，不必兴师动众。
  3. 关键证据或数字：视频未给量化基准，核心对比是定性的：全局问题每个社区都被照顾到，答案全面不遗漏；代价是索引期要离线通读全库建图、写摘要，成本前置。
  4. 结论/判断：GraphRAG 的本质是把成本从查询时挪到索引时——先把资料制成图、分好社区、写好摘要，回答全局主题时综合摘要，而不是临时只捞几段。

4可迁移

  • 面试讲 RAG 局限时，用「局部事实 vs 全局主题」的二分切入，再引出 GraphRAG 的 map-reduce over 社区摘要，是很完整的答题链。
  • 做文档问答/知识库系统时可借鉴：昂贵的全局结构（图谱、层级摘要）离线预计算，查询时按问题类型分流，全局走摘要、局部走图邻居。

5疑问 / 下一步

  • 索引期用大模型通读全库抽实体关系的成本随语料规模线性增长，增量更新（新文档进来如何局部重建社区与摘要）视频未展开，值得查原论文与开源实现的做法。
