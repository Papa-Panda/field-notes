## 一句话总结

序列长度是训练成本的最大驱动之一（注意力随长度平方增长），主流做法是主干在 4K–8K 训练、把算力大头花在短序列上，再分阶段扩长并靠 RoPE base 调整与少量长数据完成长上下文续训。

## 核心

1. **问题/背景**：长度翻倍，注意力计算量翻四倍，KV cache 与激活显存也随长度线性增长；设短了省算力但长文本能力差，设长了算力爆炸。
2. **机制/方法**：分阶段扩展——先在短序列上完成大部分预训练（如 4K 上花约 80% 算力），再逐步扩到 8K、32K 让模型渐进适应；直接从短跳到长，模型在长序列上表现会差。扩长时配合调整 RoPE 的 base 并用少量 token 验证外推效果。
3. **关键证据或数字**：主流演进轨迹是 GPT-3 用 2048、LLaMA 2 用 4096、LLaMA 3 用 8192、Qwen2.5 扩到 32K，长上下文需求推动长度持续变长，但没有任何一家全程用最大长度训练。
4. **结论/判断**：预训练主干选 4K–8K 覆盖绝大多数网页文本，长文数据单独留给后期长上下文续训；SFT 阶段与预训练对齐或稍短，按任务真实目标长度配（短对话约 2K，多轮/长文档 4K–8K），设太长纯浪费、太短截断丢信息；超长序列再考虑序列并行，并监控长文本 benchmark 确保短文本能力不降。

## 可迁移

- 成本估算时先算长度项：注意力 FLOPs 随 $n^2$ 走，长度决策本质是预算分配决策，「先短后长」是把预算花在刀刃上的标准解。
- 面试讲长上下文训练时，分阶段扩展 + RoPE base 调整 + 少量长数据验证，是比「直接训 128K」更工程化的答案。
