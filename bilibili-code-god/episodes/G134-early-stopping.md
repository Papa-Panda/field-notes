## 一句话总结

早停不是为了省时间，而是把模型停在验证指标最好的那一刻：patience 通用取 3–5，验证集必须同分布、固定、不泄漏，而预训练一般不用早停。

## 核心

1. 问题/背景：训练过了某个点，模型在训练集上继续变好、验证集上开始变差，继续训就是过拟合；早停的判决点是验证指标反弹，模型要停在最低点而不是最后一步。
2. 机制/方法：patience 是容忍验证指标多少轮不提升才停，经验值 3–5。验证集三条硬要求：与训练集同分布、固定不变、不与训练集重叠——否则早停信号本身就是假的。每隔若干步评一次，并且验证指标和对应 checkpoint 都要记下来，不能只记指标不存权重。
3. 关键证据或数字：验证集取法——预训练取约 1%，SFT 用人工标注的高质量数据，RL 用独立 benchmark。监控指标按阶段分工：SFT 看 loss 和任务准确率，RL 看 reward 和 KL，不能只看 loss；SFT 尤其要警惕 instruction loss 在降但生成质量在降的情况。
4. 结论/判断：预训练通常不设早停，因为验证 loss 会持续下降很久、没有明显拐点，按预设步数跑完即可；SFT 本来就只有 1–2 个 epoch，早停基本用不上。

## 可迁移

- 任何微调实验先把「验证集 + 按步存 checkpoint」配好，早停才有回滚对象；只存最后一个 checkpoint 等于没有早停。
- 面试答过拟合对策时，把早停和验证集设计绑在一起讲：信号质量（同分布、不泄漏）比 patience 取几更重要。

## 疑问 / 下一步

- RL 训练里 reward 平台期很长时，「多少步不提升算停」没有现成经验值，可能需要结合 KL 曲线一起判断。
