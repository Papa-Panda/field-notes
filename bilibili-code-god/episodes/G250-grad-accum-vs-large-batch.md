## 一句话总结

梯度累积只是近似模拟大 batch，与真大 batch 有三处不等价：低精度累积的舍入误差、BatchNorm 统计量按小 batch 算、以及累积期间不通信带来的梯度偏差。

## 核心

### 1. 问题/背景

显存不够时常用梯度累积：拆成若干小步分别算梯度、累加后更新一次。直觉上它等价于大 batch，实际有三处偏差，混用时容易踩坑。

### 2. 机制/方法

三个不等价点：一是精度——低精度下多次累加有舍入误差，步数越多误差累积越明显，应用 FP32 的 master weight 兜底；二是 BN 同步——BatchNorm 的统计量按每个小 batch 计算，与真大 batch 的整体统计不同，统计量重要时改用 GroupNorm 替代；三是通信——累积 $N$ 步只通信一次，省了通信，但期间各卡梯度存在偏差。

### 3. 关键证据或数字

实操红线：累积步数建议不超过 32 步，超过后舍入误差累积不可忽视；累积与真大 batch 混用时注意同步调整学习率。

### 4. 结论/判断

显存不够时用累积，但要守住三条：步数 ≤ 32、FP32 master weight 保精度、BN 敏感场景换 GroupNorm；算力与显存允许时优先真大 batch。

## 关键数字

| 项 | 梯度累积 | 真大 batch |
|---|---|---|
| 累积步数上限建议 | ≤ 32 步 | 不适用 |
| BN 统计量 | 按小 batch | 按整个 batch |
| 通信频率 | $N$ 步一次 | 每步 |

## 可迁移

- 写训练框架或复现实验时，配置里若开了梯度累积，要同时检查 master weight 精度与归一化层类型，否则结果和论文对不齐还找不到原因。
- 面试被问「累积等不等于大 batch」，按精度 / BN / 通信三点拆开答，是现成的结构。

## 疑问 / 下一步

32 步上限是经验值，对 BF16 训练（无 master weight 场景）的适用性如何，值得结合实际框架验证。
