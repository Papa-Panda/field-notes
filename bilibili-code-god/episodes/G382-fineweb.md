## 一句话总结

FineWeb 从 Common Crawl 的海量网页里用漏斗式管线（抽正文、语言过滤、质量规则、MinHash 去重）筛出约 15T token 干净语料，而它真正的方法论是每一步都用小模型消融实验验证去留；再用教育价值打分器筛出的 FineWeb-Edu 子集证明了数据质量比数量更决定模型强弱。

## 核心

1. **问题/背景**：同样芯片、同样算力、同样结构，模型聪明程度差距往往来自喂的数据。原始网络爬取语料里绝大多数是导航栏、广告、乱码和重复内容，直接训练就是垃圾进垃圾出。
2. **机制/方法**：四步漏斗管线——先从网页抽正文扔掉模板边角料，再做语言过滤只留目标语言，接着用质量规则砍掉过短、啰嗦、明显低质的页面，最后反复去重。去重是关键一环：互联网内容被转载、镜像几十遍，不去重模型会把同一内容反复背诵、浪费算力又易死记硬背，工程上用 MinHash 在海量文档中快速找出高度相似项成批折叠，且实证分批去重优于一次性全局去重。
3. **关键证据或数字**：整条管线不靠拍脑袋，每个过滤或去重步骤加入前，都用处理前后数据各训一个同规模小模型、在下游基准上比分数，涨分才保留、掉分就砍。沿此思路再进一步：训练专门的打分器给网页按教育价值打分（教科书、百科、讲解类高分，闲聊类低分），只留高分小子集得到的 FineWeb-Edu 体量小了一大截，却在知识与推理类测试上训出明显更强的模型。
4. **结论/判断**：数据处理从玄学变成可量化、可验证的工程：管线全程开源可复现，「消融驱动」是这份数据集封神的原因，而非某个单点技巧。

| 项目 | 数值 |

| 每个管线步骤 | 保留条件 = 小模型消融涨分 |

## 可迁移

- 做 post-training 数据管线时借用这套「消融驱动」纪律：每个过滤/去重/配比决定都配一次小模型对照实验，用分数而不是感觉说话。
- 面试聊预训练数据时能讲清完整漏斗（抽正文 → 语言过滤 → 质量规则 → MinHash 去重 → 质量打分分层），并点出分批去重优于全局去重的反直觉结论。
