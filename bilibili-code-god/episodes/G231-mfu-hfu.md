## 一句话总结

GPU 利用率高只说明卡没闲着，不说明算得有效：MFU 数的是「模型真正需要的 FLOPs」占硬件峰值的比例，HFU 数的是「硬件实际执行的所有 FLOPs」（含激活重算的冗余计算），所以 HFU 恒高于 MFU，两者差距恰好量出了重计算的开销。

## 核心

1. **问题/背景**：`nvidia-smi` 的 GPU-Util 是采样窗口内 SM 活跃的时间占比，内核在空转、做访存、甚至在算无用功时它照样是 100%。用它汇报训练效率会系统性高估，于是大模型训练圈改用基于 FLOPs 的口径。

2. **机制/方法**：MFU（Model FLOPs Utilization）定义为实测吞吐下的模型 FLOPs 与硬件理论峰值 FLOPs 之比。模型 FLOPs 用 Kaplan 近似估算：每 token 约 $6N$（ $N$ 为参数量，前向约 $2N$ 、反向约 $4N$ ），再乘以 token 吞吐即得分子，分母是 GPU 峰值算力（如 A100 BF16 约 312 TFLOPS）乘以卡数。HFU（Hardware FLOPs Utilization）口径相同，但分子计入硬件实际执行的全部 FLOPs：开启梯度检查点（激活重算）后，每步要多算一遍前向，实际 FLOPs 约为模型 FLOPs 的 4/3，这部分冗余在 HFU 里算「干活」、在 MFU 里不算。

3. **关键证据或数字**：PaLM 论文报告 540B 模型在 6144 块 TPU v4 上训练时 MFU 达 46.2%，当时被视为极高水平；主流大模型训练的 MFU 多在 30%–50% 区间。经验换算：同一训练若开全量重算，HFU 约为 MFU 的 1.33 倍，看报告时必须先确认口径再比较。

4. **结论/判断**：三个指标回答三个问题——GPU 利用率答「卡忙不忙」，HFU 答「硬件算力被榨出多少」，MFU 答「这些计算有多少花在模型本身」。做训练优化与成本核算，只认 MFU；GPU 利用率只能当健康检查。

## 可迁移

- 估算自家训练成本时用 MFU 反推：所需卡时 ≈ $6ND$ ÷（峰值算力 × MFU × 卡数），MFU 按 35%–45% 保守取值，避免用 GPU 利用率自欺。
- 面试高频：被问「训练效率怎么看」，答 MFU 定义、$6ND$ 估算与 HFU 的重计算差异，并指出利用率的误导性，是 infra 岗的标准加分项。
