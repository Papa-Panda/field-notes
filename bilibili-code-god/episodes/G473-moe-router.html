2一句话总结

Router 本质就是「线性层 + softmax」的小网络：给每个 token 输出一份专家概率分布，取 top-k 送去计算、按概率加权合并，稀疏激活由此实现。

3核心

  1. 问题/背景：MoE 能做到参数量暴涨而计算量几乎不涨，秘密全在 Router——需要把它从黑盒拆成可手写的实现。
  2. 机制/方法：一层 MoE 由两部分组成：稀疏专家层（把 Transformer 原来的 FFN 换成一组专家，如 8 个，每个专家本身就是一个小 FFN）和门控网络 Router。Router 接收 token 向量 $x$ ，先过线性层 $Wx + b$ ，再套 softmax，输出长度为专家数 $N$ 的概率分布，如 $[0.6, 0.1, 0.2, 0.1]$ 表示第一个专家最匹配；按概率选出 top-k 个专家。Router 的参数与整个网络一起端到端训练，它自己学会给 token 派活。
  3. 关键证据或数字：稀疏激活的账很直观：8 个专家只选 top-2，则只有这 2 个专家真正计算，其余 6 个原地待命、不花算力；两个激活专家的输出按 Router 给的概率加权合并成该 token 的最终结果。由此参数可以塞进几百个专家持续扩容，而每 token 实际计算量只取决于被激活的少数专家，远小于同参数量 Dense 模型，不同专家还能专注不同领域的细粒度知识。
  4. 结论/判断：代价同样来自稀疏：MoE 微调时不如 Dense 直接好用、需要更复杂的调参，还必须额外处理专家间的负载均衡（否则 token 全挤向少数专家）。记住一句话即可：Router 就是个带 softmax 的小网络，负责给每个 token 挑专家。

4关键数字

项目 数值（字幕示例）
专家总数 8 个
每 token 激活 top-2
闲置专家 6 个（零算力）

5可迁移

  • 手撕代码/面试场景可直接复述 Router 三步：线性打分 → softmax 成分布 → top-k 选择 + 加权合并，这是 MoE 实现题的骨架。
  • 做 RL infra 中 MoE 训练时，Router 的负载均衡（token 分布是否均匀）是首要监控量，专家倾斜会直接拖垮吞吐。
