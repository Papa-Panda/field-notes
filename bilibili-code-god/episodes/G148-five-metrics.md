## 一句话总结

loss 只反映模型学得怎么样；grad norm、PPL、MFU、学习率实际值和 token 吞吐量这五个辅助指标负责提前预警稳定性问题与工程效率问题，是拼出训练全貌的最小监控集。

## 核心

1. **问题/背景**：只盯 loss 的监控是滞后的——loss 崩掉时往往已经来不及。有一类指标不直接体现在 loss 上，却能在问题演变成灾难前几步就报警，属于训练的「内科指标」。
2. **机制/方法**：五个指标各管一段。**grad norm** 衡量当前步梯度大小，正常应在稳定范围内波动，突然飙升几个数量级是学习率过大、脏数据或梯度爆炸的前兆，持续趋近于零则可能收敛或卡在鞍点，建议设「超过平均值 10 倍报警」。**PPL** 是 loss 的指数变换（ $PPL = e^{loss}$ ），语义直观且跨模型可比：不同词表大小的模型 loss 不能直接比，PPL 可以。**MFU** 衡量 GPU 实际有效计算占理论峰值的比例，低 MFU 是工程问题而非模型问题。**学习率实际值** 逐 step 打印画曲线，与设计的 warmup/decay 计划对比，抓 schedule 配置错误。**token 吞吐量** 综合反映数据加载、前后向的整体效率。
3. **关键证据或数字**：A100 理论峰值 312 TFLOPS，实际训练 MFU 通常只有 40%–55%；7B 模型预训练结束 PPL 大约在 5–10；PPL 等于 1 表示完全确定下一个 token，等于词表大小表示完全随机猜。
4. **结论/判断**：把五个指标与 loss 并排画在同一仪表盘实时更新（WandB、TensorBoard 都支持）。监控的价值在于时间窗口：grad norm 先飙、loss 还没崩的那几步，就是回滚 checkpoint 或降学习率的机会。

## 关键数字

| 指标 | 正常区间 / 阈值 |
| --- | --- |
| MFU | 40%–55%（A100 峰值 312 TFLOPS） |
| 7B 预训练末 PPL | 约 5–10 |
| grad norm 报警线 | 超过平均值 10 倍 |

## 可迁移

- 训练监控面板设计可直接套用这套六件套（loss + 五指标）；面试聊训练稳定性时，「grad norm 先于 loss 报警、留出回滚窗口」是具体的工程叙事。
- MFU 低先查通信、数据加载、kernel 效率，而不是先怀疑模型结构。

## 疑问 / 下一步

- grad norm 报警阈值用「均值 10 倍」对 RL 训练（梯度分布更重尾）是否还合适，值得在自己的 run 里验证。
