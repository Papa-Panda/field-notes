## 一句话总结

公开 agent 轨迹里藏着环境的「化石」：把文件操作按时间倒放可重建工作区，再补全、过滤、出题，35.9 万条轨迹变成 3.2 万条带可执行判卷的 SFT 样本，让 Qwen3.5-27B 在 Terminal-Bench 2.1 上涨 11.9 分。

## 核心

1. **问题/背景**：终端 agent 训练最缺的不是模型而是能跑的环境——一个带真实项目代码、依赖和判分测试的可执行世界，人工或大模型逐个搭建，成本高所以稀缺；而公开语料里 agent 轨迹有 35 万条以上，记录了读过哪些文件、改了什么、跑了什么命令、看到什么输出，本身就泄露了环境结构。
2. **机制/方法**：三步重建——①确定性回放：按时间顺序倒放轨迹里的读写编辑操作，恢复文件被修改前的状态，得到残缺工作区；②补全代理在不泄漏解法的前提下补齐缺失文件、依赖与上下文，平均文件数从 2.9 涨到 22.4；③充分性过滤：只读 shell 的裁判代理判断工作区是否含完成任务所需的全部上下文，不够的丢弃。环境之上再出题：还原原任务意图、同工作区合成新任务、跨库任务、多轮反馈任务，每题配代理写的 pytest 判卷器，只保留全部测试通过的解题轨迹。
3. **关键证据或数字**：35.9 万条轨迹 → 3.73 万个充分环境 → 3.2 万条 SFT 样本（约 14 亿 token），纯 SFT、无 RL。Qwen3.5-27B 的 Terminal-Bench 2.1 单轮 46.2% → 58.1%（ +11.9 ），Evil Code Bench v2 多轮 6.3 → 20.1（ +13.8 ）。
4. **结论/判断**：与从零合成任务的 Terminal-World 相比，这批任务落在真实项目上下文里，是唯一同时具备可验证、多轮、跨库三特性的方案。边界三条：环境跑在通用 Ubuntu 24.04 容器里，缺专用系统依赖的项目还原不了；覆盖面受源轨迹分布限制；出题、解题、判卷同出一个 teacher，它的盲区就是数据的盲区。

## 可迁移

- agent 日志要存全（命令、文件读写、观察），日志能倒放，环境就能重建——这是把线上 trace 变成可复用训练资产（SFT 之后还能做 RL）的最便宜路径。
- 判卷器优先用可执行测试、不用 LLM 打分；重建环境必须过充分性过滤，残缺工作区进训练集等于教模型在缺上下文时硬编。
