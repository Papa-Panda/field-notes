## 一句话总结
万亿 token 去重的精髓是降维：用 MinHash 签名估 Jaccard 相似度、或用 SimHash 指纹数汉明距离，把「两篇长文像不像」变成短指纹比较，再用 LSH 分桶避开平方级两两对比。

## 核心
1. 问题/背景：网页语料里大量重复——有的原样抄了成百上千遍，有的只改几个词。重复数据的代价是三重的：模型过度记忆原文（过拟合兼隐私泄露）、同内容反复训练白烧算力、质量被稀释。精确哈希只能抓一字不差的副本，抓不到改词转载。
2. 机制/方法：先把文档切成片段（shingle）集合，用 Jaccard 相似度（交集除以并集）量化「像不像」。MinHash 用几十上百个哈希函数各取集合上的最小值，拼成短签名——两签名同位相等的比例恰好约等于真实 Jaccard 相似度。SimHash 走另一条路：特征词按权重投出正负信号、叠加后压成 64 位指纹，内容越像指纹 differing 的位数越少，即汉明距离越小。最后 LSH 把签名切段分桶，只有任一段同桶的文档对才进入精确比对。
3. 关键证据或数字：指纹只有几十到几百维 vs 原文全文比对；LSH 让绝大多数无关文档对根本不进比对环节，把平方级对比量砍掉，这是万亿规模跑得动的关键。
4. 结论/判断：工业级流水线 = 每篇文档生成签名 → LSH 分桶挑候选对 → 按相似度阈值删/留。本质是一次漂亮的降维：贵活（全文相似度）变成便宜活（短指纹相似度）。

## 可迁移
- 这套 MinHash + LSH 正是 FineWeb 等大规模语料去重的同款工具链，做 SFT/预训练数据 curation 时可直接复用思路：先近似去重再谈质量过滤。
- 面试答法成链：为什么去重 → 精确哈希不够 → Jaccard 定义相似 → MinHash 估它 → LSH 避平方对比。
