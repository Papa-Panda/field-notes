## 一句话总结

SFT 与预训练最本质的区别在损失：预训练对每个 token 都算损失，SFT 用损失掩码只对助手回答部分算损失——模型只学怎么回答，不学怎么提问。

## 核心

1. **问题/背景**：预训练模型读过海量文本却常常答非所问、顺着用户的话往下编，因为它只学会了文本接龙，没学会对话。把「博学」变成「可用」的关键一步是 SFT（有监督微调）。
2. **机制/方法**：SFT 数据是人工整理的高质量问答对，并套上对话模板：用特殊标记（如 Qwen 的 chat template 标记）把系统设定、用户提问、助手回答分隔开，让模型分清轮到谁说话。训练时整段对话都读入，但损失只计算回答部分：给每个 token 配标签，回答部分的标签是下一个词的真实 id，其余部分标签设为 $-100$ ，而 PyTorch 交叉熵默认忽略标签为 $-100$ 的位置，于是梯度只从回答部分回传。
3. **关键证据或数字**：三点区别——数据不同（无标注连续文本 vs 精选问答对）、损失不同（全 token vs 仅回答）、目的不同（知识广度 vs 任务精度与对话格式）。
4. **结论/判断**：SFT 是承上启下的一环：它接在预训练之后，又是 RLHF 的地基——奖励模型从 SFT 模型改出，PPO 的起点也是 SFT 模型。掩码实现只需一行核心逻辑，但决定了模型学的是「回答」而不是「模仿整段对话」。

## 可迁移

- 写多轮对话 SFT 数据管线时，掩码边界（模板标记、回答起止位置）是最容易出错也最值得单测的地方：掩码错位一格，模型就会学着生成用户的话或提前停。
- 面试高频题「SFT 和预训练的区别」按数据、损失、目的三点答，并落到 $-100$ 标签与梯度只回传回答部分这一实现细节上。

## 疑问 / 下一步
