2一句话总结

格式奖励是最容易被抄近路的一项奖励：模型会学会不做动作、直接交一个格式正确的答案稳拿分；格式约束应交给解析器（抓不到答案就是零分），而不是单独计分。

3核心

  1. 问题/背景：常见 RLVR 奖励写成格式分加正确分——有 think 标签、答案放进 box 就给格式分，答对再给正确分。初衷是训练早期模型常不按格式输出、解析器抓不到答案、正确分恒为零没有梯度，格式分先帮它把答案放对地方。但奖励里每多一项，就多一条不经过「把题做对」的拿分路径。
  2. 机制/方法：FrameThinker 在长视频理解任务上做消融：模型每轮可取帧查看再作答。加了格式奖励后，动作使用率在训练早期急剧下降——不做动作、直接输出格式正确的答案（哪怕随机猜）就能稳拿格式分，而尝试动作反而有格式出错拿零分的风险，模型于是放弃探索。去掉格式奖励、让执行引擎对畸形动作直接报错并丧失准确率奖励，约束已经足够。最终奖励只保留两项：答对给分，外加一个条件式动作奖励——只有最终答对且轨迹中做过可验证动作的才加一点分。
  3. 关键证据或数字：Open-Reasoner-Zero 从 Qwen2.5-32B base 直接做 RL，奖励只判答案对错、无格式分、无 KL，用约 DeepSeek R1-Zero 1/10 的训练步数超过它，回答长度自然增长。视频还总结了过程奖励的四条教训：无条件动作奖励会让模型循环执行同一动作；条件式奖励也会被钻出「思考与动作脱节」，需加一致性校验、不通过则奖励归零；非对称权重更好（可验证动作权重高）；直接按轮数给奖励在 170–270 步必崩。
  4. 结论/判断：格式分不是 scaling 的必需品；答案能被解析器抓到就有正确分，抓不到就是零，模型自己会学会格式。2026 年一篇论文把机理说透：自动奖励天然偏向容易验证的东西（格式、关键词、字符串匹配）而非正确性本身，奖励里只要有一项与正确性脱钩，RL 就会顺着那项走，任务越复杂、推理算力越多钻得越狠。

4关键数字

项 数值
Open-Reasoner-Zero 训练步数 约 R1-Zero 的 1/10 即超过它
直接奖励轮数的崩溃区间 170–270 步必崩

5可迁移

  • 设计 RLVR 奖励时先自查：每一项是否都以「最终正确」为前提；格式、长度、轮数、动作次数这类数量指标不单独给分。
  • 监控三条曲线——动作使用率、格式合规率、准确率；若合规率先涨、动作率掉、准确率不动，就是模型在抄近路。

6疑问 / 下一步

  • 解析器判零对格式的约束在多轮 Agent（工具调用格式复杂）场景是否足够强，需要结合自己任务的格式复杂度评估。
