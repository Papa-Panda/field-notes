## 一句话总结
自投机解码不用外挂小模型当草稿：让大模型只跑前一部分层、从半路出口快速接龙出候选 token，再用跑满全部层的自己一次性并行验证，同一套权重、零额外显存、结果无损，速度接近翻倍。

## 核心
1. 问题/背景：自回归生成慢在每吐一个 token 都要把整网跑一遍。投机解码用小草稿模型先猜多个 token、大模型一次验证，但痛点是必须额外准备并加载草稿模型——凭空多占一份显存，还要费力让它与大模型对齐分布。
2. 机制/方法：草稿就用大模型自己。输入只往前跑一小半层，在半路开一个出口直接读出下一个 token（提前退出），跳过后面大半层、计算量小得多，于是飞快接龙出多个候选；草稿糙、夹带错误没关系，随后完整模型把这几个 token 一次性喂入、跑满全部层并行核对，与自身判断一致的接受并前进，撞上第一个对不上的就停下、其后草稿全部作废。这样验证出的结果与逐个生成完全一致，无损加速。
3. 关键证据或数字：草稿与验证共用同一套权重，显存占用一点没多；训练时做层随机丢弃（逼浅层也能给出像样预测）、半路出口与最终出口共用同一个输出头，可明显提高跳层草稿的接受率，实测生成速度稳稳拉到接近 2 倍。
4. 结论/判断：自投机是"几乎白捡"的加速：省掉的是外置草稿模型的显存与对齐成本，代价是需要训练侧配合（层丢弃调教）才能让浅层草稿足够靠谱。

## 可迁移
- RL infra / 推理加速：rollout 阶段是 RL 训练的大头开销，投机类无损加速（含 G120 的 draft 模型路线）可直接对比选型——显存紧张选自投机，有闲置显存且能训好小 draft 时外置路线接受率可能更高。
- 面试要点：讲清"浅层草稿 + 全模型并行验证 + 首错截断 + 分布无损"四步，即可完整复述投机解码家族。
