## 一句话总结
一张高清图会变成上千个视觉 token、又多又冗余，而注意力是平方复杂度——ToMe 靠逐层合并相似 token、FastV 靠深层剪掉低注意力 token，两条路线殊途同归地给视觉 token 做减法。

## 核心
1. **问题/背景**：图像被切成 patch、每个 patch 成一个视觉 token，高清图轻松上千个，远多于同等内容的文本 token；而注意力要两两计算，token 翻倍计算量翻四倍——视觉 token 是多模态推理又慢又贵的头号原因。但冗余也大：蓝天、白墙等相邻 patch 几乎一模一样，信息高度重复。
2. **机制/方法**：两招都免训练、即插即用。ToMe（合并派）：每层把 token 分成两组，组间按特征方向相似度找最像的伙伴，只挑最相似的若干对两两取平均合成一个，每层固定减掉一批，逐层瘦身、信息尽量保留。FastV（减脂派）：抓住视觉 token 主要在前几层被吸收、到深层注意力分数低得可怜的现象，在某一层之后按注意力分数排序，直接剪掉大部分不重要的视觉 token，只留少数关键的。
3. **关键证据或数字**：套上这类方法，视觉 token 可砍掉一半甚至更多，FLOPs 大降、推理成倍提速，而各项理解任务准确率几乎不动。
4. **结论/判断**：一个温柔（合并保信息）、一个激进（剪枝丢冗余），共同逻辑是：先证明 token 里有水分，再选压缩方式把水分换成速度与成本。

## 可迁移
- 同一思路可迁移到长上下文与 Agent 轨迹：凡 token 量大且冗余高的输入（历史观察、检索结果），先想合并/剪枝再想扩窗口。
- 面试被问多模态提速，按「token 从哪来 → 为何平方级贵 → 冗余在哪 → 合并 vs 剪枝」这条链答，比罗列方法名更稳。
