## 一句话总结

复读源于已生成词的自我强化，解法是在 softmax 之前给出现过的词扣分：存在惩罚是「出现过就扣固定分」的开关，管话题发散；频率惩罚是「扣分随出现次数线性增长」的旋钮，专治逐字复读。

## 核心

1. **问题/背景**：生成时某些词一旦被选中，会让上下文越来越像它自己，分数不降反升，下一轮还选它，形成死循环；温度越低复读越严重。
2. **机制/方法**：存在惩罚对词的 logit 减去系数乘以指示函数（出现过记 1、没出现记 0），出现一次和十次扣分相同，作用是把模型推向新话题。频率惩罚减去系数乘以该词已出现次数，重复越多扣得越狠，直接掐断逐字循环。两者在 OpenAI 接口里写进同一公式、可叠加，参数范围均为 −2 到 2，作用于 softmax 之前的分数、仅推理采样阶段生效，不改模型权重。HuggingFace 的 repetition penalty 是另一套乘法实现：正分数除以系数、负分数乘以系数，一个旋钮统一让重复词概率下降。
3. **关键证据或数字**：两值都设 0 即纯采样、无惩罚；都开太大会连虚词和标点都被过度扣分，模型为避开常用词强行拼凑生僻词，反而语无伦次。
4. **结论/判断**：按症状拧旋钮——话题太单一调存在惩罚，逐字复读调频率惩罚；惩罚是采样层解法，不解决模型本身的分布问题。

## 可迁移

- 做 Agent/rollout 采样时，生成重复往往先查解码参数而非模型：presence/frequency penalty 与温度、top-p 是同一层的问题。
- 注意区分 API 的加法惩罚与 HF 的乘法 repetition penalty，迁移配置时数值不可直接照搬。
