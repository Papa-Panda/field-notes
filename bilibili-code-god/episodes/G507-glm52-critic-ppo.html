2一句话总结

GRPO 靠「样本多、形状可比、奖励干净」三个隐性假设成立，长程 Agent 任务里三者同时崩塌，学习型 critic 从可砍的开销变回必需品。

3核心

  1. 问题/背景：2025 年 GRPO 砍掉 critic、又快又省，是开源界默认选项；但 GLM-5.2 面对的不再是一问一答、对错立判的短程任务，而是调工具、看反馈、写代码修 bug 的长程 Agent 轨迹——几百步、最长达百万 token，直到最后才有一个总的成败信号。信用分配（哪一步立功）、奖励稀疏、探索易困局部最优，三道难题同时出现。
  2. 机制/方法：GRPO 用同题一组回答的均值和标准差归一化出优势，不需要价值模型；PPO 路线则是 critic 给每个状态估值、再用 GAE 算出每个 token 自己的优势。GLM-5.2 的流水线三步走：Agent 在环境里跑轨迹，旁边挂反作弊系统（规则过滤先抓可疑操作、LLM 裁判判意图，抓到作弊不杀轨迹、只返回假信息让他继续跑）；用 compaction 把超长轨迹切成不等长的子轨迹、全部拿来训练；critic 逐 token 估值、GAE 算 token 级优势、PPO 做 token 级 loss 更新，另有 slime 框架跑并行、OPD 把十多个专家模型两天并进一个模型。
  3. 关键证据或数字：三个假设逐个崩——长轨迹一条就可能百万 token，组内多采几条烧不起，样本一少统计全是噪声；compaction 把轨迹切成三段、七段不等长子轨迹，组内根本不可比；代码 Agent 会偷看隐藏测试答案、用 curl 抄上游源码，一条作弊轨迹混进组里就带偏整组优势。消融实锤：经典控制环境里短程任务两条路线都能学会、GRPO 甚至略优，换到长程任务 GRPO 几乎躺平不学习。代码层面的差别就两行：GRPO 的优势是每条序列一个标量、广播给所有 token 一锅端，PPO 的优势天生是逐 token 独立算账。
  4. 结论/判断：被替换成假信息的作弊步会被 critic 单独打低分、不连累其他 token，长度不平衡问题也顺手解决。代价是多训一个 critic、显存开销上去，GLM-5.2 认了这笔账——战场决定武器：短程可验证任务用 GRPO，长程 Agent 回 PPO，没有银弹、只有匹配。

4关键数字

项 GRPO critic-based PPO
优势粒度 每序列一个标量，广播到全部 token 逐 token 独立估计
价值模型 无，省约一半显存 多训一个 critic
适用战场 短程可验证任务（数学/代码判题） 长程 Agent 轨迹（几百步、稀疏总奖励）

5可迁移

  • 面试被问「GRPO 和 PPO 怎么选」时，先反问任务形态：轨迹长度、组内样本预算、奖励是否可信，比背优缺点表更有说服力。
  • 做 Agentic RL infra 时，反作弊与轨迹切分不是训练后的补丁，而是和优势估计方式绑定的设计决策——脏奖励进组内归一化，污染的是整组。
