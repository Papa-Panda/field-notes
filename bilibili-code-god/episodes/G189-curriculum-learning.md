## 一句话总结

课程学习的胜负手不是给数据分难度，而是把训练中的正确率稳在 70%–80% 的「跳一跳够得着」区间：先用基座模型 pass rate 给题打难度分，再按正确率门槛自适应加难。

## 核心

1. **问题/背景**：传统训练把数据打乱均匀喂，模型没有先易后难的台阶；在 RL 里问题更尖锐——一上来就给难题，模型完全拿不到奖励、没有梯度信号，课程学习同时是在缓解奖励稀疏。
2. **机制/方法**：三步落地。难度评估首选让基座模型先跑一遍推理，能答对的是简单题、答不对的是难题（pass@1 即难度分），也可用答案长度/推理步数做代理或人工标注。课程设计有线性递增（先全简单、再混中等、再混难）、指数衰减简单题占比、按正确率动态调整三类。pacing 控制节奏：加太快基础没打牢、加太慢在简单题上浪费算力。
3. **关键证据或数字**：经验法则是当前难度正确率达到 70%–80% 时混入更高难度。RLVR 里的典型做法是把数学题按通过率分 5–10 级，先只用最简单两级训练，正确率超 80% 再加一级，逐级放开直到全部难度加入。
4. **结论/判断**：分级只是准备工作，真正起作用的是 pacing——让模型始终处在「有信号又不轻松」的难度带上，太易没梯度、太难也没梯度。

## 可迁移

- RLVR/GRPO 的数据管线里可直接复用这套：用基座 pass rate 预筛难度、按组内通过率动态调采样配比，与 G125 的温度调节是同一件事的两个抓手。
- 难度评估要在训练前离线跑完并落盘，训练中只读分档，避免把评估成本摊进每一步。

## 疑问 / 下一步

- 难度分档会随模型变强而漂移，是否需要周期性重估难度、以及重估频率如何定，视频未展开。
