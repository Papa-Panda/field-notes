## 一句话总结

RL 超参的最优值随训练阶段漂移，固定日程根本抓不住：LLMZero 让 agent 在每个 checkpoint 先读指标诊断病症、再用树搜索协同改一组参数；更值钱的是它跑出的规律——容量类参数单调递增、正则类参数来回震荡，这条规律不用 agent 也能指导人工调参。

## 核心

1. 问题/背景：RL 后训练的超参分两类：容量类（最大回答长度、每题采样数、batch 大小）决定模型能探索多大的空间；正则类（KL 系数、熵系数、clip 上下界、温度）决定探索与利用的平衡。两类的最优值都随阶段变——早期要保守防塌、中期要放开探索、后期要收敛。人工只能盯着面板一次改一个、等几百步才知道对不对；网格搜索又太贵。
2. 机制/方法：LLMZero 把训练切成多个阶段：每个 checkpoint 上，agent 先读训练指标（reward 曲线、熵、平均长度、截断率、KL、clip 比例）诊断病症——是熵塌了、长度爆了、reward 平台了还是不稳定；再用树搜索提出一组协同调整（例如同时放长度上限、升温度、降 KL），而不是一次只动一个；跑一小段验证，好的分支继续展开、差的剪掉，最终得到一条每段参数都不同的多阶段训练轨迹。
3. 关键证据或数字：四个 GRPO 任务上，比固定配方基线高 9%–140%（跨任务差异很大），比网格搜索高 6%–15%，同算力预算下稳定优于随机搜索与技能型 agent。轨迹规律是最有价值的产出：容量类参数（长度上限、采样数）在各阶段单调累加、一路往上不回头；正则类参数（KL、熵、clip）主要在震荡——熵塌了就加、探索过头了又减，来回摆。这说明固定 KL 系数在某些阶段太紧、另一些阶段太松，固定日程抓不住探索-利用的动态。不利面也要讲清：它不是零成本自动化，多阶段调整要付出额外的 agent 推理成本，且效果依赖指标本身可读。
4. 结论/判断：哪怕不用 agent，也能把规律拿来做人工调参启发式：① 训练切成 3–4 段、每段单独配参数；② 容量参数按阶段递增（长度上限、采样数一路加）；③ 正则参数按症状动态调（熵低于阈值就加熵系数或升温度，KL 涨太快就加 KL，clip 比例过高就收 clip）；④ 每段结束看 reward、熵、长度、截断率四个指标，再决定下一段。

## 可迁移

- 自己的 GRPO/PPO 训练直接套用分段策略：容量参数（max length、rollout 数）按阶段递增，正则参数（KL、熵、clip）按面板症状逐段调，别再用一条固定日程跑到底。
- 面试或复盘谈 RL 调参时，用「容量 vs 正则」二分法组织答案，比罗列超参清单更有结构。
