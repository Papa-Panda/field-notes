## 一句话总结
剪枝去掉对输出贡献最小的权重或整块结构让模型变小变快：非结构化逐个权重置零、压缩率高但通用硬件跑不快；结构化整块切除、模型真的变窄变浅、拿来就能提速；标准做法是按幅度剪 + 微调恢复的迭代循环。

## 核心
1. 问题/背景：训练后的网络里大量权重接近零、几乎不贡献输出，这些冗余去掉后模型体积、显存与计算量都降，精度却可以几乎不掉。
2. 机制/方法：两条路线——非结构化剪枝逐个把小权重置零，得到稀疏矩阵；结构化剪枝整块删神经元、通道、注意力头甚至整层。选谁删主要看权重幅度（绝对值），更讲究的方法会结合梯度或二阶信息估重要性。
3. 关键证据或数字：非结构化可把八九成权重置零，但零散分布的稀疏在通用 GPU 上不会自动加速，需要专门的稀疏计算支持；结构化压缩率没那么极致，但矩阵实打实缩小，普通显卡直接提速。流程上要「训练 → 剪枝 → 微调恢复」并迭代进行，一次剪太狠精度难补回。
4. 结论/判断：选型看落地条件——有稀疏硬件、追求极限压缩选非结构化；通用硬件上想直接变快，结构化往往更实用。

## 可迁移
- RL infra / 推理优化：评估压缩方案时先问「稀疏能不能被硬件吃掉」，避免只看参数减少比例就宣称加速。
- 面试答剪枝按「删什么（权重 vs 结构）→ 按什么标准（幅度/梯度/二阶）→ 怎么恢复（迭代剪 + 微调）」三段式组织。
