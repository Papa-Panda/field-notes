## 一句话总结

评测频率的本质是在算力和早发现问题之间取舍：用轻量 proxy benchmark 高频监控趋势、用完整 benchmark 低频支撑决策，再加一道数据污染检测，构成训练—评测—调参的闭环。

## 核心

1. **问题/背景**：完整 benchmark（MMLU + GSM8K + HumanEval 等）跑一次要几十分钟到几小时，每步都测严重拖慢训练；但完全不测只看训练 loss，又不知道下游能力在进步还是退步——训练 loss 下降不代表实际能力提升。
2. **机制/方法**：分级评测。**Proxy 高频**：从完整 benchmark 抽一小部分（如 MMLU 前 200 题），几分钟跑完，结果不精确但能快速反映趋势，可每 1000 步跑一次，几乎不影响训练。**完整低频**：每 5000–10000 步或每个 checkpoint 跑一次，耗时但精确，目的是做决策——模型够不够好、要不要调超参、要不要停训。不同阶段频率不同：预训练盯 loss/PPL 与少量 benchmark；SFT 每个 checkpoint 跑完整评测看任务指标；DPO 每个 checkpoint 看 preference accuracy 与奖励差距；RLHF 每个 checkpoint 看 reward model 评分与 KL 散度，越往后阶段越敏感、测得越密。
3. **关键证据或数字**：数据污染检测不可省：对评测集每条数据在训练集里用 MinHash 或 embedding 相似度搜索重叠，重叠率超过 5% 就需要清洗；GSM8K 和 MMLU 都报告过被训练数据污染导致分数虚高的问题。另要保留一份干净的私有集兜底。
4. **结论/判断**：proxy 解决「早发现」，完整评测解决「敢决策」，污染检测解决「分数可信」，三者缺一不可。

## 关键数字

| 项 | 建议值 |
| --- | --- |
| proxy 评测间隔（预训练） | 每约 1000 步 |
| 完整评测间隔 | 每 5000–10000 步 / 每个 checkpoint |
| 污染重叠率清洗线 | > 5% |

## 可迁移

- 自己的 RL/SFT 实验同样适用分级评测：小样本快速集看趋势、全量集只在关键节点跑，省下的算力直接换迭代速度。
- 面试谈评测体系时，「趋势监控 vs 决策验证」两层分离 + 污染检测是完整的回答骨架。

## 疑问 / 下一步

- proxy 子集的抽样方式（固定前 N 题 vs 分层随机）对趋势保真度影响多大，值得查一下公开实践。
