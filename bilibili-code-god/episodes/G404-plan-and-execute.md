## 一句话总结
Agent 长任务的成败不在智商在范式：ReAct 边想边做灵活但易迷路且贵，Plan-and-Execute 先用一次规划立全局蓝图再顺序执行，实战最优解是规划 + 按需重规划的混合式。

## 核心
1. 问题：智能体干活本质是连续做「下一步调哪个工具」的选择，任务越长选择越多；同样能力的模型，有的走着走着忘了最初目标，有的稳稳做完——差别来自决策范式不同。
2. 机制：ReAct 是「想—做—看」小循环，每步依据最新观察决定下一步，能即时纠偏；Plan-and-Execute 拆成两个角色——规划器只调一次大模型，把任务拆成编号完整的计划，执行器再照单逐步落地，每步对照全图检查，发现与预期不符就退回规划器对剩余步骤重规划。
3. 关键证据或数字：视频未给量化基准，定性对比是：ReAct 每步都要调一次大模型思考，token 成本随步数线性飙升；Plan-and-Execute 只在开头集中思考一次，执行阶段开销低得多；长任务中 ReAct 因无全局蓝图，十几步后跑偏、遗忘原目标的概率显著上升。
4. 结论：短任务几步搞定用 ReAct，又快又稳；长任务先拆蓝图保方向、执行中遇意外再重规划补灵活性——「长任务先规划、短任务边走边想」是选型口诀。

## 可迁移
- 设计自己的 agent 工作流时同理：把「规划」做成显式产物（清单/计划文件）再执行，比全程即兴调用更抗跑偏，也方便中途审计与恢复。
- 成本意识：每步一次大模型调用 = 延迟与 token 双线增长，长链路任务先算这笔账再选范式。
