2一句话总结

梯度检查点只保留少数层边界的激活、其余丢弃，反向时从最近存档点重算一小段来复原激活，用约多一次前向的计算换来激活显存从线性降到根号级。

3核心

  1. 问题/背景：训练显存的大头往往不是参数，而是前向每一层产生的中间激活（一层注意力就有 Q、K、V、分数矩阵、Softmax 结果、输出等），乘上几十上百层远超参数本身。偏偏这些激活不能随手删：反向传播是链式求导，每算一个梯度都要拿前向存下的激活当乘数，删了梯度就没法算。
  2. 机制/方法：做法是每隔几层只留一个存档点，其余中间激活一律丢弃；反向走到哪一段，就从最近的存档点把这一小段重新前向算一遍，临时复原激活、用完再丢。数学上有个漂亮结论（源自 1992 年 Griewank 的经典工作）：每隔 $\sqrt{N}$ 层存一个，共存 $\sqrt{N}$ 个，激活显存从 $O(N)$ 降到 $O(\sqrt{N})$ ，每段重算长度也是 $\sqrt{N}$ ，额外计算合计约等于多做一次前向——这是显存与重算之间的最甜平衡点。工程落地有三种形态：分段式（PyTorch 的 checkpoint 把整层打包，只留入层输入、反向整块重算）、极致式（FlashAttention 干脆不存巨大的注意力分数矩阵，用片上 SRAM 分块、反向时现场重算小块）、选择性重算（按成本算账，便宜的层重算、昂贵的大矩阵乘法优先保留）。
  3. 关键证据或数字：经验口径是省约八成激活显存、只慢约两成。注意命名之争：「激活检查点」与「梯度检查点」是同一种技术，前者侧重存的是什么（前向激活），后者侧重为了什么存（反向算梯度）。
  4. 结论/判断：显存不够时第一个该想到的技巧就是它——几乎零改动成本，拿时间换空间；但要清楚它省的是激活显存，参数、梯度与优化器状态的显存它一分不省。

4关键数字

指标 不开检查点 开检查点
激活显存 $O(N)$ $O(\sqrt{N})$（间隔 $\sqrt{N}$ 层存一个）
额外计算 0 约多一次前向，整体约慢两成

5可迁移

  • RL 训练里 rollout 与训练共卡、显存吃紧时，先开 gradient checkpointing 再考虑降 batch；代价约两成速度可预期、可量化。
  • 面试回答要分清显存四本账（参数、梯度、优化器状态、激活）：检查点只动激活这一本，与 ZeRO/卸载动的是另外三本，别混答。
