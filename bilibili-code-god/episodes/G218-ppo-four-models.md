## 一句话总结

PPO 训练时显存里同时住着四个模型：演员负责生成、奖励模型负责打分、评论家提供个体化基准线把优势算出来以降方差、参考模型用 KL 惩罚防止策略为刷分跑偏——只有演员被训练，其余三个冻结或只出信号，这正是 PPO 强大又费显存的原因。

## 核心

1. 问题/背景：只按绝对奖励更新策略有两个毛病：起步弱的样本即使进步巨大也拿不到高分、不被鼓励；起步强的样本为冲满分容易走极端——本质是单靠奖励信号方差太高，训练不稳。
2. 机制/方法：四模型分工——演员（policy）即被训练的语言模型，负责生成回答；奖励模型对每个回答打一个标量分，是最直接的反馈；评论家（critic/value）为每个状态估一条预期基准线，实际分减基准线得到优势（advantage），把「绝对好坏」换成「比自己预期好多少」；参考模型是演员的初始快照，用 KL 散度惩罚约束当前策略不要偏离太远。
3. 关键证据或数字：数据流为四路汇合——演员生成 → 奖励模型打分 → 评论家估基准算优势 → 参考模型算 KL 距离，四路信号合成梯度只更新演员参数；另外三个模型要么冻结、要么只提供信号。
4. 结论/判断：四模型缺一不可的分工（生成/打分/降方差/防跑偏）是 PPO 稳定性的来源，也是它显存开销大的根源，这直接引出后续 GRPO 砍掉 critic 的动机。

## 关键数字

| 模型 | 角色 | 是否训练 |
|---|---|---|
| 演员 policy | 生成回答 | 是（唯一被更新） |
| 奖励模型 RM | 对回答打分 | 否 |
| 评论家 critic | 估基准线、算优势、降方差 | 只提供信号 |
| 参考模型 ref | 算 KL、约束防跑偏 | 否（冻结） |

## 可迁移

- 估算 RLHF 训练显存时按四份模型权重（含优化器状态只在演员侧）做预算，能提前解释为什么 PPO 的资源需求远高于 SFT。
- 理解 GRPO 的省显存逻辑就抓住了主线：它用组内样本均值替代评论家的基准线，四模型变三模型。
