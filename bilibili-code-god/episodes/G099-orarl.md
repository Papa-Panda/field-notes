## 一句话总结

把标准答案当满分 rollout 塞进 GRPO 组会抬高组均值、把原本正优势的好样本判成负优势（优势反转）；OraRL 把「策略自己的基线」和「标准答案的拉力」拆开算，用 2.2 倍 SFT 的成本拿到 RL 的效果。

## 核心

1. 问题/背景：手里有标准答案，做 GRPO 时顺手把它当一条满分 rollout 塞进组里让模型跟着学，听起来天经地义。但 GRPO 没有 critic，一条回答好不好靠同组兄弟的相对尺子：优势 = 自己的分 − 组均值，再除以标准差。基线完全由组内样本决定，尺子本身一动，所有人的评价都跟着变——这正是出事的地方。
2. 机制/方法：标准答案拿满分入组后，组均值立刻上移（新均值 = 原均值 + (标准答案分 − 原均值) / 9 ，以组大小 8 加 1 条为例）。分数落在原均值与新均值之间的回答原本是正优势的优等生，被新尺子一量变成负优势、被往下压——你以为塞进去的是老师，其实塞进去的是裁判偏见。OraRL 的修法是把两件事拆开算：① 策略自己的基线不含标准答案，优势仍是分数减原均值，兄弟之间还是原来那把尺子；② 方向增益只给正优势样本加一个放大系数，系数看加入标准答案后组离散度的变化（四次方根、截断到 1 到 4 之间），标准答案离大家越远越鼓励往那个方向走；③ 标准答案自己的优势单独算（高出原均值的量平方后乘 2 ，封顶为组内最强样本的 1.2 倍），策略越接近标准答案拉力越小、自动退场；最后再去一次均值，抹掉不对称缩放带来的偏差。
3. 关键证据或数字：朴素塞法的账——组均值被抬高，22.4% 的正样本翻成负的，42.5% 的组里出现反转，8.3% 的组一条正样本都不剩；跟踪任务翻转率 38.7% ，mIoU 从 60.3 掉到 55.4 。修好之后，同一 4B 模型上 OraRL 做到 62.7 ，高于 SFT 的 57.8 、GRPO 的 60.3 、Dr. GRPO 的 60.7 与 CPPO 的 60.5 ，任务专用奖励整形能把朴素塞法救到 61.2 ，但通用解耦做到 62.7 。成本上每步 62.4 秒、是 SFT 的 2.2 倍，而带思维链的 GRPO 每步 135.6 秒、是 SFT 的 4.9 倍；推理不用思维链、130 ms 出答案，带思维链要 4780 ms 。
4. 结论/判断：什么时候该塞标准答案——rollout 全错、组里没有正样本、梯度为零时最值得塞。有标注的任务把标注序列化成模型输出格式即可用（区间框、mask、轨迹、文本答案都行）。塞了之后一定要盯反转率（统计多少样本的优势符号被翻）；基线一定不含 oracle ，oracle 的拉力单独算、还要随策略进步衰减。一句话：有答案是好事，但别让它改写你的基线。

子任务上：持续定位 62.5 → 66.0 ，跟踪 73.0 → 78.0 ，分割 64.3 → 70.4 ；空间理解 VSI-Bench 73.1（GPT-5 为 55.0）。

## 可迁移

- RL infra 排障清单：凡是往 rollout 组里混入外部样本（标准答案、教师轨迹、回放数据），都要先问它会不会移动组基线，并把「优势符号反转率」加进训练监控面板。
- 面试要点：GRPO 的基线是相对尺子，这是它与带 critic 的 PPO 在数据注入上最本质的差异；讲 OraRL 时抓住「基线不含 oracle、增益只给正样本、拉力随接近衰减」三句即可。
