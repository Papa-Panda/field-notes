## 一句话总结

自回归生成中 Q 是一次性的——每个新 token 自带新 Q、算完即弃；而历史 token 的 K、V 要被之后每一个新 Q 反复查询，必须留存复用，否则总计算量随上下文平方增长，缓存后降为线性。

## 核心

1. 问题/背景：KV Cache 是推理标配，但很少有人讲清为什么偏偏只缓存 K 和 V。答案藏在注意力三角色的不对称里：Q 是当前 token 的查询，K 是每个 token 的检索标签，V 是每个 token 携带的内容。
2. 机制/方法：每生成一个新 token，它带着自己的 Q 与全部历史 K 做匹配、读出对应 V，算完这一步注意力后这把 Q 再也不会被用到——缓存它纯属浪费。反过来，历史每个 token 的 K、V 会被后续所有新 Q 反复翻查，像一个只增不改的知识库，所以必须驻留显存。新 token 到来时只需算自己这一份 QKV，再拼上缓存的历史 K、V 做注意力。
3. 关键证据或数字：不缓存时，每生成一个 token 都要把全部历史 K、V 从头重算，总量是 $ O(n^2) $ ——上下文长一倍、计算翻四倍；缓存后降为 $ O(n) $ 线性增长，本质是以显存换计算。
4. 结论/判断：这条不对称也解释了整条 KV 优化线的着力点：MHA 每头一组 KV 最准但最费显存，MQA 让所有头共用一组 KV 最省但略掉点，GQA 分组共享是当前主流折中，DeepSeek 的 MLA 更进一步用低秩压缩把 KV 压成一个 latent 向量——所有优化都在动 K、V，从没人动 Q，因为 Q 根本不在缓存里。

## 可迁移

- 面试讲推理优化时，先立「Q 一次性、KV 持久性」这根轴，再挂 MQA/GQA/MLA/量化/淘汰策略，整条优化线立刻成体系，而不是罗列名词。
- 做 rollout 引擎的容量估算时，KV Cache 大小由层数 × 头数 × 序列长 × batch 决定，是长上下文 RL 采样显存的第一项，应先于权重做预算。

## 疑问 / 下一步

- MLA 把 KV 压成 latent 向量后与 RoPE 的兼容需要解耦设计，其在 RL 训练侧（训练/推理一致性）的实现代价值得单独拆解。
