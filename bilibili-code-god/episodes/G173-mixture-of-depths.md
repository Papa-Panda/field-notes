## 一句话总结

MoD 让每层的路由器决定每个 token 是过这一层还是走残差跳过——在深度方向做稀疏，与 MoE 的宽度稀疏正交且可叠加。

## 核心

1. 问题/背景：标准 Transformer 里每个 token 都要走完所有层，计算量随层数线性增长；但停用词、标点这类简单 token 并不需要深层处理，真正吃算力的是少数复杂 token，均匀计算是浪费。
2. 机制/方法：每层加一个轻量路由器（线性层 + sigmoid）给 token 打分，只有 top-k 的 token 进入该层计算，其余经残差连接直接跳过；跳过的 token 不参与该层前向、也不需要该层反向传播。
3. 关键证据或数字：DeepMind 的结果显示，相同算力下 MoD 优于 dense 模型，或相同效果下省约 $20\%$–$30\%$ 的推理计算量，质量损失不到 $2\%$ 。
4. 结论/判断：MoD 最适合推理密集、长短混合的高并发场景；不适合训练密集型场景，因为训练时路由器本身有开销。实操上路由器要先 warm up（前期不跳层、模型稳定后逐渐开启），跳层比例需监控、不要超过 $50\%$ ，否则质量明显下降。

## 关键数字

| 项目 | 数值 |
|---|---|
| 推理算力节省 | 约 $20\%$–$30\%$ |
| 质量损失 | 小于 $2\%$ |
| 跳层比例警戒线 | 不超过 $50\%$ |

## 可迁移

- 面试可讲的框架：稀疏化有两个正交方向——MoE 砍宽度（选专家）、MoD 砍深度（选层），二者可叠加；类比思考推理预算按 token 难度分配，也是自适应计算的一种形态。
- 做推理成本优化时，MoD 是「按难度分配深度」的思路来源：简单请求浅出、复杂请求深算，比一刀切减层更保质量。
