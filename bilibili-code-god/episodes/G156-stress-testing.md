## 一句话总结

训练集里干净规整的输入不是生产环境的考场：上线前要按超长、空、特殊字符、多语言、对抗、重复六个维度系统压测，并把压测卡进发版流程。

## 核心

1. **问题/背景**：训练数据长度合理、格式规范，但真实用户会发十万字超长输入、零宽控制字符、多语言混排；在训练数据里占比不到万分之一的输入，上线后足以引发 OOM 或乱码崩溃。
2. **机制/方法**：六维测试集——超长输入（超过 max length 如何处理）、空输入、特殊字符（零宽/控制字符、emoji）、多语言混排（中英日韩阿拉伯语）、对抗输入（prompt injection）、重复输入（同一问题问上百次）。超长输入三种策略按场景组合：硬截断（简单但丢信息）、滑窗分段后合并、直接拒绝（最安全但体验差）；客服类倾向拒绝、搜索类倾向滑窗、分类类可用截断。特殊字符靠 tokenizer 前清洗：去控制字符、Unicode 规范化，并确认 tokenizer 对多语言字符的覆盖——常见 bug 是 tokenizer 遇到没见过的字符输出空 token 直接崩溃。
3. **关键证据或数字**：自动化框架：从日志与人工构造收集极端案例，每维度备 100–500 条，每次更新自动跑并设通过率阈值，持续从线上回流新案例。
4. **结论/判断**：健壮性不是上线后测出来的，而是把压测卡在发版路径上、失败率超阈值就阻断发布，逼出来的。

## 关键数字

| 事项 | 数值 |
|---|---|
| 极端输入在训练数据中的占比 | 不到万分之一 |
| 每维度测试集规模 | 100–500 条 |
| 发版门禁 | 自动跑压测，通过率低于阈值自动阻断 |

## 可迁移

- 做 Agent / RL 环境与评测 harness 时同样适用：先枚举极端输入维度、建成固定回归集、设门禁阈值，比上线后救火便宜得多。
- 面试被问「模型上线前做什么测试」时，可按六维度 + 三种超长策略 + CI 门禁的结构作答。
