2一句话总结

Jamba 把 Mamba（省内存）、注意力（精确检索）、MoE（扩容量）三种积木按 7:1 比例交替堆叠，让 25 万字级上下文的 KV 缓存从上百 GB 压到几 GB，单张 80GB 显卡即可跑。

3核心

  1. 问题/背景：纯注意力模型每读一个新 token 都要缓存全部历史的键值，KV cache 随上下文线性膨胀，超长文本下单卡显存根本装不下；而纯状态空间模型（Mamba）只维护固定大小状态、极省内存，却在精确检索细节上弱于注意力。一个强而贵、一个省而弱。
  2. 机制/方法：三种积木各管一件事——Mamba 层负责线性、低成本地承载长程信息；注意力层负责精确回看检索，但只少量布置；MoE 层负责在几乎不增加计算量的前提下扩大模型容量。堆叠规律：每 8 层只放 1 层注意力、其余 7 层为 Mamba；每隔一层配一组 MoE。
  3. 关键证据或数字：处理 20 多万字上下文时，纯注意力模型的 KV 缓存需上百 GB，混合架构只要几 GB，约省 8 倍，并顺带换来数倍吞吐提升。
  4. 结论/判断：省内存的根本原因在记法不同——Mamba 层状态大小与序列长度无关，注意力层才需要逐 token 缓存；把会膨胀的层压到极少数，整体缓存自然小下来。

5可迁移

  • 长上下文系统的显存估算：先分清哪些层产生随长度增长的缓存，再谈优化；混合架构是「让大部分层不产生 KV cache」的结构化解法。
  • 面试讲混合架构时可按「谁省、谁准、谁扩容量」的分工框架组织，再落到 7:1 配比与激活参数量两个数字。

6疑问 / 下一步
