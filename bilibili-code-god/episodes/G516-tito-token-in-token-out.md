## 一句话总结

多轮 Agent RL 里每轮把文本重新分词，会让梯度打在模型从没采样过的 token 序列上——这是 token 级的 off-policy，重要性采样修不了，只能用 TITO 从源头保证「训练看到的 token 就是采样出的 token」。

## 核心

### 1. 问题/背景

模型只认 token 编号：一句话先被 tokenizer 切成 token 序列，模型输出的也是 token，最后再拼回文字。关键的不对称是：编码是确定的（总选最长匹配那一种切法），但解码是多对一的——同一个字符串可以由多种 token 序列拼出来，拼回去文字完全一样。单轮 RL 没有这个问题：推理引擎采样出一串 token，训练引擎就在同一串 token 上算概率、算梯度，两边看到的是同一个东西。

### 2. 机制/方法

多轮 Agent 的循环多了一道「文本往返」：模型生成 token → 解码成文本 → 解析出工具调用 → 工具结果拼进消息列表 → 聊天模板把整段对话重新渲染 → 重新分词 → 送进下一轮，也送进训练。只要中间任何一步的切分和原来不同，训练看到的序列就不再是模型采样的那一串。具体有四种漂移：

- **解码再编码**：模型采样时的切分（例如把一个词切成两段）与重新编码时的规范切分不同，文字一样、token 完全不同。
- **模板重渲染有损**：模型输出的紧凑 JSON 工具调用被解析成结构体再渲染回去，多了空格，token 就变了。
- **思考内容被删**：某些推理模型的模板会在最后一条用户消息之前删掉此前的思考内容，Agent 注入工具结果或用户消息后，模型刚采样出的推理 token 被抹掉。
- **特殊 token 复用**：同一个特殊 token 既当结束符又当下一条消息的起始符，角色一换，边界 token 就错位。

为什么重要性采样修不了：它修的是「同一串 token，训练引擎与推理引擎算出的概率略有差别」，用概率比去校正。而这里是 token 本身对不上——训练引擎在给一串模型从没采样过的序列算概率，这个概率比没有任何意义。这是 token 级的 off-policy，无法事后修正，只能从源头避免。

解法 TITO（Token-In Token-Out）三条纪律：

1. 维护一个 token 缓冲区作为唯一真源，消息列表只用来做路由，永远不重新编码已经解码过的 token。
2. 工具结果用增量拼接：先渲染不含工具结果的前缀，再渲染含结果的完整版，两者的差值就是新增 token，直接追加。
3. 聊天模板必须满足前缀保留性：加一条消息之后，前面的 token 不能变。

基础设施已跟上：vLLM 0.10.2 起，OpenAI 兼容接口加 `return_token_ids` 参数即可拿到原始 token；请求推理引擎时打开该开关，响应的 `prompt_token_ids` 与 `token_ids` 直接供训练使用；拼接工具结果时不用 `apply_chat_template` 整段重来，而是前缀与完整版各渲染一次、取差值追加。已有训练框架把这套做成默认并带校验器（特殊 token 逐个对齐、普通文本段落解码后再比较）。

### 3. 关键证据或数字

后果直接体现在曲线上：用重新编码的文本训练，奖励曲线上下抖动、loss 偶尔尖峰，且代码一行不报错；直接用推理引擎返回的 token 训练，曲线稳稳上升（vLLM 博客的对比图）。前缀保留性方面，Hugging Face 实测 19 个开源模型，18 个直接通过，只有 Qwen3 需要改一行模板。

### 4. 结论/判断

重新分词漂移是多轮 Agent RL 的隐形炸弹：症状（曲线抖动）离根因（token 对不上）很远，又不抛任何错误。排查训推一致性时，顺序应该是先确认 token 对不对得上，再谈概率比修不修得正。

## 可迁移

- 做多轮 Agent RL 框架时，把「采样 token 序列」当作贯穿 rollout 与训练的唯一真源：工具结果走差值拼接、模板先验前缀保留性，别让任何一轮出现「文本 → 重新分词」的往返。
- 面试被问 Agent RL 的训推一致性：先答 token 级对齐（TITO 三条纪律），再答概率级修正（重要性采样只处理同序列的概率差）——两者不在一个层面。
