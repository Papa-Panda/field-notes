2一句话总结

监督学习给标准答案、RL 只给分数，这是两者最根本的区别；由此衍生出奖励延迟与 on-policy 数据分布两个反复出现的坑。

3核心

  1. 问题/背景：系列开篇，用「教小孩骑车」的类比说明为什么 RL 问题没法用标准答案监督——你只能对每次尝试给反馈，学习者靠试错自己摸索。
  2. 机制/方法：形式化为几个符号：状态 $S$ 、动作 $A$ 、奖励 $R$ （环境给的分）、转移规律 $P$ （这么做会到哪），外加折扣因子 $\gamma$ （下期展开）。两个结构性难点：一是分数来得晚，一局棋输了不知道错在哪一步（信用分配）；二是数据由策略自己走出来，走法一变、看到的世界就变（分布随策略漂移）。
  3. 关键证据或数字：映射到大模型上环境极简：一句提问、模型答一段、Reward Model 给个分，一局结束；InstructGPT 论文把这称为老虎机（bandit）式环境——单步、无状态转移。
  4. 结论/判断：理解 RL 先抓住「只有分数没有答案」这一条，其余难点（延迟奖励、数据自产）都是它的推论。

4可迁移

  • 面试开场白模板：先讲 bandit 式简化（LLM 场景），再讲一般 MDP 的两个坑，比直接背定义更显理解。
  • 做 RL infra 时记住数据是策略自产的：rollout 与训练的版本一致性（陈旧度）问题根源就在这里。

5疑问 / 下一步
