## 一句话总结

温度、Top-K、Top-P 动的是同一条概率分布：温度在 softmax 前调悬殊，Top-K 按个数截断，Top-P 按概率总量自适应截断，顺序是先 K 后 P 最后采样。

## 核心

1. **问题/背景**：同一个问题问模型两次答案不一样，随机性来自哪里？答案在每一步输出的流水线上：模型先吐出一串叫 logits 的原始分数，过温度、softmax、两道截断闸门，最后掷骰子采样出下一个词。三个参数分别站在这条流水线的不同位置。

2. **机制/方法**：
- **温度 T** 站在最前面：每个 logit 先除以 $T$ 再进 softmax。 $T < 1$ 时差距被放大、分布变尖，高概率词更一枝独秀； $T > 1$ 时差距被压缩、分布变平，低概率词也有机会。关键是温度永远不改变词的排序，只改变悬殊程度； $T$ 趋近于 0 时采样退化为永远选第一名，即贪心解码。
- **Top-K** 是第一道闸门：只保留概率最高的 $K$ 个词，其余丢弃后在剩下的里面重新归一化采样。毛病是 $K$ 是个死数字——分布平的时候，一堆合理候选被一刀切掉太狠；分布尖的时候，又硬塞进几个几乎不可能的词。
- **Top-P**（核采样）改看概率总量：词按概率从高到低累加，加到累计概率超过阈值（如 0.9）就划线，后面的全不要。候选集大小随分布形状自适应伸缩——分布尖时一两个词就凑够，分布平时自动放宽。这正是它取代 Top-K 成为当今默认采样方式的原因。

3. **关键证据或数字**：常见工程组合是温度配合 Top-P 约 0.9 微调，一般不建议两个同时大动，容易互相打架；事实类、写代码用低温甚至贪心求准稳，创意发散才调高温度。一个面试冷知识：即便温度设为 0 ，同一 prompt 也未必每次一字不差——浮点规约顺序、并发批处理等系统因素也会带来微小抖动。

4. **结论/判断**：一句话区分三者：温度管胖瘦（悬殊），K 管个数，P 管概率总量；理解流水线顺序（温度 → softmax → K → P → 采样）比背参数表重要。

## 可迁移

- 调推理参数先定位问题出在哪一站：输出太发散先降温度或收紧 Top-P，输出太单调重复则相反；不要同时大改温度和 Top-P，否则效果互相纠缠难以归因。
- 面试回答可加分项：主动指出温度不改排序、以及温度为 0 也不保证完全确定性（系统层浮点与批处理抖动），显示理解到了实现层。
