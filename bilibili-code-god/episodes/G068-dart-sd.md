## 一句话总结

多轮工具调用的真实结构是「菱形」而非线性链：DART-SD 先建交互状态图定位学生第一次走出有效区域的断点，只在断点之后的恢复步骤上算 loss，从而不惩罚同样有效的替代探索顺序。

## 核心

1. **问题/背景**：同一任务里两个独立子任务（如查天气、查余票）谁先谁后都对，但全轨迹 SFT 按教师的单一顺序逐 token 计算 loss，会把学生走另一条有效边的探索当成错误惩罚掉；标准 RL 又只给整条轨迹一个奖励，分不清是哪一步出的问题，信用分配粗糙。
2. **机制/方法**：DART-SD 把状态定义为「已获得的信息原子集合 + 自上个主节点以来的无用操作次数」，工具返回值按语义等价类折叠（报错、空返回不算新信息）；获得新信息的步骤是主节点，只转圈的是辅助节点，独立子任务因此汇合到同一节点形成菱形。训练时先由教师轨迹建图、标出成功可达区域，再把学生的失败轨迹逐步投影到图上，第一次无法投影的步骤即关键拓扑断点（CTB），其前一个可恢复位置为恢复锚点；随后做局部自蒸馏：以断点前的学生前缀加图上检索的特权参考为条件，生成断点后的修复步骤，loss mask 只覆盖断点之后、最终答案之前的 assistant token，学生前缀、用户消息、工具返回权重全为零。
3. **关键证据或数字**：Qwen3-8B 域内 FTRL soft F1 从基座 23.48、SFT 41.89、GRPO 40.22 提升到 45.66；域外 BFCL 多轮 57.38 对 SFT 的 48.81，ToolHop 45.66 对 GRPO 的 37.66；平均工具调用次数随迭代从 4.23 降到 3.55，低于黄金参考的 4.02；断点平均位置从 0.348 推后到 1.452，说明学生越来越晚才走出有效区域。
4. **结论/判断**：在多轮工具调用里，「只修错的那一步之后」比整轨 SFT 或整轨奖励都更对路；前提是需要先由教师轨迹建图、原子划分依赖一条成功 rollout，且默认不含 thinking 模式。

## 可迁移

- 做多轮 Agent 的 SFT/RL 数据时，先想清楚哪些步骤顺序可交换：对顺序等价的轨迹做全量 SFT 会系统性压制有效探索，面试里这是「拓扑坍塌 + 信用分配短视」的典型案例。
- loss mask 的设计原则可迁移到任何带恢复段的训练：只给需要纠正的片段梯度，前缀与环境返回一律零权重。
