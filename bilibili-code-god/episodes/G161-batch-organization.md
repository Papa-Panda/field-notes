## 一句话总结

RL 的 batch 不是随机抽样的数据集，而是要按难度配比、类型平衡和 rollout 数量精心组织的题库——组内没有质量差异，就没有梯度信号。

## 核心

1. **问题/背景**：RL batch 与 SFT batch 本质不同。每个 prompt 要生成多个 rollout、打分算 reward，同 prompt 的 rollout 构成一个 group；GRPO 的 advantage 靠组内归一化，组内回答质量无差异时信号直接消失。所以 batch 怎么组织，直接决定信号质量。
2. **机制/方法**：
   - **难度分布**：全是简单题模型全对、全是难题全错，两种情况都没有区分度。推荐配比为简单 30%、中等 50%、难 20%，中等题提供的学习信号最多。
   - **难度筛选**：训练前先用当前模型对题库全量推理、按正确率分级；训练中持续评估、动态调整配比。
   - **类型平衡**：数学、代码、推理等多类题不能让某一类主导；维护多个 prompt 池，按均匀采样或目标能力配比抽取，防止模型偏科退化。
   - **rollout 数量**：太少则组内统计不稳定，太多则算力浪费、收益递减；可按难度自适应——简单题少采、难题多采。
3. **关键证据或数字**：难度配比 3:5:2（简:中:难）；GRPO 原论文 rollout 取 8–16，经验区间 4–16。
4. **结论/判断**：训练中要盯住 reward 方差，方差塌掉的 batch 等于没有梯度，应当直接丢弃并回头调整题库配比。

## 关键数字

| 项 | 取值 |
| --- | --- |
| 难度配比（简/中/难） | 30% / 50% / 20% |
| 每 prompt 的 rollout 数 | 经验 4–16（GRPO 论文 8–16） |

## 可迁移

- 做 GRPO/RLVR 训练前，先给题库跑一遍基线正确率分级，这是零成本的信号质量保险。
- 面试被问「RL 数据怎么组织」时，按难度、类型、rollout 数、动态调整四点展开，比只谈数据清洗更切中要害。

## 疑问 / 下一步

- 难度分级依赖基线模型正确率，训练中模型变强后分级会漂移——动态重评估的频率与成本如何权衡，视频未展开。
