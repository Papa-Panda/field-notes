## 一句话总结

一次乘加算 2 次浮点运算，由此每 token 前向约 $2N$ 、反向约 $4N$ ，乘上 token 总量 $D$ 就是估算训练算力的 $6ND$ 。

## 核心

### 1. 问题/背景

训练一个大模型要烧多少算力、花多少钱，不用翻财报：圈内靠一个乘法当场估出来，前提是把计数单位先定清楚。

### 2. 机制/方法

算力按浮点运算次数计。神经网络最核心的动作是乘加（乘一次再加一次），正好 2 次浮点运算。一个 token 流过模型要与每个权重各做一次乘加，所以 $N$ 参数模型处理一个 token 的前向约为 $2N$ 。反向更贵：既要算误差对输入的梯度（把信号继续往前传），又要算对权重的梯度（更新参数），两笔账各约 $2N$ ，合计约 $4N$ 。前向加反向，每 token 共 $6N$ ；再乘训练 token 总量 $D$ ，得总算力公式：

$$C \approx 6ND$$

### 3. 关键证据或数字

以 GPT-3 代入：$N = 175$ B ， $D \approx 300$ B token ，总算力约 $3 \times 10^{23}$ FLOPs——单卡要连轴转几十年，堆上千卡也要大半个月，电费加卡费轻松百万美元级。两个进阶点：MoE 的 $N$ 必须用每 token 的激活参数而非总参数，否则严重高估；算力固定时参数与数据要平衡，Chinchilla 结论是数据量约取参数量的 20 倍最划算。

### 4. 结论/判断

$6ND$ 把一次训练的算力估得八九不离十，是做容量规划和成本估算的第一性公式；用之前先确认 $N$ 是激活参数、$D$ 与 $N$ 的配比是否合理。

## 关键数字

| 量 | 值 |
| --- | --- |
| 一次乘加 | 2 FLOPs |
| 每 token 前向 | $\approx 2N$ |
| 每 token 反向 | $\approx 4N$ |
| GPT-3 总算力（175B × 300B token） | $\approx 3 \times 10^{23}$ FLOPs |
| Chinchilla 最优配比 | $D \approx 20N$ |

## 可迁移

- RL 训练成本估算可直接借这套账：rollout 是纯前向（约 $2N$ /token），训练步再叠反向，先用 $6ND$ 量级判断预算是否现实。
- 面试手推 $6ND$ 时记得补 MoE 用激活参数这一句，是最常见的追问点。
