## 一句话总结

Agent RL 的环境饱和本质是组内奖励没了差异、梯度归零；EnvHarness 不加新任务，而是在环境外包一层可插拔组件，按策略的失败模式改初始状态、交互规则或串联长回合，再用自动闭环决定保留哪个组件。

## 核心

1. **问题/背景**：GRPO 类算法靠同一任务多条轨迹之间的奖励差异产生梯度。训练推进后，简单任务全对、难任务全错，组内无差异即零梯度——这就是环境饱和。继续合成新任务治不了它：一是任务静态、策略动态，今天造的难题明天又被学会；二是大量失败其实源于策略自身的坏习惯（重复动作、读不完长观察、误读工具约束），与题目内容无关。
2. **机制/方法**：EnvHarness 不动环境核心逻辑，在外面包三类可插拔组件：
- **Stage**：改初始状态。Agent 进场前先回放一串动作（如把杯子收进抽屉），迫使它学搜索而不是走捷径。
- **Contract**：改交互规则。用三个变换函数分别约束动作空间、状态转移与观察，例如没拿杯子就禁用清洗动作、把观察压缩成两句、去掉传送类指令制造部分可观测，逼它按规矩逐步走。
- **Chain**：把多个环境串成一个长回合，考它能否记住最初目标。
组件由名为 Envrior 的自动回路挑选：先跑一批轨迹观察，再诊断失败根因（死循环、长观察解析失败、误读约束，或已达 100% 需加难），据此合成组件，最后验证——只有让任务变难但仍可解的组件才被接受；太简单或改成无解（成功率 0 与 1 同样无梯度）都会被拒绝或带反馈返修。
3. **关键证据或数字**：五个基准全涨（见下表）；环境规模扩到 300 个时，原始环境与 SWE-smith 都已平台化，EnvHarness 仍在上升；消融显示三类组件各有取舍（Chain 步数最省、Stage+Contract 成功率更高、三者合用兼得）；换不同基座模型仍普涨；接入真实 RL 训练后 ALFWorld、WebShop 均优于基线。
4. **结论/判断**：饱和的解药不是更大的题库，而是会随策略弱点变化的环境动态。作者把好环境比作盯着弱点出题的教练，而非静态题库。

## 可迁移

- **RL 环境设计**：给环境留可重置的 gym 接口并把「难度变换」做成可插拔层，是让 RL 课程自动跟随策略水平的前提；诊断—合成—验证的闭环可以复用到自建 agent 环境的难度调度上。
- **面试/排障**：遇到 RL 成功率平台期，先查组内奖励方差是否塌掉，再区分是题目太易/太难还是策略行为缺陷——三者的解法完全不同。
