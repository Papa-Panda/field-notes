## 一句话总结

长程 Agent 的上下文压缩摘要不是预处理步骤而是一个影响成败的决策：CompactionRL 把摘要 token 一并纳入 RL 损失，用 token 级归一化和跨段折扣处理「一条轨迹被压缩切成多段」的记账问题，GLM-4.5-Air 在 SWE-bench Verified 上从 59.8 涨到 66.8。

## 核心

1. **问题/背景**：上百轮的 Agent 任务里上下文几十轮就塞满 64K 窗口，工程做法是空间低于阈值时触发压缩：模型自写摘要，再用「系统提示 + 摘要 + 最近两步原文」重拼上下文继续。但写摘要的能力从未被训练过，摘要写坏则后续步骤全程信息缺失；实验证明执行 Agent 不动、只换摘要模型，准确率就从 49.0 变到 55.5。
2. **机制/方法**：把摘要生成当作策略的一部分进 RL，处理两个记账坑：其一是 loss 平均——若按段平均，压缩三次（四段）的轨迹权重是压缩一次的两倍，但两者任务奖励相同，故改用 token 级归一化，全部 assistant token（含摘要 token）一视同仁；其二是折扣——每段的优势还要乘上跨段折扣（与该段之后生成的 token 数相关），使每个 token 的折扣等于它到最终结果的真实距离。
3. **关键证据或数字**：GLM-4.5-Air 在 SWE-bench Verified 上从 59.8 涨到 66.8；消融显示去掉 token 级归一化掉到 60.0，去掉跨段折扣掉到 63.0；对照组「做 RL 但不训练压缩」反而掉到 48.0，把窗口拉到 128K 不压缩也只有 52.5。训后摘要反而越写越长、越详细，但压缩次数更少。ECHO 则补上信用溯源：压缩切断了「最后答对该归功于哪一轮搜索」的链路，它给每个回合留带元索引的记忆记录，压缩时由策略自选最多 S 条历史记忆加最近 K 轮，学习时只沿被选中的证据回合与挑选动作回传正信用（负信用不传），在 BrowseComp 类任务上 GRPO 28.9、摘要式基线 36.1、ECHO 43.4，回合数从 62.5 降到 45.3。
4. **结论/判断**：压缩是模型必须学会的一种行动而非省 token 的技巧；只要轨迹被切段，归一化口径和折扣对齐就是 RL 正确性的前提。

## 可迁移

- 任何「轨迹被切成多段再拼接」的训练（压缩、多轮拼接、续写）都要检查 loss 归一化口径：按段平均会按段数放大权重，这是 RL infra 里隐蔽的系统性偏差。
- 面试可迁移的判断：上下文管理组件（摘要器、记忆检索）只要影响最终成败，就应视为策略的一部分参与训练，而不是冻结的预处理。

## 疑问 / 下一步

- 跨段折扣的具体形式（指数底数如何与段后 token 数挂钩）值得对照原论文公式核对，摘要里只给了定性描述。
