## 一句话总结

Agent 的「收手」是多轮顺序决策而非一次性判断；实测主流模型及时收手率大多不到 30% 且不随规模改善，但一份从轨迹里总结出的行动手册不用训练就能大幅补上这块短板。

## 核心

1. **问题/背景**：给 Agent 派一个根本不存在的商品去买，它不会说买不到，而是换关键词一轮轮搜下去、死不收手。传统 LLM 的弃权是一次性的（答或不答当场二选一），但 Agent 每一步都面临三选一：直接回答、就此收手、或继续行动多搜集信息；而任务到底可不可行，往往要交互好几步才暴露，所以收手是一连串顺序决策。

2. **机制/方法**：论文用 28000 个任务实测 8 个主流模型在不可行任务上的收手表现，并提出免训练的补救方法 CONVOLVE：先让 Agent 跑 20 条任务，再让一个反思型 Agent 回看这些完整轨迹，把「什么情况下该收手」的信号总结成一份结构化行动手册，直接贴进上下文即可。

3. **关键证据或数字**：
- 面对注定做不成的任务，能第一时间果断收手的比例大多不到 30% ，最强的模型也只有 26.7% 。
- 参数从 8B 一路扩到 235B（近 30 倍），及时收手能力几乎纹丝不动——会不会收手与模型大小基本无关。
- 贴上行动手册后，即时收手率从 26.7% 跳到 57.4% ，十步内最终收手率从 83.2% 拉到 100% ；而且 8B 小模型总结的规则原样给 70B 大模型照样管用，收手经验可以跨模型通用。
- 不可行任务分两类：一类是要求本身不成立（假前提、信息不全、无标准答案的主观问题），相对好认；另一类是听起来合理、交互半天才发现环境里根本没有目标物（商品不存在、依赖装不上），最难。意图模糊的任务还会被模型的坏习惯坑：先假设一个最可能的意思一条道走到黑。
- 两个易忽略的点：其一，同一模型换一套脚手架（框架），收手行为能差出一大截，框架比模型更影响收手；其二，收手不是越多越好，长交互里有的模型矫枉过正、把能做成的任务也提前放弃，过度弃权率一度冲到 34% 。

4. **结论/判断**：会干活的 Agent 满地都是，稀缺的是知道何时停手的判断力；而且这份判断力可以靠轨迹复盘 + 上下文手册低成本注入，不必等模型变大。

## 关键数字

| 指标 | 基线 | 改进后 |
|---|---|---|

| 参数规模 8B → 235B 对收手的影响 | — | 几乎无改善 |

## 可迁移

- 做 Agent 系统时把「终止判断」当一等公民设计：每轮显式评估任务是否还可行，而不是只靠最大步数兜底；框架层的收手逻辑收益可能比换更大模型还大。
- CONVOLVE 式做法可直接迁移到自己的 Agent 流水线：定期让反思模型回看失败轨迹、沉淀成结构化手册回注上下文，是零训练成本的经验复用方式。
