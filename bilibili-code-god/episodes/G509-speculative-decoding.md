## 一句话总结

自回归解码的瓶颈是显存带宽而非算力，于是让小模型先起草、大模型一次并行验证，再用接受-拒绝采样保证输出分布与大模型单独采样分毫不差。

## 核心

1. **问题/背景**：大模型自回归生成，一次前向只能吐一个字，要五个字就排队跑五次；这五次里 GPU 算力大量闲置，真正卡住的是把几百亿参数从显存搬进搬出的带宽。由此得到关键事实：算一个字和一次并行算五个字，耗时几乎一样——这就是提速的突破口。
2. **机制/方法**：第一步，草稿模型自回归地抢答接下来的 $K$ 个字，反正它便宜；第二步，把这 $K$ 个字一次性塞给大模型、一次前向并行验证，全对就等于用一次前向的代价白赚 $K$ 个字，运气好还能顺手多送一个。贪心解码直接比对即可，但真实采样下两个模型分布不同，要靠接受-拒绝采样：草稿按自己的分布 $p$ 采出一个字，再掷一个 0 到 1 的随机数，小于 $q/p$ 就接受（ $q$ 是大模型概率）；一旦某字被拒，丢掉它及后面所有草稿，从修正分布重采一个字。
3. **关键证据或数字**：例子里某个字草稿给了 0.8 的概率、大模型只给 0.3，接受概率只有 $0.3/0.8 = 0.375$ ，大概率被拒、后面草稿全部作废。为什么重采必须用修正分布：接受这一步只稳稳拿到了两条分布曲线较低的那部分，即 $\min(p, q)$ ；而 $q$ 高出 $p$ 的那部分还没补上，正好就是 $(q - p)$ 的正部——拒绝后从它重采，两块拼起来恰好等于 $q$ ，最终分布精确无损。
4. **结论/判断**：推测解码是无损加速：输出分布和只用大模型采样一模一样，端到端却能快两到三倍。实践极简，vLLM 已内置——目标模型之外挂一个草稿模型、设好每次猜几个 token 的 $K$ 即可开箱即用。

## 关键数字

| 项 | 数值 |
|---|---|
| 示例接受概率（ $p=0.8$ ， $q=0.3$ ） | 0.375 |
| 端到端加速 | 约 2–3 倍 |
| 输出分布偏差 | 0（严格无损） |

## 可迁移

- 推理优化面试里，先讲清「瓶颈是带宽不是算力」再讲草稿-验证，比直接背流程高一个层次；这也是 batching、量化等优化共同的出发点。
- RL rollout 阶段同样受解码带宽制约，推测解码可与 rollout 引擎组合，但草稿模型的接受率随策略更新而漂移，需要纳入监控。

## 疑问 / 下一步

- 草稿与目标分布越接近接受率越高，实际工程中 $K$ 取多大、草稿模型选多小最划算，取决于 workload，需要实测调参。
