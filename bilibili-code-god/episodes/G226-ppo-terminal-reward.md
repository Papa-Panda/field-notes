## 一句话总结

PPO 的逐 token 奖励由两笔账组成：每生成一个 token 就按该步与参考策略的 KL 散度扣一笔小钱，只有最后一个 token 才一次性加上奖励模型的整段得分——所以中间 token 奖励恒为负、终局才转正。

## 核心

1. **问题/背景**：奖励模型只能对完整回答给一个总分，没法逐 token 打分；同时又要防止策略为了刷分偏离 SFT 模型太远，需要一种把"整段奖金"和"逐 步约束"拼在一起的记账方式。
2. **机制/方法**：总奖励定义为 RM 得分减去 ， $\beta$ ， 乘以与参考策略（冻结的 SFT 模型）的 KL 散度，并按 token 拆开：中间每个 token 的奖励只有 KL 扣款一项，即 ， $-\beta \cdot \mathrm{KL}_t$ ， ；最后一个 token 的奖励是 KL 扣款再加上 RM 的整段得分。$\beta$ 是"严苛系数"旋钮：调小则扣款轻、探索大但易钻空子练歪，调大则被死死按在参考策略附近、稳定但奖励上不去。
3. **关键证据或数字**：手算示例取 ， $\beta = 0.5$ ， ，5 个 token 的 KL 依次为 0.15、0.3、0.1、0.3、0.2，前五步累计扣款 0.525；最后一步 KL 为 0.25、RM 给分 2.2，该步奖励变为 +2.075，全程总收益 1.55——扣款很碎、奖金很集中。
4. **结论/判断**：记住"终端发奖金、每步扣偏离"这个账本结构，就理解了 PPO 奖励的核心；它也解释了为什么逐 token KL 惩罚形状会直接影响生成长度与探索行为。

## 关键数字

| 项 | 示例值 |
|---|---|
| $\beta$（KL 系数） | 0.5 |
| 前 5 个 token 的 KL | 0.15 / 0.3 / 0.1 / 0.3 / 0.2 |
| 前五步累计扣款 | −0.525 |
| 末 token 奖励（KL 0.25 + RM 2.2） | +2.075 |
| 全程总收益 | 1.55 |

## 可迁移

- 这套记账方式是理解 credit assignment 难点的入口：终局稀疏奖励 + 逐 token KL 是 PPO 的默认形态，GRPO 等后续方法只是换了优势估计，奖励塑形骨架不变。
- 调 RLHF 时若出现回答变短/变长，先查 KL 惩罚与 $\beta$ ：逐 token 扣款天然对长回答不利，是长度异常的常见根因。

## 疑问 / 下一步

- 把 RM 得分只放在末 token 会让长回答的早期 token 信用分配极弱，这正是过程奖励（PRM）想解决的问题，可与结果奖励做一组对照实验。
