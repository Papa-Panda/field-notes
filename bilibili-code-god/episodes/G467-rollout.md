## 一句话总结

Rollout 是 RL 训练的「做题」环节——用当前模型批量生成样本并打包成经验数据；因生成是自回归的，它吃掉训练约六七成时间，是头号瓶颈。

## 核心

1. **问题/背景**：RL 训练不能凭空更新参数，必须先让当前策略实际生成一批轨迹、拿到奖励，才有可学的材料；没有 rollout，PPO/GRPO 就是无米之炊。
2. **机制/方法**：一次完整 rollout 分四步：① 环境初始化，从训练数据抽一批 prompt 喂给策略模型；② 动作生成，逐 token 生成完整回答，并同步记录每个 token 在当前策略下的 log prob，上下文 + 动作构成一条轨迹；③ 计算奖励，奖励模型对「prompt + 回答」整段打分；④ 数据收集，把序列、旧 log prob、KL 惩罚、奖励打包塞进经验缓冲区。
3. **关键证据或数字**：生成时记录旧 log prob 是为重要性采样留分母：等训练更新几步后策略已变，用新旧概率比给旧数据的梯度加权校正，旧数据才能安全复用。耗时上，实测 rollout 生成约占整个 RL 训练的 60%–70% ；且回答长短不一，短的先生成完只能等最长的那条，GPU 大量空转。
4. **结论/判断**：rollout 慢的根源是自回归逐 token 生成，而训练侧一次前向 + 反向反而快；工程解法是上 vLLM / SGLang 这类推理引擎做批量并行生成与前缀缓存共享，把这块最贵的时间压下去。

## 关键数字

| 项 | 值 |
| --- | --- |
| Rollout 占 RL 训练总时长 | 约 60%–70% |
| Rollout 四步 | 抽 prompt → 逐 token 生成记 log prob → 奖励打分 → 打包入缓冲区 |

## 可迁移

- RL infra 的第一性判断：优化 RL 训练吞吐先看 rollout 侧（生成引擎、长尾对齐、批调度），而不是先抠训练侧的算子。
- 长短回答混批时，长尾决定整批延迟——按长度分桶、动态批处理、截断策略都是直接作用于这 60%–70% 的杠杆。
