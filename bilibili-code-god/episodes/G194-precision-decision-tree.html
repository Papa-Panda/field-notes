2一句话总结

三种格式的取舍只看位数怎么分：指数位决定动态范围、尾数位决定精度——BF16 用精度换范围，是大模型训练的默认；FP16 精度高但必须配 loss scaling；FP8 再快也要 H100 与 Transformer Engine 才玩得转。

3核心

  1. 问题/背景：混合精度选型表面看是工程偏好，根子在浮点格式的位数分配。FP16 是 5 位指数 + 10 位尾数：精度高但范围小、容易溢出。BF16 是 8 位指数 + 7 位尾数：动态范围与 FP32 一样大，精度略低。FP8 只有 3–4 位有效精度，但算力可翻倍。
  2. 机制/方法：按格式给场景。FP16 适合不支持 BF16 的老硬件（如 V100），以及需要较高精度的任务（如 RL 训练），但必须配合 loss scaling 防梯度下溢，且 scaling 本身要调参——过大上溢、过小下溢。BF16 在 A100/H100 上原生支持，范围大、不需要 loss scaling，精度损失对大模型训练可忽略，是 GPT、LLaMA、Qwen 等主流模型的默认选择。FP8 需要 H100/H200 与 Transformer Engine，前向用 E4M3、反向用 E5M2 的分层配置，速度比 BF16 快约 1.5–2 倍，适合大规模预训练追极致吞吐；微调与 RL 不建议用，精度不够。
  3. 关键证据或数字：决策树收敛成三句：硬件支持 BF16 就用 BF16（最简单最稳定）；只能 FP16 就加 loss scaling；有 H100 且追极速才上 FP8。资源受限时还可以用 INT8 量化做微调。
  4. 结论/判断：BF16 用精度换范围这笔交易在大模型训练里几乎总是划算的——训练的瓶颈是数值稳定性（别溢出、别下溢），不是最后一位尾数。

4关键数字

格式 指数/尾数位 关键代价 定位
FP16 5 / 10 必须配 loss scaling 老硬件、精度敏感（如 RL）
BF16 8 / 7 精度略低 大模型训练默认
FP8 约 4 / 3 需 H100 + Transformer Engine 大规模预训练，约 1.5–2 倍于 BF16

5可迁移

  • 面试答「为什么大模型训练用 BF16 不用 FP16」直接落到位数：梯度量级跨度大，范围比精度重要；FP16 的下溢要靠 loss scaling 打补丁，BF16 从格式上免了这一层复杂度。
  • 给训练框架定精度策略时按阶段分：预训练可激进（FP8 试点）、RL 与微调保守（BF16/FP16），别全流程一把梭。
