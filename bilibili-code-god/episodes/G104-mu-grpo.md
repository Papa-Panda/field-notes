## 一句话总结

标准 GRPO 每轮只更新几步是过度保守：μ-GRPO 把训练切成 4 个大阶段、每阶段在冻结策略生成的数据上连做 1024 次更新（陈旧度为标准的 250 倍），靠 clip 放宽到 $[0, 5]$ 加负优势否决稳住，精度持平或更好，rollout 时间平均缩短 1.82 倍。

## 核心

1. **问题/背景**：陈旧度 $\mu$ 指一批 rollout 数据被用多少步更新。标准 GRPO 取 $\mu = 4$ ，理由是 PPO 的 clip 理论认为数据太旧、重要性比离 1 太远，clip 掉的 token 越来越多、梯度就没了。代价是 rollout 太频繁——RL 训练 60%–70% 的时间花在生成上，训练器在等。
2. **机制/方法**：μ-GRPO 把 4096 次更新切成 4 个大阶段：每阶段先冻结当前策略、一口气生成整个阶段要用的 rollout，再在这批数据上连续优化 1024 步。生成与优化各自成批后切换开销消失，还能流水化，训练器空转从 24.2% 压到 0.6%。稳住陈旧数据靠两招：一是放宽 clip，重要性比的界从标准的 $[0.8, 1.2]$ 放宽到 $[0, 5]$ ，保住陈旧数据里仍带信息的梯度；二是负优势否决（NAV）——对优势为负的序列，只要有任一 token 的重要性比低于 $10^{-4}$ ，整条序列 mask 掉，因为比率极低说明当前策略几乎不可能生成这个前缀，在不可能的前缀上惩罚后缀是有害的 off-support 更新。正优势序列不否决，两招必须一起用。
3. **关键证据或数字**：在 Llama-3 2B Instruct、Qwen2.5-Math-7B、Qwen3-Base 1.7B/8B、DeepSeek-7B 上测 AIME、MATH-500、LiveCodeBench 等基准，5 个模型 4 个持平或更好（DeepSeek-7B 68.6 对标准 GRPO 66.1，Qwen2.5-Math-7B 48.0 对 47.3）。效率上 rollout 生成时间平均缩短 1.82 倍、总训练时间 1.53 倍，DeepSeek-7B 强中提速 2.2 倍、代码任务上 Qwen2.5-Coder-7B 2.16 倍；异步执行下精度 47.7% 不变、训练时间从 22.3 小时降到 17.4 小时。
4. **结论/判断**：陈旧本身不可怕，可怕的是没有诊断与稳定机制；它与「陈旧度大就降学习率」的缩放律路线互补——那边靠降速，这边靠 clip 放宽加否决诊断。

## 关键数字

| 项 | 标准 GRPO | μ-GRPO |
|---|---|---|
| 陈旧度 $\mu$ | 4 | 1024（250 倍） |
| clip 区间 | $[0.8, 1.2]$ | $[0, 5]$ |
| 训练器空转 | 24.2% | 0.6% |
| rollout 生成时间 | 1× | 平均缩短 1.82 倍 |
| DeepSeek-7B 精度 | 66.1 | 68.6 |

## 可迁移

- RL infra 做吞吐优化时，rollout 与训练的批量化/流水化收益可能比抠 kernel 更大；先量训练器空转率再决定优化方向。
- 放宽 clip 必须配负优势否决这类「不可能前缀」过滤，单独放宽会不稳——面试谈 off-policy 稳定性时这是完整的答法。

## 疑问 / 下一步
