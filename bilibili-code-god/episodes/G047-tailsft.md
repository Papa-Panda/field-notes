## 一句话总结

SFT 的交叉熵与「覆盖」（pass@k）不对齐：标准 SFT 为了降 loss 会把概率质量从基座本来会的其他正确写法上搬走，pass@1 涨而 pass@k 掉；后面要接 RL 时，SFT 的 KPI 应该是给 RL 留多少覆盖，而不是 loss 多低。

## 核心

1. **问题/背景**：一道题往往有多种正确写法，SFT 数据里只有一种。标准 SFT 反复强化这一种写法，另外几种本来能采到的正确解概率被压低。玩具实验里三种过滤方法的 pass@8 都显著高于标准 SFT，尽管标准 SFT 的交叉熵和 pass@1 最好——证明 loss 与覆盖是两个目标。
2. **机制/方法**：TailSFT 的规则是按「相对初始策略已经学了多少」过滤：每条序列算当前 loss 减去它在初始策略下的 loss，学得最多的底部一截直接剔除、不进梯度，剩下的做普通 token 平均；开销只是训练前存一次初始 loss。有定理保证：以初始策略为参照的偏移过滤，覆盖不会比标准 SFT 或最优绝对阈值差。直觉是基座本来就会的东西再使劲教，只会把它教窄。SWE-Prime 走数据侧路线：成功轨迹不等于好轨迹（有的不探索就改代码、有的偷看 git 历史、有的补丁范围失控），先按五项质量分（先看仓库再改、改完验证、工具可靠、无重复、无泄漏、补丁范围受控）筛选聚类去冗，再对每个语义段打分、只在高分段上算 loss。
3. **关键证据或数字**：TailSFT 在 RL 之前让 pass@16 在编码基准上最高涨 16.8 分（另有 +8.3 、数学 AIME +3.1 等），8 个数据—基准组合里 15 个改善；接着做 GRPO，pass@1 再涨最高 3.9 分。代价是 RL 前 pass@1 常掉 0.75–2.82 分，属有益取舍；可用「覆盖比」事先预判是否值得做。SWE-Prime 只用约 10% 筛过的成功轨迹（3.2 万条留 1.3 万条），在 SWE-bench Verified 上把 GLM-4.7-Flash 从 41.4 提到 51.4 ，打赢用全部轨迹的版本。
4. **结论/判断**：边界在第三篇：选「模型本来就喜欢」的高自然度数据只对小模型或短训练成立、早期涨得快；大模型长训时低自然度（更难更陌生）的数据会反超。所以数据选择规则随容量与算力预算翻转，不能当普世真理。

## 可迁移

- Post-training 流程设计：SFT 阶段的验收指标从 loss 换成 pass@k 覆盖，尤其是后面要接 RL 的管线；SFT 过训压窄分布会直接吃掉 RL 的探索空间。
- Agent 轨迹数据 curation 可直接借 SWE-Prime 的五项质量分做过滤器，轨迹「成功」只是入场券。
