## 一句话总结

同步买的是稳定、异步买的是吞吐，付的都是梯度新鲜度：大模型预训练 99% 选同步，异步只在异构集群和在线学习场景配延迟限制使用。

## 核心

1. 问题/背景：多卡训练时，同步更新要等所有 GPU 算完梯度做 all-reduce 再统一更新，最慢的卡拖累全局、产生气泡；异步更新每张卡算完立刻更新，没有等待但梯度来自不同版本的参数。
2. 机制/方法：异步的核心病灶是 staleness（陈旧度）——用旧参数算出的梯度更新新参数，更新方向会偏，陈旧度越大收敛越抖，严重时发散。三种缓解：限制最大 staleness、按 staleness 缩小学习率、梯度补偿。
3. 关键证据或数字：约 99% 的大模型训练用同步（含 ZeRO 等数据并行方案），因为梯度精确无偏、训练稳定。
4. 结论/判断：选型看场景——硬件齐整、要求稳定的预训练用同步；卡速差异大的异构/跨机房集群可以走异步但必须加延迟上限并缩放学习率；数据持续到来的在线学习场景异步天然合适，再配梯度补偿。

## 可迁移

- 面试答分布式训练时，把同步/异步的取舍落到 staleness 一个词上：它同时解释异步为什么快、为什么不稳、以及三种补救手段。
- RL 训练里 rollout 与训练的异步化（如异步采样）本质是同一笔交易，评估时先问陈旧度上限是多少。
