2一句话总结

0.8B
token 的高质量数学

决定重复数据是否过拟合的不是重复次数，而是两次见到同一样本的间隔：每条样本都有一个以 token 计的「记忆窗口」，间隔超过窗口后再喂，边际效用和全新数据完全一样——按窗口排期，0.8B token 的高质量数学数据能训到 190 个 epoch 不过拟合。

3核心

  1. 问题/背景：经验规则说数据最多重复约 4 遍，再多就过拟合。这篇工作换了问法：重复的关键变量也许不是次数，而是间隔。
  2. 机制/方法：定义记忆窗口：样本在时刻 ，$T$ ，被训过后，模型对它的 loss 低于未训过时的差值（loss 保留差）会随之后训练的 token 数先升后衰，衰减到零即「忘干净」，这段长度是保留窗口；再定义泛化窗口（下游表现达峰而未过拟合的跨度），记忆窗口取两者较小值。用回滚协议测量：比较相隔不同 token 量的两个检查点对同一样本的 loss 曲线形状。100M 模型上窗口约 1–5B token，保留差在约 0.15 倍训练量处达峰后迅速衰减。
  3. 关键证据或数字：当重复间隔远大于窗口时，验证 loss 的下降速率与一直喂全新数据的曲线完全一致——被忘掉的 token 再喂一遍，边际效用完全恢复而非递减；间隔小于窗口时模型还记着样本，只是在背 loss，验证集开始上翘，这才是过拟合的来源。排期规则由此而来：设 epoch 大小（一个 epoch 的 token 数）为 ，$N$ ，窗口为 ，$\tau$ ，则 ，$N < \tau$ ，是过度记忆风险区， ，$N \approx \tau$ ，最优（样本在快忘时被刷新）， ，$N > \tau$ ，无坏处但收益递减。实验中 1.6B 与 3.2B 两个间隔的饱和点相近，说明超过窗口后再拉大间隔没用。
  4. 结论/判断：在 100M Transformer 上，高质量数学数据只有 0.8B token，按窗口排期最多训了 190 个 epoch；且只掺 6% 的低质量网页数据就大幅优于纯高质量数据——原因不是低质量更好，而是纯高质量分布太窄，间隔再合理也会把模型训偏，多样性本身是正则。

4关键数字

量 数值
记忆窗口（100M 模型） 约 1–5B token
高质量数据规模（OpenMathInstruct 系） 0.8B token
按窗口排期的最大 epoch 数 190（常规经验上限约 4）
低质量数据（FineWeb）掺比 6% 即大幅优于纯高质量

5可迁移

  • 高质量数据不够时别硬堆 epoch：先用回滚协议离线测记忆窗口（拿两个间隔已知的检查点比同一批样本的 loss），再把 epoch 大小设到不小于窗口，让每条样本在快忘时被刷新；总 epoch 数仍要有上限。
  • 边界要记牢：该结论的证据是验证 loss 下降速率相同，不是下游分数相同；大模型忘得更慢、窗口更长只是论文假设，未充分验证，190 epoch 是 100M/0.8B 的结果，别直接外推到 7B。面试被问数据重复，答间隔不答次数。

6疑问 / 下一步

  • 记忆窗口目前只能离线测，训练中在线估计窗口是论文列出的未来工作；若能在线测，就能把排期做成随训练进程自适应的数据调度器。
