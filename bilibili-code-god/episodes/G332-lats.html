2一句话总结

LATS 把 LLM 的每步决策建成搜索树、用 MCTS 的选择-扩展-评估-模拟-回传-反思循环替代 ReAct 的单链串行决策，用 5–10 倍调用成本换来可回溯的探索能力。

3核心

1. 问题/背景

ReAct 是 thought → action → observation 的串行循环，每一步都建立在前一步之上，没有回头路。视频用 WebShop 购物任务举例：搜索、点详情、选尺码、下单四步里，第三步尺码选错，后面整条轨迹全部作废——早期一个错误，后面全错，这是单链决策的根本代价。

2. 机制/方法

LATS 把决策过程建成一棵树：节点是「状态 + 历史轨迹」，边是候选动作，每个节点存一个由 LLM 评出的价值分数；agent 卡住时可以回到树上另一个有潜力的节点继续，而不是一条道走到黑。一轮迭代走 MCTS 的六步：

  1. Select：用 UCB 公式从根往下选最有潜力的叶子，在已验证价值与未探索可能性之间权衡；
  2. Expand：让 LLM 对该节点采样生成多个候选动作；
  3. Evaluate：再由 LLM 给每个候选打 0–1 分，充当价值函数；
  4. Simulate：从高分候选往下 rollout 到任务终局，拿到回报；
  5. Backpropagate：回报沿路径回传，更新所有祖先节点的价值；
  6. Reflect：分支失败时让 LLM 生成一段反思文本，作为后续扩展的上下文负面证据。

相对经典 MCTS 有三处关键替换：用 LLM 推理替代随机模拟、用 LLM 自我评估替代手写价值函数、新增 reflection 节点把失败经验显式注入下一轮。保留的精髓是 UCB 这个搜索骨架。

3. 关键证据或数字

WebShop 上成功率从 50% 提升到 70%（+20 个百分点），ALFWorld 家务交互基准从 55% 提升到 85%（+30 个百分点）。代价同样明确：每个树节点都是一次完整 LLM 推理，扩展、评估、模拟、反思全要花钱，总调用量约为 ReAct 的 5–10 倍。

4. 结论/判断

LATS 不是更快的 ReAct，而是更稳的 ReAct，本质是用算力换稳定性。简单任务、成本敏感、要求实时响应的场景继续用 ReAct；复杂规划、容错率低、可离线批处理的场景才值得上 LATS。

4关键数字

基准 ReAct → LATS 增益
WebShop 成功率 50% → 70% +20 个百分点
ALFWorld 成功率 55% → 85% +30 个百分点
LLM 调用成本 1× → 5–10× 明显更高

5可迁移

  • 设计 Agent 系统时先判断任务是否「一步错、步步错」：不可逆动作多的长链任务优先考虑树搜索/回溯结构，可逆的短任务用 ReAct 即可，别为搜索框架白付 5–10 倍 token。
  • Reflection 作为独立节点注入失败经验，是比「把失败轨迹塞进 prompt」更结构化的做法，做 Agent 评测与日志时可单独统计反思命中率。

6疑问 / 下一步

  • LATS 的价值评估完全依赖 LLM 自评，自评偏差会不会在深层节点被放大、与搜索深度如何权衡，值得查原论文的消融。
