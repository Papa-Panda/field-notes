ZeRO（DeepSpeed 的显存优化方案）

2一句话总结

ZeRO 把数据并行中每卡冗余存放的优化器状态、梯度、参数逐级切分到 $N$ 张卡上，三个 Stage 切得一样比一样多，单卡显存越来越省，代价是通信越来越贵。

3核心

  1. 问题/背景：数据并行时每张 GPU 都完整存了一份优化器状态、梯度和模型参数，$N$ 张卡就是 $N$ 份一模一样的数据。其中优化器状态最大：以 Adam 混合精度训练为例，每个参数要存 FP32 主权重加一阶、二阶动量，共 $12$ 字节。
  2. 机制/方法：Stage 1 只切优化器状态，每卡只保存并更新自己负责的那一份，优化器显存降到 $1/N$ ，且专挑最大的一块下手，性价比最高、通信代价最小；Stage 2 在此基础上再切梯度，每卡只保留自己的梯度分片，反向后做一次分片聚合；Stage 3 连参数也切，每卡平时只存部分参数，前向/反向用到某层时临时从其他卡取回完整参数、用完即弃。
  3. 关键证据或数字：见下表；Stage 3 三大件全部降到 $1/N$ ，但需要频繁跨卡同步参数，通常靠异步通信或计算与通信重叠把开销藏起来。
  4. 结论/判断：选哪一档本质是显存与通信速度的权衡——显存够用就用低 Stage 图快，模型大到单卡装不下才上 Stage 3 用通信换显存。一句话：ZeRO 用通信换单卡显存。

4关键数字

对象 切分前 Stage 1 Stage 2 Stage 3
优化器状态 全量 $1/N$ $1/N$ $1/N$
梯度 全量 全量 $1/N$ $1/N$
模型参数 全量 全量 全量 $1/N$

5可迁移

  • 面试答 ZeRO 不要只背三个 Stage 的名字，要能说清「为什么先切优化器状态」：它在混合精度 Adam 下占 $12$ 字节/参数，是三大件里最大的一块，先切它收益最大、通信最便宜。
  • 做 RL infra 的显存预算时可直接套用这张分工表估算每卡占用，再决定是否需要 Stage 3 级别的参数切分（对应 FSDP 的 full shard）。

6疑问 / 下一步

  • Stage 3 按需取参数的通信如何与计算重叠（prefetch 粒度、异步队列），值得对照 FSDP 的实现再看一遍。
