## 一句话总结

Mixture-of-Depths 在每一层前加一个轻量路由器，只让分数最高的少数 token 真正过这一层，其余 token 沿残差连接跳过，在深度维度做稀疏，省算力且基本不掉点。

## 核心

1. **问题/背景**：标准 Transformer 中每个 token 不管轻重，都要穿过每一层的注意力与前馈计算——标点、语气词和关键术语烧掉同样的算力，这是结构性浪费。
2. **机制/方法**：每层前放一个路由器，用 token 向量与一个可学习权重做点积得到标量分数；按分数排序，只放行 top-k 个 token 做该层的完整计算，其余 token 不进层、直接经残差连接原样输出。关键设计是 k 为固定预算（例如每层只算 12.5% 的 token），于是每层的计算量与张量形状提前确定，总算力可控可预测；且这种逐层 top-k 路由天然负载均衡，无需额外的均衡损失。与 MoE 的区别：MoE 在宽度上稀疏（token 照样过层，只是从多个专家里挑几个），MoD 在深度上稀疏（决定 token 要不要过这一层），两者正交可叠加。
3. **关键证据或数字**：论文结论为同等效果下推理采样最高可快接近一半；反过来在相同算力预算下，MoD 能训出比普通模型更低的损失。示例预算为每层仅 12.5% 的 token 参与计算、87.5% 跳过。
4. **结论/判断**：深度的算力分配应该是按 token 重要性差异化的；固定容量预算让 MoD 的加速可预测，这是它比动态路由更易落地的工程优势。

## 关键数字

| 量 | 数值 |
|---|---|
| 示例每层参与计算的 token | 12.5%（其余走残差跳过） |
| 推理采样加速 | 同等效果下最高接近 2 倍（快约一半时间） |
| 额外均衡损失 | 不需要（top-k 路由天然均衡） |

## 可迁移

- 面试对比类问题：MoE 管「宽度上选哪些专家」、MoD 管「深度上过哪些层」，一句话划清界限，再补一句两者可叠加。
- 做推理优化时可迁移这个思路：先看算力花在谁身上——若大量算力耗在低信息 token 的深层计算上，深度稀疏比单纯量化/剪枝更对症。
