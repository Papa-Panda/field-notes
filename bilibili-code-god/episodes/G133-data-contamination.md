## 一句话总结

Benchmark 题混进训练集就是数据污染，分数虚高而能力没涨；跑分之前先确认题没漏进训练集，否则那个分数毫无意义。

## 核心

1. 问题/背景：数据污染指训练数据混入了 benchmark 测试题，模型记住的是答案而不是能力，是预训练最常见的评测失真来源。三大污染源是 Common Crawl 爬到了含 benchmark 的网页、GitHub 上有人上传了题目、论文引用题目后被爬取。
2. 机制/方法：三重检测——n-gram 匹配（把题目切成 n-gram 在训练数据里搜重叠）、embedding 相似度（抓语义相同但措辞不同的污染）、困惑度检测（模型对某题 PPL 异常低，说明大概率见过）。清洗流程：检出重叠 → 从训练集删除 → 数据不够时用相似但不重叠的样本补充 → 重新训练消除记忆 → 干净复测确认分数可信。
3. 关键证据或数字：实操上用 n-gram + embedding 双重检测组合；报告分数时应附上 decontamination（去污染）结果。
4. 结论/判断：防线要前移——评测集绝不外发、不上公开仓库，自己留一份私有 holdout；数据入库前先与评测集跑一遍双重过滤；命中即整条删除，已经训过的模型要靠续训来消除记忆。

## 可迁移

- 做数据 curation 时把去污染做成入库流水线的固定一步（n-gram + embedding 双过滤），而不是评测前临时补。
- 看任何 benchmark 分数先问一句去污染做了没有、怎么做的，这在面试讨论评测可信度时是加分项。
