## 一句话总结

解码策略就是「每步拿到一张词概率表后按什么规矩挑词」：贪心短视、beam search 留多条候选逐层剪枝拿整句最优、采样先截断再随机换多样性，选哪种取决于任务要忠实还是要有趣。

## 核心

1. **问题/背景**：同一个模型、同一道翻译题，只换一个不起眼的解码设置，输出质量天差地别；更反直觉的是，每一步都挑概率最高的词，拼出的整句反而可能不是最好的。
2. **机制/方法**：
- 模型逐词生成，每步给出一张下一个词的概率表；整句的好坏约等于每步挑中概率的连乘总分。
- 贪心：每步只挑当前概率最高的词，快而简单，但太短视——这一步的局部最优可能把整句带进平庸的路，凑不出整句最优。
- Beam search：每步同时保留最有希望的 $B$ 条候选—— $B$ 即束宽——逐层展开所有候选的下一步、按整句累计总分只留最好的 $B$ 条、其余剪掉，等于多留几手绕开贪心的陷阱。
- 随机采样：先把概率表截断只留靠谱的一小撮候选，再按概率随机抽——保留概率最高的 $K$ 个叫 Top-K，保留累积概率刚够数的一小撮叫 Top-P（核采样）；截断防抽到离谱词，随机换多样性与创造力。
3. **关键证据或数字**：同一道翻译题对比：贪心第一步就被高概率词勾走、整句被锁死在平庸路线；beam 因保留多条候选绕过陷阱，整句综合总分明显更高、更通顺忠实——模型没改，只换解码策略，输出就上了一个台阶。
4. **结论/判断**：不是无脑上 beam：beam 的强项是翻译、摘要这类有标准答案、必须忠实的任务；用在聊天、写作等开放生成上，它会一味挑最安全的词，结果保守、重复、无聊。圈内默契是「要忠实用 beam，要有趣上采样」。

## 可迁移

- 推理/评测：做模型评测或 A/B 时先固定解码策略再比模型，否则贪心 vs 采样的差异会污染结论；线上服务则按任务类型分流（忠实型任务 beam、开放型采样）。
- 面试：答解码策略按「概率表 → 贪心短视 → beam 多候选剪枝 → 采样截断（Top-K/Top-P）换多样性 → 按任务选」这条链讲，并点明 beam 在开放生成上会退化重复。
