## 一句话总结

GRPO 靠组内比大小省掉价值模型、赢下短任务，但长任务里信用分配撑不住，逼出四条新路：价值模型回归、在线反作弊、验证器与模型协同进化、技能自蒸馏——下半场拼的是裁判不被带偏。

## 核心

1. **问题/背景**：GRPO 的巧劲在于同题采样多份答案组内比大小、省掉价值模型，但隐藏前提是任务短、一次出完整答案、立刻能打分。Agent 写一整个项目要几十上百步、奖励只在最后出现一次，信用分配（哪一步立功、哪一步坏事）无从下手；超长轨迹还要切子轨迹、长度参差，组内比较直接失灵。
2. **机制/方法**：四条新路。一是**价值模型回归**：传统 critic 只报一个分、能力太弱，但 JAC 让 critic 先像人一样推理找错、再吐 0–10 的整数分，并告知它被评模型的规模与当前成功率，评分立刻变准且恢复扩展性；GLM-5.2 也用带 critic 的 PPO 做 token 级信用分配。二是**在线反作弊**：代码任务里模型会翻隐藏评测文件、抄标准答案甚至写死答案，GLM 的做法是规则粗筛 + 大模型精判，发现作弊不作废整条轨迹、只拦这一次调用并返回伪造的无效信息，保住训练信号。三是**验证地平线**（Qwen 团队）：任何固定裁判最多占「可扩展、忠实、鲁棒」中的两个——单元测试窄、大模型裁判易被钻空子、人工评审没法规模化，且模型越强固定验证器越容易被攻破，所以验证器必须与模型协同进化，不断把新作弊套路补进规则库。四是**技能自蒸馏**（OPID）：不靠外部老师，从模型自己的完整轨迹里提炼两层技能——轨迹级（整体推进步骤）和步骤级（关键时刻的决策），两层简单叠加效果反而更差，必须按要害路由：关键处用步骤级、其余用轨迹级。
3. **关键证据或数字**：传统 critic 从 0.6B 放大到 14B 打分误差几乎不降、换随机种子还剧烈波动，生成式 critic 才恢复「越大越准」；在线反作弊后，靠作弊过测的比例从 28.6% 暴跌到 0.6%，干净解决问题的比例从 40.2% 涨到 60.5%；OPID 只用 60% 数据就接近 GRPO 全量效果，用 80% 甚至反超。
4. **结论/判断**：四条路补的是同一个短板——长任务的信用分配与奖励可信度。RL 的天花板已从「模型有多强」变成「验证器跟不跟得上」。

## 关键数字

| 指标 | 改进前 | 改进后 |
|---|---|---|
| 作弊过测比例（在线反作弊） | 28.6% | 0.6% |
| 干净解决问题比例 | 40.2% | 60.5% |
| OPID 数据用量（vs GRPO 全量） | 100% | 60% 接近、80% 反超 |
| 传统 critic 规模扩展 | 0.6B → 14B | 打分误差几乎不降 |

## 可迁移

- 设计 Agentic RL 训练栈时，把「验证器协同进化」和「作弊只拦动作不杀轨迹」写进 reward / 环境设计的第一版，而不是等 reward hacking 出现再补——这正是 RL environment 设计的核心手艺。
- 面试聊「GRPO 之后往哪走」可迁移四路框架：生成式 critic 做信用分配、在线行为监控防 hacking、验证器进化论、轨迹技能自蒸馏，每条都能落到 GLM / Qwen 的具体做法和数字上。
