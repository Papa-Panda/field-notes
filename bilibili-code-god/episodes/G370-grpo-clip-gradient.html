2一句话总结

标准 PPO/GRPO 里被 clip 的 token 反向梯度为零：clamp 把超界的比值摁成常数，常数乘优势构成的损失项对参数求导自然是零。

3核心

  1. 问题/背景：一道高频面试陷阱题——clip 明明改变了 loss 的数值，梯度又是对 loss 求导，被 clip 的 token 似乎理所当然应该有梯度；但正确答案恰恰相反。
  2. 机制/方法：关键不在 clip 有没有改变 loss 数值，而在它把 loss 变成了什么形式。用 PyTorch 的 clamp 做实验：把 $-2$ 、 $-0.5$ 、 $0.5$ 、 $2$ 四个数 clamp 到 $[-1, 1]$ 后求和当 loss 再反向，未被裁的中间两数梯度为 $1$ ，两头被裁掉的数梯度为 $0$ 。原因是当重要性比值超出区间，clamp 将其固定在边界值上，该 token 的损失项从「随参数变化的变量」变成「常数 × 优势」，里面不再有任何与模型参数挂钩的量，常数的导数为零，整项梯度就是零。
  3. 关键证据或数字：见下表，四数实验是可亲手复现的最小验证。
  4. 结论/判断：这正是 clip 的设计意图——比值偏离太远的样本太危险，干脆不让它更新模型，clip 是一个安全阀。延伸考点：正因为硬裁剪会白白丢掉这些 token 的信号，才有软裁剪类改进，保留梯度、只压住重要性权重的大小；「硬裁剪梯度归零、软裁剪梯度保留」是面试加分对比。

4关键数字

输入值 clamp 后 反向梯度
$-2$ $-1$（被裁） $0$
$-0.5$ $-0.5$ $1$
$0.5$ $0.5$ $1$
$2$ $1$（被裁） $0$

5可迁移

  • 排查 GRPO 训练「有效梯度枯竭」时，先统计每步被 clip 的 token 比例：比例过高意味着大量样本在空转，这与 G324 讲的「同一 batch 跑太多 epoch 后有效梯度枯竭」是同一件事。
  • 读 RL 框架源码时看到 clamp/min-max 组合，先判断它作用在比值还是损失上、被裁部分梯度是否被 detach，这决定了它到底是硬裁剪还是软裁剪。

6疑问 / 下一步

  • DAPO 的 Clip-Higher 只是放宽上界，被裁 token 梯度仍为零；它和保留梯度的软裁剪在长训练里谁更稳，值得找实验对照。
