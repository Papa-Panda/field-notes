## 一句话总结

多轮 SFT 的核心仍是 loss mask：整段对话拼成一条序列，但 loss 只算 assistant 的回复，user 部分 label 一律 -100。

## 核心

1. **问题/背景**：单轮 SFT 是一条指令加一条回答；多轮对话是 user 与 assistant 交替的多轮交互。训练时要把完整对话历史拼成一个长序列喂给模型，让它学习在给定上下文下生成 assistant 回复——但 loss 的计算范围和单轮不同，拼错或 mask 错都会教坏模型。
2. **机制/方法**：按时间顺序拼接 user1、assistant1、user2、assistant2……，每轮用特殊 token 分隔（如 ChatML 的起始/结束标记）。Loss 只落在 assistant 生成的 token 上，user 部分 label 设为 -100 被忽略；若不 mask，模型会学着生成 user 的话。样本构造上，一条 $N$ 轮对话可逐轮展开为 $N$ 个训练样本：第 $k$ 个样本包含前 $k$ 轮上下文、以第 $k$ 轮 assistant 回复为监督信号，每轮回复都是独立的训练信号。
3. **关键证据或数字**：一条五轮对话可展开成五个训练样本，数据利用率随轮数线性放大。长对话超长时两种截断策略：从左侧丢弃最早轮次、保留最近上下文（实操更常见，因为近期对话通常最重要）；或滑动窗口截取不同片段各自成样本。截断必须以整轮为单位，不能从一轮中间切断。
4. **结论/判断**：多轮 SFT 与单轮的差别不在拼接而在监督范围——mask 对地方，让模型只为自己的回答负责，是整条管线的关键。

## 可迁移

- 构造多轮 SFT 数据时默认逐轮展开成多样本并只对 assistant 段算 loss；检查数据管线时先抽查 label 是否把 user 段正确置 -100。
- 截断策略选「保留最近轮次 + 整轮截断」，避免半轮样本污染训练信号。

## 疑问 / 下一步

- 逐轮展开会让早期轮次被重复用作上下文，多轮数据是否存在轮次间的隐性权重不均，值得在真实训练里对照验证。
