## 一句话总结

padding 方向由「要不要在末尾续写」决定：encoder 只理解不生成、右填充无妨；decoder 自回归必须让真实内容紧贴末尾，填充只能靠左。

## 核心

1. **问题/背景**：批处理要求把长短不一的句子补齐成等长矩阵，补位符（通常为 0）放尾是右填充、放头是左填充。以 BART 为代表的 encoder 时代普遍用右填充，现在的 decoder-only 大模型却清一色左填充。
2. **机制/方法**：encoder 双向读入整句做理解、不向后生成，填充在后面用注意力掩码屏蔽即可。decoder 在序列末尾逐个生成新 token：若右填充，新 token 只能接在一串 0 之后，填充符被夹在真实内容与生成内容中间，打断语义连续性；左填充把 0 全挪到前面，真实内容紧贴末尾，生成自然衔接。
3. **关键证据或数字**：批量推理时左填充让 batch 内所有样本的最后一个真实 token 对齐在最右侧，下一个要预测的位置天然对齐、可一起计算，避免逐样本找生成起点带来的错位。
4. **结论/判断**：一句话判据——末尾要生成就左填充，只做编码理解才右填充；这是架构（自回归 vs 双向编码）决定的，不是框架口味。

## 可迁移

- RL rollout / 推理工程：批量生成时 position_ids 与 attention mask 必须按左填充口径构造，混用训练时的右填充习惯是常见的静默 bug 来源。
- 面试延伸：训练阶段常用右填充（有完整 label 序列、无续写问题），推理生成切左填充——能讲清训练/推理为何不同向，是加分项。
