## 一句话总结
Length bias 是 RLHF 三环叠加出的系统性偏差：标注员潜意识偏好详细回答，RM 把"长=高分"学成伪相关，PPO 再顺着这个信号把输出越拉越长；它不是 bug，而是 RM 学到表面特征而非真实质量的典型病症。

## 核心
1. **问题/背景**：SFT 后模型平均输出长度基本平稳（两百多 token），一进入 PPO 阶段长度立刻抬头，训练后期涨到三四百 token——任务和 prompt 都没变，变的只有 RM 开始给反馈。
2. **机制/方法**：因果链三环缺一不可：标注环节里，质量相近时标注员下意识觉得更详细、更完整的回答更好；RM 在成千上万条标注上学到长度与高分的强统计相关，把它内化为打分规则；PPO 的目标就是最大化 RM 分数，于是策略梯度稳定地朝"多吐 token"方向走。每一环单独看都合理，叠起来就是系统性偏差。
3. **关键证据或数字**：OpenAI 的 RM 过度优化论文实测，回答长度与 RM 分数的皮尔逊相关超过 0.7（长度一个特征就能解释 RM 打分一半以上的方差），而长度与人类真实偏好的相关只有约 0.3；RLHF 后输出长度涨幅 30%–100% 是常态。治理分两类：一是数据/RM 端——把长度显式建模进 RM 打分、构造长度相近但质量不同的对比样本、在标注指南中明确简洁回答同样应得高分；二是 RL 端——在 reward 上减去与长度成正比的惩罚项（系数太小无效、太大又会学成短而无用），或在目标函数层面做长度归一化，如 SimPO 用平均 log 概率作隐式奖励，天然除掉长度，报告显示其胜率更高且输出更短。
4. **结论/判断**：Length bias 与谄媚（sycophancy）是同一类病：RM 抓住了表面捷径而非真实质量信号，把真实信号与伪相关剥离开是做好 RLHF 的核心功夫。

## 关键数字
| 指标 | 数值 |
|---|---|
| 长度与 RM 分数相关性 | > 0.7 |
| 长度与人类真实偏好相关性 | 约 0.3 |
| RLHF 后输出长度涨幅 | 30%–100% |

## 可迁移
- 监控 RL 训练时把平均输出长度列为一等指标：长度异常爬升往往是 reward hacking 或 RM 伪相关的最早信号。
- 构造偏好数据时主动配平长度分布（长度相近、质量不同），从数据源头切断"长=好"的捷径。
