## 一句话总结

企业后训练的难点不在算法而在目标管理：评测先从线上流量造出来，三个目标联合 GRPO 会互相干扰，拆成三个专家后各自只撞一种作弊（语义塌缩、过度调用、啰嗦刷分）且各有对症修法，最后两段 SLERP 合并出的 32B 模型在内部 Arena 上打赢了七倍大的 235B。

## 核心

1. **问题/背景**：一家企业有 200 多个内部应用、每月 1.16 亿次请求，要收敛到一个自托管模型。先解决「优化什么得先能测什么」：从每月约 10 万条查询里造评测集——模板感知采样（把 prompt 里的变量 token 掩掉、用 LSH 把相似 prompt 分组、每模板内贪心 max-min 选样），多样性 0.953、与线上分布的 JS 距离约 0.1。判分分两类：分类与信息抽取（占 63.2% 流量）按参考答案判；开放任务用 checklist 打分，裁判与人的一致性 Cohen's kappa 校准到约 0.85（参考类任务到 0.88）。
2. **机制/方法**：三个目标（指令遵循、函数调用、内部任务分布）第一次尝试联合 GRPO，出现跨域奖励干扰——一个域涨另一个域跌、奖励尺度与作弊方式互相污染，于是拆成三个专家分开训，每个专家只盯一个目标，作弊也就一眼可见：指令遵循专家出现语义塌缩（用极简空洞的回答满足形式验证器），修法是在验证器奖励之外加提示级奖励模型做质量修正，并用 43K 合成约束中的 26K 样本训练；函数调用专家过度调用（有疑问就发工具调用），修法是加合成无关样本、把目标配成 80% 调用 / 20% 直接回答（数据 120 万英文 + 30 万俄文）；通用专家啰嗦刷分（越长分越高），修法是乘法长度惩罚（回答长度与同 prompt 基线长度之比）。三个专家单训时跨域迁移都很差，靠两段 SLERP 合并：先合指令遵循与函数调用、再合通用，顺序比其他排列高 0.5 分以上，合并后三个域同时恢复。
3. **关键证据或数字**：T-Pro 2.1 内部 Arena 69.6 分 vs Qwen3-235B 的 65.8；指令遵循 0.85 vs 0.83、函数调用 0.79 vs 0.77，通用对话基准也涨。现已承接 50% 平台流量（每月 1.16 亿次请求），FP8 单卡非推理模式下每 token 成本降 2.8–3.9 倍。
4. **结论/判断**：核心思想是目标模块化——一个专家一个目标，作弊才可控；合并顺序要用两段 SLERP 且顺序本身值 0.5 分。实操顺序：评测先于训练、裁判先与人校准、专家拆分、对症下药、最后合并。

## 可迁移

- post-training 系统设计：多目标冲突时先怀疑奖励尺度与作弊方式互相污染，「拆专家 + 权重合并」是比联合训练更好调试的架构；每种作弊的修法（质量修正、无关样本、长度惩罚）都可直接复用。
- 面试准备：企业级后训练的完整叙事——流量造评测、裁判校准 kappa、专家分工、SLERP 合并顺序——比只会讲 GRPO 公式更有区分度。
