## 一句话总结

领域检索效果差，换更大的通用 embedding 不如自己微调：用 InfoNCE 对比学习重塑向量空间，而胜负手在难负样本挖得好不好。

## 核心

1. **问题/背景**：RAG 的第一步是把文本变向量算相似度，embedding 质量直接决定检索准确率；通用模型（BGE、E5 等）没见过领域专业术语，在垂直场景往往不好用。
2. **机制/方法**：对比学习把正样本对拉近、负样本推远，InfoNCE 是其 softmax 形式——分子是 query 与正文档的相似度，分母汇集与负文档的相似度，模型由此学会区分相关与不相关。数据上正样本好找（业务日志里的 query 与点击文档），难点在负样本：随机采样太简单，学不到精细区分。
3. **关键证据或数字**：难负样本的挖法是用当前模型或 BM25 检索出排名靠前却并不相关的文档——如同类不同实体、排前十但不是答案的文档；每个 query 配 5–10 个难负样本，领域数据至少准备约 1 万对，基座选 BGE-large 或 E5-large，温度系数取 0.01–0.05，学习率在 $10^{-5}$ 量级，微调后检索指标可涨约 20 个百分点。
4. **结论/判断**：微调 embedding 的胜负手不在模型而在数据，尤其是难负样本的质量；流程是收集、挖负、选基座、微调、评估迭代补负样本的闭环。

## 关键数字

| 项 | 建议值 |
|---|---|
| 领域 query-doc 对 | 至少约 1 万对 |
| 每 query 难负样本 | 5–10 个 |
| InfoNCE 温度 | 0.01–0.05 |
| 效果 | 检索指标约 +20 个百分点 |

## 可迁移

- 「难负样本决定对比学习上限」这一判断同样适用于 reward model 的偏好对构造：只用随机负样本训出的区分边界必然粗糙。
- 做数据 curation 面试时，可迁移这套「线上日志挖正样本 + 检索挖难负样本」的 pipeline 叙述。

## 疑问 / 下一步

- 难负样本挖过头会引入假负样本（实际相关却被标为负），视频提到的迭代评估环节应重点监控这一比例。
