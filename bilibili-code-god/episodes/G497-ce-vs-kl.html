2一句话总结

交叉熵等于熵加 KL 散度；标签是 one-hot 时熵为零，两者数值相等、梯度相同，所以训练直接用交叉熵，只有目标变成软分布（蒸馏、RLHF 的 KL 惩罚）时 KL 才需要单独登场。

3核心

  1. 问题/背景：训练大模型天天用交叉熵，可既然有专门衡量分布差异的 KL 散度，为什么训练时几乎从不直接写 KL？要回答它，先看清模型输出的是什么：隐藏向量经 LM head 投影得到 logits，再过 softmax 归一化成分布 $Q$ ；真相是下一个词的 one-hot 分布 $P$ 。后面所有故事都是在比较 $P$ 和 $Q$ 。
  2. 机制/方法：基石是惊讶度——概率为 $p$ 的事件，惊讶度定义为 $-\log p$ ；按分布概率加权平均惊讶度得到熵，衡量分布的不确定性。交叉熵是「真相是 $P$ 、却用 $Q$ 去猜」时的平均惊讶度； $P$ 是 one-hot 时求和塌缩成一项，就是正确词概率的负对数。KL 散度是「本该用 $P$ 却用了 $Q$ 」多付出的额外惊讶，恒大于等于零、仅当两分布相同时为零、且不对称。三者关系一行：交叉熵 = 熵 + KL 。one-hot 标签的熵恒为零，所以交叉熵与 KL 完全相等；一般情形下熵是不随模型变的常数，优化交叉熵与优化 KL 梯度一样，而交叉熵还少算一项、更省事。
  3. 关键证据或数字：概率 0.9 的常见词惊讶度只有约 0.15 比特，概率 0.03 的罕见词高达约 5 比特；动画示例中 $P$ 与 $Q$ 的 KL 约 0.14 比特；模型给正确词的概率从 0.5 涨到 0.9，交叉熵从约 1.0 掉到 0.15。代码层面用 PyTorch 验证：one-hot 时 cross_entropy 的结果与手动算的 KL 断言相等。
  4. 结论/判断：交叉熵 vs KL 是伪命题——硬标签用交叉熵即可；只有目标是软分布时才显式写 KL：知识蒸馏拟合老师的软分布、RLHF 里用 KL 惩罚拉住新策略别偏离参考模型；且要分清正向 KL（撒大网覆盖所有峰）与反向 KL（只认一个峰），方向不同行为差别很大。顺带：困惑度就是交叉熵取指数，交叉熵每降一点，困惑度指数级下降。

5可迁移

  • 面试被问「为什么训练用交叉熵不用 KL」可直接答：one-hot 时熵为零、两者等价，交叉熵少算常数项；再补蒸馏和 RLHF 两个 KL 独立登场的场景，答案就完整了。
  • 写 RLHF / GRPO 损失时记住 KL 项的方向含义：对参考模型的 KL 是正则绳，正反向 KL 的 mode-covering / mode-seeking 差异会直接影响策略行为。
